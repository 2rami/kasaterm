# 학생 협업

다른 학생을 조회·소환하거나 일을 맡기고 보고할 때만 읽는다. 작업 범위는 사용자가 정하며 보드·로그는 관찰 자료다. 아래 `board`·`tell` 등은 `kasaterm-cli`의 하위 명령이다.

## 확인과 전달

- `kasaterm-cli board --all`로 최신 신원과 전체 `address`를 확인한다. 현재 기기만 필요하면 `--local`, 자리만 필요하면 `where`를 쓴다. 끊김·오래된 관측은 미확인이다.
- 필요한 대상만 `activity --address '<주소 JSON>' N`으로 본다. 화면은 `peek`·`capture`; 흐린 추천 문구를 사용자의 입력으로 읽지 않는다.
- 받은 말 머리의 `⟦이름⟧` 은 보낸 학생, `⟦이름@기계⟧` 는 다른 기기의 그 학생이다(보낸 앱이 기기를 붙인다). 답은 그 이름 그대로 `tell 이름@기계`. 끝의 `⟦폰⟧`·`⟦미러@기계⟧` 는 사람이 폰·그 기기 미러에서 보낸 말이다.
- 이름이 유일하면 `tell 이름@기계 '본문'`. 자동화·긴 본문은 `tell --address '<주소 JSON>' --stdin`. 같은 CLI가 원격도 처리하므로 SSH나 옛 인박스 전송으로 우회하지 않는다.
- 새 일은 `--title '작업명'`과 목적·담당 파일·완료 조건을 전달한다. 답장에는 제목을 붙이지 않고 발신자 이름도 본문에 덧붙이지 않는다.
- 전송 ID·주소·본문을 보관한다. `accepted`는 접수, `submitted`는 입력 전달이며 읽음 증명이 아니다. 불확실하면 `tell --status ID`로 확인한다. 동일 요청 조회·재시도는 `tell --id ID --address '<같은 주소 JSON>' --stdin`에 같은 본문을 준다. 같은 ID는 기존 영수증만 반환하며 다시 입력하지 않는다. `uncertain`이면 수신 화면·대화로 도착 여부를 확인하고, 확정할 수 없으면 미확인으로 보고한다. 새 ID의 자동 재전송은 하지 않는다.
- 작업 중에도 전달할 수 있다. 승인창·초안·한글 조합·신원 보호를 우회하지 않는다. 셸·닫힌 칸에 새 일을 넣지 않고, 구판이 명령을 모르면 업데이트 필요를 알린다.

## 배분과 완료

- 일을 나눠 맡긴 학생이 그 작업의 조율을 맡는다. 별도 감독 학생을 먼저 늘리지 않고, 기존 담당 중 한 명이 방 배치·중복 방지·사용량·결과 검수·완료 칸 정리까지 책임진다. 담당을 넘길 때는 남은 일·학생 주소·방·도는 잡을 함께 넘긴다.
- 작은 일은 직접 한다. 큰 일은 기존 담당을 확인하고 파일 경계를 나눈다. 소환 전 `guide panes`로 작업방을 고르고, 같은 목적의 학생은 그 방에 모은다. 같은 레포여도 목적이 다르면 다른 방이다. 브리프에 목적·담당 파일·완료 조건과 보고받을 담당을 넣는다.
- 작업 위임은 보드에 보이는 학생 칸을 쓴다. 짧은 읽기 전용 탐색·설계나 사용자가 직접 요청한 서브에이전트는 예외다. 모델은 사용자 선택과 현재 앱 설정을 따른다.
- 새 학생의 `summon`은 `--cmd`를 생략하거나 `--cmd auto`이면 도착 기기의 모든 Claude·Codex 로그인 계정 사용량을 비교하고 선택한 계정으로 그 새 세션만 실행한다. 최신 사용량이 낮은 계정을 고르고 동률이면 선호 하네스와 현재 계정을 우선한다. 오래된 수치·조회 실패를 0%로 보지 않는다. 알려진 값이 없으면 로그인된 현재 계정만 선호 순으로 쓰며, 로그아웃·소진 계정은 제외한다. 전역 선택값이나 기존 대화는 이 선택으로 바꾸지 않는다. `agent-plan [--machine ID]`로 선택 계정·사용률·사유를 조회할 수 있다. `--cmd claude`, `--cmd codex`, 사용자 래퍼·resume 명령은 그대로 따른다.
- 남이 잡은 미커밋 파일은 덮지 않는다. 겹침 가드가 막으면 담당자와 조율하고 명시적으로 넘겨받는다.
- 기다릴 때는 `board --wait 이름 --since <소환 값 또는 전송 ID>`를 별도 잡으로 둔다. 전체 변경 감시는 `board-watch --all --json --since CURSOR`; `reset_required`면 새 snapshot을 받는다.
- 끝나면 `kasaterm-cli done succeeded '완료·미확인·남은 것'` 한 번. 실패는 `failed`, 막힘은 `blocked`, 승인 필요는 `needs_approval`. 이 보고가 사람의 폰·맥 알림과 폰 종 목록이 되고(`succeeded` 는 완료, 나머지는 고를 것), 부른 창에도 자동 전달되므로 완료 쪽지를 중복 보내지 않는다. 사람이 직접 시킨 일도 정말 끝났을 때 같은 명령으로 알린다 — 턴이 끝난 것만으로는 알림이 가지 않는다.
- `idle`·침묵은 완료가 아니다. done·결과·미커밋·남은 잡을 확인한 뒤 자신이 맡겼던 같은 신원의 칸을 정리한다. 계속 맡길 일이 있으면 같은 작업방에서 재사용한다. 사람이 직접 쓰는 칸·출처가 불명확한 칸은 닫지 않는다.
- 보고는 결론·끝난 것·남은 것·사용자가 할 일을 간결하게 쓴다. 확인하지 못한 것을 완료로 말하지 않는다. 위험·취향·범위 판단은 사용자에게 묻고 이미 승인된 일은 이어 간다.

실제 인증 입력·승인이 필요하면 옆의 소유한 빈 셸에 명령만 준비하고 사용자가 제출하게 한다. 비밀은 `kasaterm-cli secret`의 기기 키체인·승인 경로로 사용하고 값을 출력하지 않는다.

다른 기기를 켜거나 재시작한 뒤에는 `kasaterm-cli app inspect --machine <id>`의 `ready`까지 확인한다.
복원 창을 만난 일반 조작은 자동으로 복원을 시작하지만 그 요청은 `app_restoring`으로 거절된다.
완료 뒤 `board`/`where`에서 새 주소를 찾아 다시 요청한다. 복원 전 칸 번호를 그대로 재사용하지 않는다.
