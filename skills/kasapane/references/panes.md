# 칸·방 조작

카사텀의 칸·탭·방을 실제로 조회하거나 바꿀 때만 읽는다.

- 조작은 `kasaterm-cli`로 한다. 연결은 현재 `KASATERM_SOCKET_PATH`를 사용한다. 연결을 확인할 수 없으면 임의 소켓·포트로 대신하지 않는다.
- `where`는 자리, `board --all`은 학생·신원, `activity`는 도구의 실제 결과다. 필요한 범위만 조회한다.
- `%N`은 재사용될 수 있다. 조회한 현재 대상을 쓰고, 원격·자동화에는 보드의 전체 `address`를 고정한다. 다른 기기는 `%N@기계` 또는 유일한 이름으로 지정한다.
- `split right`는 호출한 칸을 나눈다. 반환된 ID를 저장하고 이후 조작에 쓴다. 초점 이동은 필요한 때만 명시한다.
- `tell --raw`는 소유한 빈 셸에 명령을 넣는 용도다. 실행 중인 Claude·Codex나 사람의 입력창에는 일반 `tell`을 쓴다.
- `close`는 현재 대상과 미커밋 변경을 확인한다. 넓은 패턴이나 `--force`로 보호를 우회하지 않는다. 원격 칸 닫기는 원본에도 영향을 주므로 사용자가 의도한 대상인지 먼저 확인한다.
- `bind-transcript`, `notify`, `attention`은 훅용 명령이다. 일반적인 칸 조작에 호출하지 않는다.

## 작업방 배치

- 방은 기기·레포가 아니라 작업 목적별로 만든다. `where`로 같은 작업방을 먼저 찾고, 방 이름은 사용자가 구별할 수 있는 짧은 업무명으로 붙인다. 기존 사람 배치를 매번 다시 짜지 않는다.
- 같은 작업의 학생은 `summon --beside '<기존 칸의 전체 주소 JSON>' --cwd /작업/경로 --name '맡을 일' '브리프'`로 그 방에 둔다. 호출한 학생의 방이 맞으면 로컬 `summon`은 자기 칸 옆에 둔다. 다른 기기에서는 `--machine`만 주지 않고 반드시 자리를 지정한다.
- 새 작업의 첫 학생은 `summon [--machine 기기] --new-room '업무명' --cwd /작업/경로 --name '맡을 일' '브리프'`로 부른다. 빈 셸을 따로 남기지 않는다. 다음 학생부터는 반환된 주소를 `--beside`에 쓴다. 원격·새 방 소환은 반환된 `wait` 명령으로 완료를 받는다.
- 구판에 `--new-room`이 없으면 `window-new --on 기기` → 반환된 빈 칸 주소에 `rename-window --room` → 그 주소 옆으로 소환한다. 학생이 선 뒤 직접 만든 빈 셸만 닫는다. 기존 학생을 새로 띄우지 않고 옮길 때는 `move <주소> <같은 기기 도착 칸 주소> 방향`을 쓴다.
- 분할을 기본으로 하되 글을 읽기 어려울 만큼 칸을 늘리지 않는다. 보조 잡은 탭으로 두거나 순차 실행하고, 독립된 하위 작업만 이름 붙인 별도 방으로 나눈다. 배치 뒤 `where`로 소속·탭·크기를 확인한다. 미러 배치는 원본에 영향을 주므로 원본 작업방을 기준으로 조율한다.

자주 쓰는 조회: `where --json`, `peek <대상> N`, `activity <대상> N`, `capture --window /절대/경로.png`.
만들기·이름·배치·닫기 옵션은 `kasaterm-cli --help`에서 필요한 명령만 찾는다. 화면 검증을 위해 앱을 띄운다면 먼저 `guide develop`의 격리 규칙을 따른다.

## 앱 화면과 재시작

- `app inspect [--machine 안정ID]`로 현재 방·칸·OS 초점·복원 대기/진행·재시작 영향을 읽는다. 배경 앱의 선택을 사용자가 실제 보는 화면으로 단정하지 않는다.
- 실제 모니터는 `app screen [--machine 안정ID] [--display 번호] --out /새/경로.jpg`로 한 장 본다. 화면 기록 권한은 OS가 관리한다.
- 복원은 `app restore … --expect <방금 inspect의 revision>`, 재시작과 자동 복원은 `app restart … --expect <revision>`이다. 사용자가 허락한 시점에 실행하고 이미 받은 승인을 되묻지 않는다. 바쁜 작업 중단을 허락받았으면 `--interrupt`를 붙인다. 미저장 문서는 이 옵션으로도 넘지 못한다.
- 재시작 응답의 job_id를 `app-restart status`로 확인하고 새 앱의 `app inspect`로 복원 완료를 확인한다. 대화 복원과 중단된 작업의 자동 재개는 다르다. `app update-check … --expect <revision>`은 표준 업데이트 창만 연다. 상세 계약은 `docs/app-controls.md`다.
