# CLI 세션 이동

도는 Claude·Codex 세션은 사이드바의 다른 기기·방으로 끌어 옮기거나 `kasaterm-cli machines move`로 옮긴다. 이동 후 같은 대화·모델을 이어 쓰며, 원래 자리를 걷고 도착 기기의 방을 보기 창으로 연다.

## 끌어 옮기기

학생 칸·탭을 다른 기기의 방에 놓으면 그 방에, 기기 머리에 놓으면 새 방에 앉힌다. 다른 기기 학생을 「이 기기」 머리에 놓아도 새 방으로 데려온다. 누르는 순간 출발 칸의 세션·화면 열쇠를, 놓는 순간 도착 방을 고정한다. 화면 열쇠가 없는 구판 기기에서 데려오기는 업데이트 뒤에 가능하다.

놓은 프레임부터 도착 기기 줄에 진행을 표시한다. 드래그와 CLI·본인 세션·덮개 이사는 같은 재개 확인 경로를 쓴다. 도착 기기는 새 판이어야 하고 새 칸 셸이 입력줄 표식(OSC 133 B)을 내야 한다 — 맥은 zsh, Windows 는 cmd·PowerShell·Git bash(칸을 띄울 때 표식을 심는다, 사용자 rc 가 bash `PROMPT_COMMAND` 를 덮으면 빠진다). 지원 여부와 작업 폴더가 확인되지 않으면 출발 CLI를 종료하지 않는다. 도착 셸을 먼저 준비하고, 입력이 없는 같은 자리인지 확인한 뒤 출발 CLI를 종료하고 마지막 기록까지 옮긴다. 고정된 2.2초 명령 대기·3.5초 화면 전환 대기 대신, 도착 CLI의 같은 대화 번호·실제 입력창을 확인해 완료한다. 대화가 크거나 CLI 시작·인증이 늦으면 더 기다리며, 작업 중이면 턴이 끝날 때까지 예약한다. 모든 조건에서 1초 완료를 약속하지 않는다.

예약한 도착 셸에 사람이 입력했거나 다른 프로세스가 시작됐으면 실행 명령을 넣지 않는다. 출발 칸이 닫히거나 바뀌면 늦게 도착한 결과로 새 칸을 덮지 않는다. 여러 탭 중 하나만 이사할 때 나머지 탭은 유지한다. 도착 앱에서 재개가 실패하거나 확인이 끊기면 성공으로 표시하지 않으며 대화 파일은 출발 기기에 남는다.

새 재개 경로는 셸 별칭·함수가 덧붙이는 옵션을 건너뛰고 카사텀 하네스 래퍼를 직접 부른다. 출발 프로세스에서 읽은 권한 옵션이 도착 기기 프로필의 기본값으로 바뀌지 않게 하기 위해서다. 줄은 도착 칸 셸 문법으로 짓는다(`kasa_socket::shell_line::direct_line`): POSIX `command 'claude' …`, PowerShell `& (Get-Command -CommandType Application -TotalCount 1 -Name 'claude').Source …`, cmd `call claude …`.

출발 하네스 끄기는 맥은 SIGTERM, Windows 는 빈 입력창을 확인한 뒤 `/exit`(codex `/quit`) + Enter 다 — Ctrl+C 는 `claude.cmd` 를 감싼 cmd 가 「일괄 작업을 끝내시겠습니까」로 받아 멈춘다. 8초 안에 안 꺼지거나 입력창에 쓰던 글이 있으면 실패로 멈추고, `--force` 일 때만 강제 종료한다(`kasa_mcp::agent_stop`). Windows PowerShell 칸은 사용자 프로필(conda 등)로 뜨는 데 7초 남짓 걸려 도착 셸 준비를 20초까지 기다린다.

## 기기와 칸 고르기

현재 기기의 CLI에서 등록된 기기 이름과 옮길 칸 번호를 확인한다.

```sh
kasaterm-cli machines
kasaterm-cli where
kasaterm-cli machines move %3 맥미니
```

기기 이름은 목록의 이름을 그대로 쓴다. 공백이 있으면 `"Mac Mini"`처럼 따옴표로 감싼다. 짧은 이름은 정확히 한 기기와 맞을 때만 전체 이름으로 풀린다. 알 수 없는 이름·중복 이름·여러 후보·연결되지 않은 기기는 이동 요청 전에 거부된다. `mini`도 등록된 이름이나 유일한 이름 앞부분일 때만 통한다. 주소와 SSH 포트를 추측하거나 다른 기기에 SSH로 들어가 CLI를 실행할 필요가 없다.

`%3`은 **현재 기기의 칸 번호**다. 이동 대상에 `%3@맥미니`를 주지 않는다. 현재 칸 안에서 자신의 세션을 옮길 때는 칸 번호를 생략할 수 있다.

```sh
kasaterm-cli machines move 맥미니
```

생략한 번호는 `$KASATERM_PANE_ID`에서 읽는다. 칸 밖에서는 `where`로 확인한 번호를 명시한다.

본인이 요청하면 명령 자체가 현재 턴에 포함돼 먼저 예약 응답을 받는다. 요청 전에 작업 파일과 재개 지점을 정리하고, 예약 응답 뒤에는 턴을 끝낸다. 자기 턴에서 도착할 때까지 기다리면 그 턴이 끝나지 않아 이사가 시작되지 않는다. 다른 이사가 진행 중이어도 실행 중인 세션의 요청은 큐에 보존한다. 예약에는 요청 시점의 대화·칸 신원을 고정하므로 나중에 같은 칸 번호가 재사용되어도 새 대화를 대신 옮기지 않는다. CLI의 도착 방은 출발 방 이름으로 새로 만든다.

## 도착 경로와 데려오기

`--cwd`를 생략하면 등록된 기기의 경로 매핑을 사용한다. 경로 매핑이 없으면 도착 기기 기준의 경로를 지정한다. 매핑은 `machines.json` 항목의 `roots`(이쪽 경로 → 저쪽 경로, 접두가 긴 규칙 우선)다. Windows 경로는 드라이브·대소문자·`\`/`/` 를 가리지 않고 견주고, 남은 꼬리는 상대 OS 구분자로 바꾼다.

```json
[{"label": "맥미니", "ssh": "nachoneko",
  "roots": {"C:\\Users\\me\\Desktop\\KASA": "/Users/me/Desktop/KASA"}}]
```

맥에서 Windows 기기를 적을 때는 반대로 `{"/Users/me/Desktop/KASA": "C:\\Users\\me\\Desktop\\KASA"}`. 이사 칸의 작업 폴더는 맥은 셸 프로세스 cwd, Windows 는 하네스 프로세스 cwd(PowerShell 은 `cd` 해도 프로세스 cwd 가 그대로다)다.

```sh
kasaterm-cli machines move %3 맥미니 --cwd /Users/me/project
```

다른 기기에서 도는 세션을 이쪽으로 데려올 때는 도착지에 `local`을 준다. 대상은 이쪽에 열린 **거울 칸**의 번호다. 방 이사 뒤 남는 그 기기 방의 보기 창 칸도 된다 — 원격 작업 폴더는 그 기기 칸 목록의 cwd 로 메운다. 거울이 아직 없으면 `board --all`에서 원격 칸을 확인하고 `attach %N@기기`로 연 뒤 `where`에서 이쪽 번호를 확인한다.

```sh
kasaterm-cli machines move %3 local --cwd /Users/me/project
```

이동은 양방향 모두 **대화만** 옮긴다(`session/migrate.rs` — 레포 맞추기는 2026-09-14 에 걷었다). 미커밋 변경·안 올린 커밋은 따라가지 않으므로 옮기기 전에 커밋·푸시하고, 도착 기기 작업 트리에서 받는다. 도착 작업 트리가 다른 세션의 파일을 덮지 않도록 경로를 고른다.

`--run '<명령>'`은 필요할 때 도착 셸에 실행 명령을 준다. 한 인자로 인용하며 `local`에서는 지원하지 않는다.

## 예약·실패 확인

기본 이동은 진행 중인 턴이 끝나기를 기다린다. 응답의 `result.remote_id`에 `예약됨`이 있으면 예약 접수다. 턴을 마친 뒤 `where`, `board --all`, `peek %3`으로 도착 세션과 거울을 확인한다.

맥북을 닫아도 이어지는 기준은 **도착 기기에서 같은 대화가 준비됐는지**다. 이사 후 실행은 도착 기기에 있어 맥북의 잠자기와 분리된다. 이사 중 덮개 잠자기를 막으려면 [덮어도 마저 하기](lid-away.md)의 별도 설정과 설치가 필요하다. 설치된 경우 본인이 신청한 예약·실행·보기 창 전환도 잠자기 대기에 포함한다. 예약 접수만으로 닫아도 된다고 안내하지 않는다. 재개된 CLI가 자동으로 다음 일을 시작하는 것은 아니므로, 도착 확인 후 최신 보드 주소로 남은 작업을 전달한다.

빠른 자동 이사의 다음 단계는 작업 목록을 명시하는 준비 요청, 변경 파일 사전 운반과 마지막 차이 검증, 앱 재시작에도 남는 요청 ID·상태 조회, 도착 후 재개 지시의 한 번만 전달이다. 현재는 자동 파일 운반·영속 요청·자동 작업 재개를 제공하지 않는다. `/tmp`·cwd 밖 자료와 장기 프로세스는 학생이 정리해야 하며, 데이터가 큰 작업은 맥미니에서 시작하고 맥북에서는 미러로 보는 편이 이사 지연을 없앤다.

`--force`는 진행 중 턴의 중단과 도착지 충돌 덮어쓰기를 허용한다. 기본 절차에는 필요하지 않다.

실패 응답이나 응답 시간 초과를 이동 완료로 판단하지 않는다. 먼저 원본과 거울 상태를 확인한다. 확인 전 `close`, `closed`, 세션 종료, `--force` 재시도를 하지 않는다. CLI는 잘못된 입력과 도착지 선택을 이동 요청 전에 거부하며, 이동 응답이 실패하거나 불확실해도 종료 요청이나 자동 재시도를 보내지 않는다.

## 도움말과 검증

```sh
kasaterm-cli machines --help
kasaterm-cli machines move --help
kasaterm-cli help machines move
```

이 도움말은 앱·소켓 없이 출력된다. 파서와 명부 선택, 이동 실패·응답 없음의 처리는 `crates/kasa-socket/src/cli/session_move.rs`의 회귀 검사에서 가짜 전송으로 검증한다. 실제 세션 이동 없이 `cargo test -p kasa-socket cli::session_move::tests`로 실행한다.
