# 디자인 정본 — 색·모양·치수와 그 뒤의 규칙

화면을 만들거나 고치기 전에 읽어라. 새로 발명하지 말고 **여기 있는 값을 써라.**
여기 없는 값이 필요하면 그때 이 문서에 추가하고 쓴다 — 파일 안에 상수를 새로 만들지 마라.

이 문서가 생긴 이유: 설정 화면은 HTML 목업에서 옮겨 왔는데 **그 목업이 레포에 없다.**
치수와 규칙이 `native_settings.rs` 주석 13군데에 파편으로만 남아, 새 화면을 만들 때
참고할 정본이 없었다. 아래는 그 파편과 `theme.rs` 의 토큰을 한자리에 모은 것이다.

> 값은 현재 체크아웃에서 재확인할 것. 이 문서는 정본이지만 코드가 최종이다.

---

## 1. 색 — `theme.rs`

색은 **직접 쓰지 않는다.** 전부 `theme::` 함수를 거친다. 테마를 갈면 같이 따라가야 하기 때문이다.

`Palette` 한 벌이 화면 전체를 덮는다:

| 갈래 | 필드 |
|---|---|
| 바탕 | `bg` `fg` `surface` `surface_hover` `surface_active` |
| 선 | `border` |
| 글자 | `text` `text_dim` `text_mute` |
| 뜻 | `success` `danger` |
| 코드 | `syn_keyword` `syn_string` `syn_number` `syn_comment` `syn_function` `syn_type` |
| 터미널 | `ansi[16]` |

- 프리셋은 `THEME_PRESETS`(System·Light/Dark/Light/Catppuccin/Gruvbox/Tokyo Night/Sky/Amber CRT/나초네코),
  강조색은 `ACCENT_PRESETS`. 사용자 정의 테마는 `custom_*` 계열로 같은 `Palette` 를 채운다.
- **`Palette` 에 없는데 `theme::` 에는 있는 것들이 있다.** `panel_bg()` 는 `bg` 와 `surface_hover` 를
  반씩 섞어 만들고, `accent()` 는 팔레트가 아니라 `ACCENT_PRESETS` 에서 따로 온다. 자리마다 배경이
  달라 고정 토큰을 못 쓰는 것들(판 위에 올라온 버튼의 채움 등)은 `base` 를 받아 계산한다.
  **함수가 있으면 함수를 써라** — 필드 목록에 없다고 새로 만들지 마라.
- 반투명이 필요하면 `theme::with_alpha(theme::border(), 140)` 처럼 **기존 색에 알파를 얹어라.**
  새 회색을 만들지 마라 — 라이트 테마에서 혼자 안 따라간다.

## 2. 모양 — `theme.rs` 의 `Shape`

| 필드 | 뜻 |
|---|---|
| `radius_sm` `radius_md` | 모서리 두 단계 |
| `border_w` | 구조선 두께 |
| `shadow_offset` | 흐림 없는 그림자 거리(0 = 없음). 누르면 줄어드는 그 어긋남이 「물체」로 읽힌다 |
| `roundness` | 원·알약이 네모로 굽는 정도(1 = 정원, 0 = 정사각). **반지름과 별개다** — 6px 점과 200px 판이 같이 굽으면 안 된다 |
| `pixel_chrome` | 글자·아이콘을 도트 에셋으로. 중간값이 없어 별도 축이 아니라 여기 얹었다 |

프리셋 셋: `rounded`(6/9, 그림자 없음) · `sharp`(2/3) · `pixel`(0/0, 선 2px, 그림자 3px, 도트).
원·알약은 `circle_rect` / `pill_rect` 를 거쳐라. `radius_sm` 으로 원을 그리지 마라.

## 3. 치수

### 설정 화면 (정돈된 기준 — 새 화면은 이걸 따라라)

| 이름 | 값 | 자리 |
|---|---|---|
| `HEADER_H` | 44 | 페이지 이름이 앉는 머리 칸. 본문은 그 아래 14px 에서 시작 |
| `ROW_H` | 40 | 플랫 행 한 줄 |
| `CTL_H` | 26 | 조작 부품 높이(버튼·입력칸·스테퍼) |
| `CONTENT_MAX_W` | 800 | 읽기 열 상한 |
| 묶음 제목 | 위 30 · 아래 24 (합 54) | `section_title` 뒤에 `*y += 54.0` |
| 열 좌우 여백 | 28 (좁은 창 20) | 760px 이 갈림길 |

- 설정 탐색은 머리글 아래 56px부터 하단 돌아가기 버튼 위 8px까지 쓴다. 돌아가기는 하단 46px 위치의 32px 행으로 고정한다.
- 32px 행·4px 간격과 묶음 제목 24px가 전부 들어가지 않으면 묶음 제목을 접고 `CTL_H` 26px 행·4px 간격으로 줄인다.
- 그래도 높이가 모자라면 탐색 목록만 독립 스크롤한다. 그리기와 클릭 영역을 같은 탐색 뷰포트로 잘라 본문·하단 버튼과 겹치지 않게 한다.
- 일반 안내문은 테두리 없는 `plain_hint`를 공유한다. 10.5pt·줄높이 18px로 전체 문장을 감싸며 고정 높이·말줄임을 쓰지 않는다.
- 옆 목록은 묶음 셋 — 화면(외형·터미널·앱 하단바·날씨)·에이전트(계정·코딩 에이전트·캐릭터)·앱(앱 일반·연결 기기·펫·피드백).
  묶음 머리는 24px, 묶음 안은 자주 여는 것이 위다. 시작 자리는 `NAV_GROUPS` 한 곳이다.
- 칩·카드 묶음 위 이름(`row_label`)은 위 10·글 20 — 바로 위 행 밑줄에 글자를 붙이지 않는다.
- 페이지 안 묶음 머리는 전부 `section_title`(11 `text_dim`)이다. 12.5 굵은 사설 머리를 따로 만들지 않는다.
- 고를 것이 열 개를 넘는 목록(글꼴·팔레트 슬롯)은 칩을 깔지 말고 선택 상자(`dropdown_row`)로 한 줄에 둔다.
- 보이는 모습을 바꾸는 칸은 「외형」 한 페이지에 모은다(2026-10-06): 팔레트·강조색·모서리·대비·글자 크기·UI 배율·UI 글꼴·탭 위치·
  창 상태줄·pane 하단바 높이·터미널 글꼴·커서·기기 색·기기 아이콘. 「터미널」은 셸만, 「앱 일반」은 시작·파일·편집 감각만 둔다.

### 빠른 설정 (첫 실행)

- B안: 캐릭터·모양·코딩 에이전트·터미널의 현재 값을 한 화면에서 요약하고 한 영역씩 펼친다.
- 옆 목록 폭은 190px(760px 미만 154px), 읽기 열은 최대 800px로 남는 공간의 가운데에 둔다.
- 핵심 요약 행은 64px. 본문 폭 470px 미만에서는 값을 다음 줄로 내려 80px로 늘린다.
- 미리보기는 112px, 하단 시작·건너뛰기 영역은 62px로 고정해 펼친 내용만 스크롤한다.
- 안내·오류가 있으면 하단을 40px 늘려 피드백이 스크롤에 가려지지 않게 한다. 스크롤바는 본문 밖 14px 여백에 둔다.
- 일반 안내문은 박스 없이 보조글 10.5pt, 줄높이 18px로 접어 표시한다.
- 상세 펼침 행은 일반 설정과 같은 40px이며, 접힌 상태가 기본이다.
- 시안의 임의 모델명·글꼴·팔레트와 카드 장식은 구현 값으로 채택하지 않는다.

### 작업현황 판 (보드 방 첫 탭)

- 사람용 판이다. 에이전트용 관측(「관측」 탭·`kasaterm-cli board`)과의 경계는 [boards.md](boards.md).

- 작업현황과 나쵸 대화는 같은 네이티브 방이다. 기존 아로나 입구는 나쵸 대화를 고른다. 스케줄·대상 격자는 이 방에 두지 않으며 저장된 예약과 백엔드 실행은 변경하지 않는다.
- 머리 높이 44에 작업현황·나쵸·도구, 새로고침·닫기를 둔다. 관측·에이전트·소스 컨트롤·이사는 도구를 명시적으로 펼쳤을 때만 추가 40px 행에 나타난다.
- 순서: 장부 상태 → 프로젝트 필터 → 내 답변 필요 → 진행 중 → 결과 → 선택한 작업 상세. 기본 화면에 모든 기기·세션 명부를 펼치지 않는다.
- 좌우 여백은 판 폭 760 이상에서 28, 그 미만 20px 한 번뿐이다(`paint` 의 `content_x`). 본문(`hub_layout`)은 그 칸을
  그대로 받아 머리글 「작업현황」과 같은 왼쪽 줄에서 시작한다 — 여백을 또 빼면 600px 판에서 카드 폭이 406 → 366 으로 준다.
- 머리글 아래는 상태 한 줄(11 흐림, 「진행 N · 계정 기록」)과 그 오른쪽 테두리 단추(새 프로젝트·연결 설정, 26, 사이 6)다.
  한 줄에 안 들어가면 단추를 다음 줄 왼쪽으로 내린다. 큰 「프로젝트」 제목은 두지 않는다 — 판 이름과 겹친다. 그 아래 프로젝트 칩.
- 본문 폭 960 이상은 작업과 대화를 나란히 둔다. 간격 24, 대화 폭은 본문의 36%를 340~420px로 제한하고 작업 읽기 열은 최대 800px다. 더 좁으면 작업현황·나쵸 탭으로 바꾸며 입력 초안은 유지한다.
- 작업 목록과 대화는 각각 스크롤한다. 작업 상세·검사 근거는 선택한 작업 아래에 표시한다.
- 카드 안쪽 여백 10, 카드 사이 6. 제목은 12(답 줄은 13) **보통 굵기** — 긴 한글 문장을 굵게 그리면
  글자마다 굵기가 갈려 보인다. 굵게는 묶음 제목·기기 머리에만.
- 완료 줄기는 「성공 확인」(success)·「끝남 · 검증 안 됨」(text_dim)·「실패」(danger)·「접음」(text_mute)을 가른다.
- 꺼 둔 동작(승인)은 흐린 테두리 단추로 자리를 지키고 이유를 옆에, 안 들어가면 다음 줄에 적는다.
- 카드 한 줄 설명은 아는 칸만 싣는다. 「미확인」은 상세의 맡음·연결 줄이 말한다.

### 나쵸 대화

- 대화 머리는 40px, 작업 문맥이 있으면 40px를 더 쓴다. 입력 영역은 하단 최소 126px에 고정한다(이름18·입력40·안내18·버튼26·간격). 오류·연결 안내가 길면 한 줄당 18px씩 높여 문장을 자르지 않는다.
- 메시지 안쪽 여백은 10px, 메시지 간격 6px, 본문12pt·보조10.5pt·줄높이18px다. 말이 길어져도 입력·전송 버튼은 대화 스크롤에 밀리지 않는다.
- 색·버튼·포커스는 기존 공통 부품을 사용한다. 진행을 흐리게 만드는 장식 애니메이션은 넣지 않는다.
- 나쵸의 대화 원장과 접수 영수증만 사실로 표시한다. 연결 실패·아직 접수 미확인·전송 중·답변 완료를 구분하고, 불확실한 재전송은 같은 메시지 id와 본문으로만 한다.
- 작업 선택은 문맥 지정이지 전송·승인이 아니다. 전송 버튼을 누르기 전에는 사용자 메시지를 보내지 않는다. 인증되지 않은 기기의 읽기 권한을 대화 쓰기 권한으로 확장하지 않는다.

- 새 판 알림(`update_notice.rs`): 「새 판 vX.Y.Z 있어요 · 업데이트를 누르면 받아서 다시 켜요」 + [업데이트][닫기]. 뜻은 할 일 있음
  (`accent`, 표지 글리프 `arrow-up`)이고 닫기는 위험색이 아니다. 끊길 일이 있으면 같은 자리가 「지금 업데이트하면 끊겨요 ·
  일하는 창: …」 + [그래도 업데이트][닫기](주의)로 바뀐다. 다른 알림보다 낮아, 덮이면 칩을 거두고 물러섰다가 자리가 비면 다시 선다.
- 들어오기 180ms: 위 6px 에서 끝이 느린 곡선으로 내려앉으며 선다(결정 알림은 흐려지지 않고 미끄러지기만).
  나가기는 2.4초 선 뒤 0.6초 흐려진다. 승인 알림은 답할 때까지 선다.

### claude 스크롤바·프롬프트 눈금 (`prompt_nav.rs`)

claude 칸이면 렌더러와 상관없이 선다. 그림·누름·단축키는 하나이고 정본만 둘이다 — classic 은 이 터미널의
스크롤백(절대 줄, `prompt_anchors` 의 `❯` 줄), 풀스크린(대체 화면)은 칸 안 mod(`collab-hooks/claude-mods/prompt-nav`)가
잰 행. 막대·눈금·누름이 같은 행 비례(`행 / 전체 행 × 홈 높이`)를 쓴다.

- 자리: 격자 오른쪽 여백(`PANE_INNER_X` 6) 가운데. 글자 칸·옆 창·claude 띠를 덮지 않는다. 홈은 classic 이면 칸 높이
  전체(입력 상자도 대화와 함께 흘러간다), 풀스크린이면 대화 맨 위부터 입력 상자 위 빈 줄 앞까지.
- 손잡이: 쉴 때 폭 3.5 · `with_alpha(text, 0x66)`(파일 트리 막대와 같다), 올리거나 끄는 중 폭 5 · `0x99` 에 홈
  `with_alpha(text, 0x14)`. 최소 높이 24, 모서리는 `pill_rect`. 전체가 한 화면에 들면 그리지 않는다.
- 프롬프트 눈금: 폭 6 · 높이 2, `with_alpha(accent, 0x80)`, 지금 보는 턴의 눈금만 `accent`. 누름은 위아래 4.
  눈금은 턴을 여는 줄마다 하나 — 사람이 친 것, tell·다른 세션·예약이 넣은 것, 슬래시 명령. 배경 작업 알림과
  SendMessage 전달은 아니다. claude 가 plugin 프롬프트 위에 그리는 출처 줄(`› Prompt from …`)도 세지 않는다.
- 누름 자리: 격자 끝 4 안쪽부터 여백까지(폭 `PANE_INNER_X + 3`) — 칸 경계의 나누기 손잡이는 남긴다.
- 동작: 눈금 = 그 프롬프트가 맨 위에, 손잡이 끌기 = 끄는 자리의 줄로, 홈 = 누른 자리가 가운데 오게.
  Option·Ctrl+↑↓ 가 앞뒤 프롬프트 — 앞은 지금 턴의 머리가 맨 위가 아니면 그 머리로, 맨 위면 하나 앞으로,
  마지막 다음은 맨 아래(따라가기). classic 은 kasaterm 이 키를 받아 옮기고, 풀스크린은 키가 claude 로 가 mod 단추가
  받는다. `/prompt-nav 3` 은 셋째 프롬프트(classic 은 mod 가 kasaterm 에 맡긴다).

    안쪽에 가로 스크롤이 있으면 그 칸이 먼저 가져간다(밀 거리가 없으면 쪽 넘김이 받는다).
  - 놓으면 반 넘게 갔거나 그쪽으로 튕겼을 때 넘긴다. 단추·점으로 바꾸면 240ms 미끄러진다. 동작 줄이기(`Look.still`)면
    손가락은 따라오되 놓는 순간·누르는 순간 바로 바뀐다.
  - 두 쪽과 두 입력줄은 살려 둔다 — 쓰던 글·붙인 사진·스크롤 자리가 남고, 입력칸에 초점이 있었으면 새 쪽 입력칸으로 옮겨
    자판이 내려가지 않는다. 대화 칸은 따로다(바로 치기 칸의 글은 이미 화면 입력상자에 가 있다). 밀어 둔 쪽은 움직임을 멈추고
    대화도 받지 않는다.
- **경고 띠**: `danger` 12% 바탕 + `danger` 글자, 모서리 12. 원색 채움 금지.
- **빈·실패 화면**: 문장 하나 + 다음 행동 단추(「다시 시도」 등). 문장만 두지 않는다. 쌍둥이 그림은 위 「쌍둥이 결」.
- **밝기**(`desktop_palette.dart`): 「데스크톱 따라감」은 데스크톱 팔레트 그대로, 밝게·어둡게는 **같은 팔레트를 그 밝기로
  뒤집는다** — 폰 기본색으로 가지 않는다. 바탕·면·선·글자는 OKLab 밝기만 바탕(밝음 .975 · 어두움 .25)↔글자(.25 · .93)
  사이에서 거울로 옮기고 색조·채도는 둔다. 강조·위험색은 원색을 지키고 새 바탕 위 4.5:1 까지만 민다(데스크톱
  `accent_text_bg` 와 같은 공식). 학생 색은 이름표라 그대로, 터미널 ANSI 16색은 그 밝기의 기본판. 명암은 테마 키가 아니라
  바탕 휘도(BT.601, 데스크톱 `is_light`)로 잰다.
- **켤 때 계정 확인**(`twins_loading.dart`): 쌍둥이 그림 둘(각 136 정사각, 동생을 언니 쪽으로 0.6 당김)이 반 박씩 엇갈려
  깡총 — 한 박 1.1초, 동생 12·언니 6 높이, 내려앉을 때 살짝 눌림, 발밑 그림자 6. 아래 24 띄워 「계정 확인 중」 15 `text_dim`
  + 차례로 켜지는 점 셋. 동작 줄이기(`disableAnimations`·iOS `reduceMotion`)면 서 있는 그림. 기다림 화면을 본 뒤의 다시
  확인은 그 화면 단추가 진행을 보인다.
- **예외 — 대화와 모달은 A 이전 모습**(2026-09-29 「대화랑 모달은 전이 더 나은데」). 쌍둥이 결이 이쪽으로 왔으니 이제
  예외라기보다 값이 조금 더 둥근 같은 얼굴이다.
  - 대화(나쵸 대화·학생 대화 보기): 말풍선. 내 말은 오른쪽 강조색 채움, 상대는 왼쪽 표면색 채움. 보내기는 채운 원 44.
    말풍선 모서리 16 · 말한 쪽 아래 모서리 4 · 안 여백 14×10 · 맞은편 여백 48(`SpeechBubble`). 예약(아직 안 간 내 말)은
    강조색 대신 `attention` 12% 바탕.
    붙여 두고 아직 안 보낸 사진은 입력줄 위에 48 정사각(작은 칸 모서리 8, 사이 8, 넘치면 옆으로 민다) + 「보내면 함께 가요」
    13 `text_dim`, 아래 8. 이 줄이 알려 주니 첨부 알림 띠는 띄우지 않는다(입력줄을 덮는다).
  - 모달(대화상자·아래 시트): 둥근 판(대화상자 모서리 28, 시트 위쪽 28)과 채운 주 동작 단추(모서리 12 — 쌍둥이 결의 단추와 같다).
    판은 테마가, 채운 단추는 `ModalLook` 이 맡는다 — 주 동작이 있는 대화상자·시트는 `ModalLook` 으로 감싼다.

## 4. 형태 규칙 — 목업에서 온 것

**플랫이다. 채움은 쓰지 않는다.**

- 버튼·세그먼트·스테퍼·입력칸·알약 — 전부 **채움 없이 테두리만.**
  고른 것은 강조색 테두리 + 강조색 글자. 올리면 한 톤 진한 회색.
  (2026-09-10 지시: 「버튼 아웃라인, 텍스트만 색 바꿔서. fill 은 x」)
- **토글**: 꺼짐 = 회색 테두리 + 회색 점, 켜짐 = 강조색 테두리 + 강조색 점.
- **행**: 왼쪽 이름(+보조글), 오른쪽 조작, 아래 얇은 선. 조작은 오른쪽 끝에 붙는다.
- **입력**: 한 줄은 이름 왼쪽·칸 오른쪽의 한 행. 여러 줄은 이름 위·칸 아래.
- **묶음 제목**: 작은 흐림 글자 하나(11pt `text_dim`). 설명은 제목에 붙이지 말고 행마다 보조글로.
- **옆 목록(nav)**: 구분선 없이 배경만 다르게. 머리글은 작은 흐림 글자.
- **카드는 쓰지 않는다** — 2026-09-10 에 걷어냈다. 카드처럼 보이는 것은 고르는 대상(테마·캐릭터)뿐이다.

## 5. 배치 규칙

- **읽기 열은 가운데 세운다.** 열이 `CONTENT_MAX_W` 에서 멈추므로 넓은 창에서 남는 폭을
  좌우로 갈라야 한다. 안 그러면 전부 오른쪽에 쌓여 글이 왼쪽 벽에 붙는다
  (2560 창에서 우여백 1026px 였다). → `content_column()`, 회귀 테스트 둘.
- **세로로 남는 공백은 채우지 않는다.** 항목이 적은 페이지 아래가 비는 것은 정상이다.
  페이지마다 다른 양을 내리면 카테고리를 바꿀 때 본문이 튀고, 이름은 헤더에 고정이라
  본문만 내려가면 이름이 떠 보인다.
- **개수를 고정하지 말고 폭에 맞춰 채워라.** 미리보기 얼굴·격자 열 수는 상자 폭에서 계산한다.
  고정 개수는 상자가 넓어진 날 가운데가 빈다.
- **없는 동작의 자리는 비우지 말고 이유를 적어라.** 번들 테마에는 이름 바꾸기·열기·지우기가
  없는데 그 모서리를 비워 두니 카드마다 줄이 어긋나 보였다. 못 쓰는 단추를 세우는 대신
  「기본」 알약을 같은 자리에 놓았다.
- **선택은 강조로 말하지, 요소를 빼서 말하지 마라.** 고른 카드에서 단추가 사라지면 격자가 깨진다.
- **창 칸은 크기가 같은 벤토 격자다.** 칸이 열리거나 닫힐 때마다 방 전체를 다시 짠다(`layout.rs rebento_window`).
  칸 하한은 셸 격자로 40칸×16줄(`BENTO_MIN_COLS`·`MIN_PANE_ROWS`) — 이보다 작아질 때만 새 칸을 연 칸의 탭으로
  보낸다. 터미널이 아닌 것(웹·문서·이미지)은 칸을 차지하지 않고 연 칸의 탭으로 연다.

## 6. 글자

### 팔레트 미리보기

- 첫 선택 줄은 Graphite·Ink·Paper·Mist 네 개만 색 미리보기로 보여 준다. 폭 560px 이상은 4열, 그 미만은 2열이며 간격은 8px이다.
- 각 선택은 높이 64px로, 실제 pane·header·sidebar 토큰을 쓰는 32px 미리보기와 간격 6px·공통 26px 이름 버튼으로 구성한다.
- 선택 중인 기존·커스텀 팔레트는 현재 이름을 계속 표시한다. 나머지 프리셋은 기본 접힘 「다른 팔레트」에서 고르며 삭제하지 않는다.
- 설정의 앱 미리보기는 Rust 네이티브로 높이 204px에 헤더·사이드바·분할 터미널·우측 패널을 그린다. 영역을 누르면 같은 색 편집기에 연결한다.
- `bg`는 창 바탕, `pane_bg`는 터미널 기본 배경, `header_bg`는 타이틀·pane 헤더, `sidebar_bg`는 사이드바·좌우 패널이다. 후자의 세 값이 없으면 기존 팔레트 값에서 유도한다.
- 기존 기본색 11칸·ANSI 16칸의 순서를 유지하고 역할색 세 칸은 마지막에 추가한다. 저장·미리보기·실제 렌더가 같은 값을 읽는다.
- 미리보기는 12pt 본문·10.5pt 보조글과 26px 헤더를 사용한다. 색 이름을 항상 함께 보여 주며, 선택은 강조색 테두리로 표시한다.
- Graphite·Ink·Paper·Mist는 본문·보조글을 창·입력·패널 바탕에 대조한 대비가 모두 4.5:1 이상이다. 새 색 조합은 같은 역할별 대비 검사로 검증한다.

- 본문 12 · 보조글 10.5 · 묶음 제목 11 · 페이지 이름 20 · 카드 이름 14 · 알약 9.5 (pt, 논리)
- 넘치는 글자는 `fit(g, text, 가용폭, 크기, 굵게)` 로 자른다. 직접 자르지 마라.
- UI 글꼴은 `theme::ui_font()`. 터미널 글꼴과 다른 축이다.

## 7. 고칠 때 지킬 것

### 자체 브랜드와 다음 시각 방향

- 모바일의 표시 이름은 `KASA Mobile`이다. 내부 bundle ID·Keychain 식별자는 바꾸지 않는다.
- 제품 로고·기본 배경·기본 캐릭터는 KASA 자체 에셋을 사용한다. 특정 작품의 로고·학교·교실 그림을 제품 기본 얼굴로 배포하지 않는다. 사용자 소유 테마 파일과 기존 세션의 이름·주소는 보존한다.
- 자체 캐릭터의 기준은 하늘색 긴 트윈테일과 차분한 눈의 언니, 호박색 경단머리와 활발한 표정의 동생, 두 색의 우산이다. 기존 시안은 보존하며 새 제작물의 입력·모델·원본 위치를 함께 기록한다.
- 모바일 UI 글꼴은 Pretendard 400/600을 기준으로 한다. 터미널 격자는 별도 고정폭 글꼴과 한글 두 칸 규칙을 유지한다. 글꼴 이름·공통 테마는 계정 설정으로 동기화하고 로컬 글꼴 파일 경로는 보내지 않는다.
- 다음 디자인 방향은 **비에 젖은 유리**다: 은은한 투명 표면·절제된 물방울·하늘색과 호박색 빛. 이번 로그인/업데이트 구현의 완료 조건에는 유리 셰이더 구현을 포함하지 않는다.
- 유리 효과는 장식이며 가독성을 대신하지 않는다. 글자 뒤에는 안정된 표면을 두고 텍스트 대비 4.5:1, 상태 경계 3:1을 검증한다. 투명도 감소 설정과 저성능 환경에는 불투명 표면을 제공한다. 입력·스크롤 중 지속적으로 움직이는 물방울은 기본값으로 넣지 않는다.

### 공통 조작 부품과 닫기

- 구현 정본은 `native_controls.rs`다. 설정·문서 창·우측 패널은 같은 버튼 페인터를 쓴다.
- 텍스트 버튼은 높이 26px, 본문 12pt, 좌우 여백 10px다. 아이콘 버튼은 26×26px, 그림은 14px다.
- 설정 행의 이름·보조글과 토글에도 같은 10px 안쪽 여백을 둔다. 포커스 테두리가 글자나 토글 외곽과 겹치지 않아야 한다.
- 우측 패널 머리의 아이콘 버튼 간격은 8px, 줄바꿈 탭의 줄 높이는 30px다. 다음 줄의 클릭 영역이 윗줄 버튼에 겹치지 않는다.
- 보이는 버튼과 클릭 영역은 같은 사각형이다. 선택·주 동작은 강조색 테두리, 일반은 기본 테두리, 호버는 밝은 글자·테두리다. 채움색으로 상태를 덮지 않는다.
- 설정의 Tab·Shift+Tab은 전체가 보이는 활성 조작을 순환한다. Enter·Space는 한 번만 실행하고, PageUp·PageDown은 본문을 이동한다.
- 스크롤·카테고리·팝업 변경 후 이전 좌표로 조작하지 않는다. 잘린 색 선택기는 원래 색판 좌표로 값을 계산하고, 한 줄 입력 커서는 실제 그린 글리프 경계를 사용한다.
- 비활성 버튼은 흐린 글자이며 클릭 영역에 등록하지 않는다. 위험한 동작은 위험색과 동작 이름을 함께 쓴다.
- 마우스를 켠 TUI(DECSET 1003, Claude Code 전체화면) 위에서는 버튼 없이 움직여도 칸이 바뀔 때마다 이동을 넘긴다 —
  앱의 호버 효과(×가 밝아지는 것 등)는 이걸 받아야 그려진다. 넘긴 칸을 앱이 같은 글자로 모양만 바꿔 그리면
  누를 수 있는 것으로 보고 손가락 커서를 띄운다. 앱이 포인터 모양 신호(OSC 22)를 안 보내서 이것이 유일한 단서다.
- 키보드 포커스는 실제 클릭 영역 안쪽에 2px 강조색 테두리로 표시한다. Tab/Shift+Tab은 활성 조작 사이를 이동하며 Enter/Space는 한 번만 실행한다.
- 문서 편집의 Tab 들여쓰기는 유지한다. F6으로 문서 도구모음에 진입하고, 도구모음에서 Tab으로 이동하며 F6/Esc로 문서에 돌아간다.
- `x`는 오른쪽 위에서 **현재 화면을 닫기**다. 패널 닫기는 패널만 숨기고 실행 중인 작업을 종료하지 않는다.
- 세션 종료는 `세션 종료` 또는 `작업 종료`로 표시한다. 패널의 `x`와 같은 이름·설명을 사용하지 않는다.
- 문서 창의 `x`는 저장하지 않은 편집 확인을 거친다. 팝오버 바깥 클릭·Esc는 팝오버만 닫는다. 종료 확인을 자동 승인하지 않는다.
- 설정의 Esc는 열린 선택 목록, 편집 중인 입력, 버튼 포커스를 먼저 해제한다. 해제할 대상이 없을 때만 설정을 닫는다. Enter·Esc를 계속 누르고 있어도 닫힌 확인창 뒤로 입력이 전달되지 않는다.
- 확인창이 열려 있으면 키보드와 IME 입력은 맨 위 확인창만 소유한다. Git 커밋 확인창의 Enter는 화면에 선택한 포함 범위를 지킨다.
- 새 화면은 공통 부품을 사용하고, 기존 화면을 수정할 때 같은 역할의 사설 페인터를 함께 걷는다.

1. 값이 필요하면 **여기서 찾고**, 없으면 여기 추가한 뒤 쓴다.
2. 치수를 파일 안 `const` 로 새로 만들지 마라 — 위의 「아직 정돈 안 된 곳」이 그렇게 생겼다.
3. 눈으로 판정하기 전에 **px 로 재라.** 판독은 틀린다(2026-09-22: 「여러 페이지 하단이 비었다」가
   실제로는 한 페이지뿐이었고, 「카드 오른쪽 절반이 빈다」는 카드는 실제로 차 있었다).
   재는 법은 [`verify-app.md`](verify-app.md).
4. 배치 계산은 순수 함수로 빼고 테스트를 걸어라. 걸었으면 **한 번 깨뜨려** 잡히는지 확인해라.
