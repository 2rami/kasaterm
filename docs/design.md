# 디자인 정본 — 색·모양·치수와 그 뒤의 규칙

화면을 만들거나 고치기 전에 읽어라. 이 문서는 합의한 디자인의 기록이며 이전 모양을 고정하는 제약이 아니다. 사용자가 전면 개편을 요청하면 기존 값부터 재검토하고, 비교·검증한 새 기준을 문서와 공통 코드에 함께 반영한다.
공유 토큰을 바꿀 때는 그리기·레이아웃·클릭 영역을 함께 맞춘다. 선택 전의 시안 값은 기본값으로 승격하지 않는다.

이 문서가 생긴 이유: 설정 화면은 HTML 목업에서 옮겨 왔는데 **그 목업이 레포에 없다.**
치수와 규칙이 `native_settings.rs` 주석 13군데에 파편으로만 남아, 새 화면을 만들 때
참고할 정본이 없었다. 아래는 그 파편과 `theme.rs` 의 토큰을 한자리에 모은 것이다.

> 값은 현재 체크아웃에서 재확인할 것. 이 문서는 정본이지만 코드가 최종이다.

## A · Cloud OS — 채택 및 정렬 보정

사용자는 A를 선택했고 고정 좌표·글자보다 큰 버튼·정렬 문제의 보정을 요청했다. 아래 비교 값은 시안 기록이다. 실제 공통 UI는 A의 표면과 여백을 따르되 조작부를 글자에 맞춰 다듬는다.

| 기준 | A · Cloud OS | B · Precision | C · Playroom |
|---|---|---|---|
| 기본 바탕 / 패널 | #EAF0F8 / #FFFFFF | #161A20 / #20262E | #F6EFF8 / #FFFCFF |
| 글자 / 보조글 | #24344D / #667790 | #E8EEF5 / #9BAAB8 | #493850 / #806989 |
| 강조색 | #2F6FD4 | #65CABB | #A35485 |
| 버튼 / 행 | 36 / 58 | 28 / 42 | 40 / 64 |
| 판 모서리 / 버튼 모서리 | 20 / 12 | 6 / 4 | 26 / 18 |
| 간격 / 본문 글자 | 24 / 13 | 14 / 12 | 24 / 14 |
| 탐색 | 208px 떠 있는 탐색 판 | 184px 고정 도구 목록 | 78px 얼굴·아이콘 레일 |

아래는 선택 전 비교 시안의 기록이며 공유폴더 샘플은 제품 화면에서 제거됐다. 비교 화면은 같은 설정·작업 공간·공유 폴더 샘플을 사용했다. 720px 미만은 탐색을 상단 세 버튼으로 합치고 내용은 세로로 흐른다. 설정 본문 780px 미만은 작업 미리보기를 아래로, 공유 화면 680px 미만은 파일 미리보기를 아래로 옮긴다. 각 화면은 독립 스크롤하고 잘린 클릭 영역은 받지 않는다. 작업 화면의 Info는 300px, 터미널은 최소 260px이고 아래 18px 간격·60px 작업 요약과 바닥 16px를 남긴다.

비교 시안은 54px 앱 머리, 18px/0px/20px 바깥 여백을 사용한다. 제목 28px(B는 22px), 설정 묶음 제목 16px(B는 14px), 아이콘 18px, 화면 안 입력칸과 선택칸은 각 안의 버튼 높이를 따른다. 판 그림자는 A는 얇은 두 겹, B는 없음, C는 강조색의 낮은 농도로 구분한다. 배경 블러를 구현했다고 표현하지 않는다.

### 실제 앱의 공통 배치 계약

- 일반 조작부는 32px·글자 13px·좌우 여백 12px, 좁은 도구 모음은 최대 26px·글자 12px·좌우 여백 10px다. 주어진 칸보다 크게 그리지 않는다. 행은 기본 48px이며 긴 설명은 실제 줄 수만큼 늘어난다.
- 동작 버튼의 너비는 실제 글꼴의 글자 영역과 전진 폭 중 넓은 값 + 좌우 여백으로 결정한다. 선택 탭·분할 선택처럼 폭을 공유해야 하는 부품만 할당된 칸을 채운다. 버튼 묶음은 측정한 너비로 8px 간격을 두고 부족하면 다음 줄로 내린다.
- 버튼의 글자는 글리프 bearing·높이로 잰 실제 그려지는 영역을 기준으로 가운데에 둔다. 그리기와 클릭·키보드 포커스는 같은 사각형을 쓴다. 소수 배율에서는 장치 픽셀에 맞춰 정렬한다.
- 기본 둥근 모양은 조작부 12px·패널 20px다. 설정은 208px 탐색 판과 본문 판 사이 16px, 본문 안쪽 24px를 사용한다. 외형 본문은 최대 1100px, 780px 이상에서 설정과 실제 작업 미리보기를 나란히 둔다. 작업 미리보기는 높이 224px 안에 각 영역을 6px 안 여백·5px 간격으로 놓고 색 선택 버튼도 내용 너비로 흐른다.
- 팔레트·강조색은 현재 사용자 색을 공통 표면에 적용한다. 그림자는 별도 흐림 패스 없이 낮은 농도의 둥근 사각형으로 만든다.

## 1. 색 — `theme.rs`

색은 **직접 쓰지 않는다.** 전부 `theme::` 함수를 거친다. 테마를 갈면 같이 따라가야 하기 때문이다.

`Palette` 한 벌이 화면 전체를 덮는다:

| 갈래 | 필드 |
|---|---|
| 바탕 | `bg` `fg` `surface` `surface_hover` `surface_active` |
| 선 | `border` |
| 글자 | `text` `text_dim` `text_mute` |
| 뜻 | `success` `danger` |
| 코드 | `syn_keyword` `syn_string` `syn_number` `syn_comment` `syn_function` `syn_type` |
| 터미널 | `ansi[16]` |

- 프리셋은 `THEME_PRESETS`(System·Light/Dark/Light/Catppuccin/Gruvbox/Tokyo Night/Sky/Amber CRT/나초네코),
  강조색은 `ACCENT_PRESETS`. 사용자 정의 테마는 `custom_*` 계열로 같은 `Palette` 를 채운다.
- **`Palette` 에 없는데 `theme::` 에는 있는 것들이 있다.** `panel_bg()` 는 `bg` 와 `surface_hover` 를
  반씩 섞어 만들고, `accent()` 는 팔레트가 아니라 `ACCENT_PRESETS` 에서 따로 온다. 자리마다 배경이
  달라 고정 토큰을 못 쓰는 것들(판 위에 올라온 버튼의 채움 등)은 `base` 를 받아 계산한다.
  **함수가 있으면 함수를 써라** — 필드 목록에 없다고 새로 만들지 마라.
- 반투명이 필요하면 `theme::with_alpha(theme::border(), 140)` 처럼 **기존 색에 알파를 얹어라.**
  새 회색을 만들지 마라 — 라이트 테마에서 혼자 안 따라간다.

## 2. 모양 — `theme.rs` 의 `Shape`

| 필드 | 뜻 |
|---|---|
| `radius_sm` `radius_md` | 모서리 두 단계 |
| `border_w` | 구조선 두께 |
| `shadow_offset` | 흐림 없는 그림자 거리(0 = 없음). 누르면 줄어드는 그 어긋남이 「물체」로 읽힌다 |
| `roundness` | 원·알약이 네모로 굽는 정도(1 = 정원, 0 = 정사각). **반지름과 별개다** — 6px 점과 200px 판이 같이 굽으면 안 된다 |
| `pixel_chrome` | 글자·아이콘을 도트 에셋으로. 중간값이 없어 별도 축이 아니라 여기 얹었다 |

프리셋 셋: `rounded`(12/20, 패널에 낮은 농도의 그림자) · `sharp`(2/3) · `pixel`(0/0, 선 2px, 그림자 3px, 도트).
둥근 채움·테두리는 한 GPU 인스턴스의 거리 함수로 그린다. 반경은 장치 픽셀의 0.5px, 선 두께는 0.25px 단위로 전달하고 1px 가장자리만 보간한다. 작은 사각형으로 모서리를 조립하지 않는다.
원·알약은 `circle_rect` / `pill_rect` 를 거쳐라. `radius_sm` 으로 원을 그리지 마라.

## 3. 치수

### 설정 화면 (정돈된 기준 — 새 화면은 이걸 따라라)

| 이름 | 값 | 자리 |
|---|---|---|
| `HEADER_H` | 60 | 페이지 이름이 앉는 머리 칸. 본문은 그 아래 14px 에서 시작 |
| `ROW_H` | 48 | 설명 길이에 따라 늘어나는 설정 행 |
| `CTL_H` | 32 | 조작 부품 높이(버튼·입력칸·스테퍼) |
| `CONTENT_MAX_W` | 800 | 읽기 열 상한 |
| 묶음 제목 | 위 30 · 아래 24 (합 54) | `section_title` 뒤에 `*y += 54.0` |
| 열 좌우 여백 | 24 (좁은 창 16) | 상단 탐색에서는 12 |

- 설정 탐색은 머리글 아래 검색칸(높이 32px)을 거쳐 82px부터 하단 돌아가기 버튼 위 8px까지 쓴다. 돌아가기는 하단 46px 위치의 32px 행으로 고정한다.
- 검색은 설정 페이지 이름·관련 낱말을 함께 찾는다. 검색 중 묶음 머리는 생략하고 결과 없음·지우기를 제공한다. Cmd/Ctrl+F로 진입하고 Enter로 첫 결과를 연다.
- 일반 텍스트 편집 중에는 하단에 편집 상태와 내용 너비의 32px 완료·취소 버튼을 둔다. 버튼은 폭이 부족하면 줄바꿈한다. 로그인·기기 연결 폼은 각자의 명시적인 제출 버튼을 사용한다.
- 연결 기기는 이 기기 → 다른 기기 → 브라우저·자동 전환의 순서다. 기기 행은 60px로 아이콘·이름·상태를 표시하고, 기기 이름과 연결 정보 편집을 구분한다.
- 기기 추가·수정은 두 입력칸을 세로로 배치한 초안이며 저장 전에는 명부를 쓰지 않는다. 오류는 폼 안에 남기고 삭제는 대상 이름을 확인한 뒤 실행한다.
- 화면 표시 이름(연필)과 명령·연결에서 쓰는 연결 이름(연결 정보)을 구분한다. 검색과 연결 초안은 계정 동기화를 막지 않으며, 연결 저장 시 편집 전 항목과 대조해 다른 기기 항목을 덮지 않는다.
- 공통 버튼의 강조·위험 글자는 설정 바탕과 최소 4.5:1, 키보드 포커스 테두리는 최소 3:1로 보정한다. 표면·색 선택은 아래 OS 스타일 규칙을 따른다.
- 설정 패널 폭이 600px 미만이면 탐색은 상단 3~4열로 재배치하고 짧은 메뉴 이름을 쓴다. 기기 폼 폭 420px 미만에서는 라벨 20px → 입력 32px → 간격 8px로 쌓아 라벨을 자르지 않는다.
- 32px 행·4px 간격과 묶음 제목 24px가 전부 들어가지 않으면 묶음 제목을 접고 작은 조작 26px 행·2px 간격으로 줄인다.
- 검색칸을 포함한 낮은 창에서 간격만 2px로 줄이면 모두 보이는 경우에는 그렇게 배치하며, 행 높이는 26px를 유지한다.
- 그래도 높이가 모자라면 탐색 목록만 독립 스크롤한다. 그리기와 클릭 영역을 같은 탐색 뷰포트로 잘라 본문·하단 버튼과 겹치지 않게 한다.
- 일반 안내문은 테두리 없는 `plain_hint`를 공유한다. 10.5pt·줄높이 18px로 전체 문장을 감싸며 고정 높이·말줄임을 쓰지 않는다.
- 옆 목록은 묶음 셋 — 화면(외형·앱 하단바·날씨)·에이전트(계정·코딩 에이전트·캐릭터)·앱(앱 일반·연결 기기·펫·피드백).
  묶음 머리는 24px, 묶음 안은 자주 여는 것이 위다. 시작 자리는 `NAV_GROUPS` 한 곳이다.
- 칩·카드 묶음 위 이름(`row_label`)은 위 10·글 20 — 바로 위 행 밑줄에 글자를 붙이지 않는다.
- 페이지 안 묶음 머리는 전부 `section_title`(11 `text_dim`)이다. 12.5 굵은 사설 머리를 따로 만들지 않는다.
- 고를 것이 열 개를 넘는 목록(글꼴·팔레트 슬롯)은 칩을 깔지 말고 선택 상자(`dropdown_row`)로 한 줄에 둔다.
- 보이는 모습을 바꾸는 칸은 「외형」 한 페이지에 모은다(2026-10-06): 팔레트·강조색·모서리·대비·글자 크기·UI 배율·UI 글꼴·탭 위치·
  창 상태줄·pane 하단바 높이·터미널 글꼴·커서·기기 아이콘. 「앱 일반」은 시작·파일·셸·편집 감각만 둔다 — 셸만 남은 「터미널」 페이지는 여기 합쳤다(2026-10-07).
- 「캐릭터」 페이지는 지금 테마 이름과 「테마 관리」 단추만 둔다. 테마 고르기는 「캐릭터 테마」 페이지 카드 한 곳이다(첫 실행 화면은 칩 그대로).

### 결과 파일 접근

- PC Info와 모바일 허브에 별도 공유폴더 목록을 두지 않는다. 설정의 공유폴더 관리도 제거한다.
- 결과물은 작업한 프로젝트·출력 폴더에 저장하고 대화에 파일 링크를 남긴다. 사진은 인라인 표시 블록으로 보여 준다. 공유폴더에 복사하는 절차를 기본 지침으로 요구하지 않는다.
- 기존 파일과 기기 간 전송 저장소는 유지한다. 폴더 목록을 사용자 기본 동선으로 되살리지 않는다.

### 빠른 설정 (첫 실행)

- B안: 캐릭터·모양·코딩 에이전트·터미널의 현재 값을 한 화면에서 요약하고 한 영역씩 펼친다.
- 옆 목록 폭은 190px(760px 미만 154px, 600px 미만은 같은 섹션 동작이 있는 본문 요약 행으로 통합), 읽기 열은 최대 800px로 남는 공간의 가운데에 둔다.
- 핵심 요약 행은 64px. 본문 폭 470px 미만에서는 값을 다음 줄로 내려 80px로 늘린다.
- 미리보기는 112px, 하단 시작·건너뛰기 영역은 62px로 고정해 펼친 내용만 스크롤한다.
- 안내·오류가 있으면 하단을 40px 늘려 피드백이 스크롤에 가려지지 않게 한다. 스크롤바는 본문 밖 14px 여백에 둔다.
- 일반 안내문은 박스 없이 보조글 10.5pt, 줄높이 18px로 접어 표시한다.
- 상세 펼침 행은 일반 설정과 같은 40px이며, 접힌 상태가 기본이다.
- 시안의 임의 모델명·글꼴·팔레트와 카드 장식은 구현 값으로 채택하지 않는다.

### 작업현황 판 (보드 방 첫 탭)

### 대화 기록 (오른쪽 열)

- 탭 이름은 「기록」, 본문 제목은 「대화 기록」이다. 이 기기에 저장된 과거 대화이며, 현재 실행 목록이 아님을 설명한다. 「닫은 칸」은 별도 보기로 분리해 기록을 가리지 않는다.
- 좌우 여백 14px, 본문 제목 14pt, 행 제목 12pt·보조 10.5pt, 얼굴 26px다. 행 높이 80px·안 여백 10px로 제목 → 대화 발췌 → 폴더·시각을 구분한다. UUID를 제목으로 쓰지 않는다.
- 범위는 「현재 폴더 / 이 기기 전체」이며 Claude·Codex 종류 필터를 제공한다. 실제 폴더 이름을 범위 아래 표시하고, 폴더가 없으면 전체 목록인 척하지 않는다.
- 대화 행을 누르면 선택만 한다. 선택한 행 아래에 발췌와 작업 폴더를 감싸 표시하고 「새 방에서 이어가기」를 눌러야 실행한다. 선택은 하네스+세션 ID로 유지하며 목록 재정렬·새 수집 뒤 다른 대화로 바뀌지 않는다.
- 닫은 칸의 「다시 열기」와 「실행 종료 / 목록에서 지우기」는 별도 버튼이다. 종료·삭제는 한 번 더 확인하며 일반 행 클릭으로 실행하지 않는다.
- 주 동작·범위 필터는 공통 네이티브 버튼이다. 목록은 독립 스크롤, 4px 손잡이(최소 24px)를 표시하며 넘친 글은 말줄임 또는 줄바꿈한다. Tab/Shift+Tab으로 보이는 동작을 고르고 Enter/Space로 실행하며, 포커스는 즉시 표시한다. 자주 훑는 목록에 장식 진입 애니메이션을 추가하지 않는다.

### 기기 이름 (설정 「연결 기기」 맨 위 · 폰 설정 「기기 이름」)

- 계정이 기계 id 에 붙이는 화면 이름(`device_names`). 기기 이름을 그리는 자리는 `pane_identity::device_name`(PC)·
  `machineName`(폰)을 거친다 — 기기 제 이름을 그대로 그리지 않는다. 아이콘·길은 제 이름으로 찾는다.
- PC: 묶음 제목 「기기 이름」(12.5 굵게) + 보조글 10.5 `text_mute` 한 단락, 그 아래 기기마다 `ROW_H` 40 한 줄.
  아이콘 `ICON_SIZE`(x 0) · 이름 12 `text`(위 5) · 둘째 줄 10.5 `text_mute`(위 22, 「원래 이름 …」 또는 「이름을 안 붙였어요」,
  이 기기면 「 · 이 기기」) · 오른쪽 연필 `CTL_H` 26 칸. 줄 아무 데나 누르면 그 자리에 입력칸(`CTL_H`, 글 시작선과 같은 x)이 서고
  아래 안내 한 줄(10.5 `text_dim`, 18). 줄 사이 1px 선(`border` 알파 140).
- 폰: 설정 「데스크톱」 묶음의 한 줄(계정으로 붙었을 때만) → 기기 이름 화면. 기준 기기 먼저, `~id` 로 닿는 계정 기기만
  (id 를 모르는 기기엔 이름을 못 붙인다). 누르면 입력 대화상자(40자, 「원래 이름으로」·「그만」·「바꾸기」).

### 기기 아이콘 설정

- 모양 설정에 기기별 아이콘을 둔다. 이름 행은 `ROW_H` 40, 아이콘은 `ICON_SIZE`를 쓴다.
- 자동·노트북·데스크톱·서버·모바일은 기존 선택 칩으로 고른다. 폭이 모자라면 다음 줄로 감싼다.
- SVG 가져오기(110)와 초기화(64)는 높이 `CTL_H` 26, 간격 6이다. SVG는 `text_dim`으로 그린다.
- 데스크톱에서 기기는 색 대신 아이콘·이름으로 구분한다. 본문·헤더·파일트리·Git 칼럼·배치도는 기기와 무관한 테마색을
  쓴다. 기존 기기 배지의 바탕은 해당 바탕과 `text`를 8% 섞고 글·아이콘은 대비 4.5 이상인 `text_dim`이다.
  학생색·초점·작업·경고 표시는 유지한다. 기기 색 고르기는 없애되 저장값·동기화 필드는 구형 클라이언트 호환용으로 보존한다.

### 하단바 칸 (`render.rs` 상태줄)

- 칸 = 아이콘 12 + 값. 아이콘·값은 늘 `text_dim`(사람이 칸 색을 정했으면 그 색)이고, 팝오버가 열린 칸만 `text`.
  **글자색으로 상태를 말하지 않는다** — 칸마다 글자색·강조색·점을 섞어 써 같은 「연결됨」이 달라 보였다(2026-09-29).
- 상태는 값 뒤 점 하나: 지름 4, 값과 사이 4(`STATUS_DOT`·`STATUS_DOT_GAP`). `success` 연결·켜짐 · `attention` 중계·느림·
  고를 것 있음 · `danger` 끊김·빌드 다름·로그인 필요 · `accent` 할 일 있음(새 판) · `text_mute` 꺼짐·모름.
  개수·클립보드처럼 상태가 없는 칸은 점을 안 단다. 아이콘만 남는 좁은 폭에서는 점도 뺀다.
- 경고(자원)만 예외: 삼각형 아이콘이 뜻 색, 글은 `text`. 사용량 게이지의 % 숫자 색은 한도 임계값이라 이 규칙 밖이다.

### PC 사이드바 폭 단계 (`chrome::Density` · `chrome/sidebar.rs`)

- 기준은 창 폭이 아닌 실제 사이드바 논리 폭이다. 기존 Icon(<124)·Compact(124~167)·Full(168~319)을 유지하고 Wide(320~479)·Spacious(480 이상)를 더한다. 다른 칼럼의 `Density::of` 문턱은 바꾸지 않는다.
- 목록 행은 Icon·Compact 28px 한 줄, Full 40px 제목·진행 눈금, Wide 48px 제목·상태 설명, Spacious 56px 제목·상태 설명이다. 얼굴은 20px, Spacious는 26px다. 상태 설명은 확인 필요·작업 중·백그라운드 작업·입력 대기·닫힌 칸을 구분하고 경과 시간은 오른쪽에 예약한다. 부제 시작은 위 22px(56px 행은 29px)이며 눈금은 마지막 6px 위치에 둔다.
- 목록·배치도 전환은 Wide부터 높이 32px·폭 88px의 이름 단추, 그 아래는 기존 아이콘 단추다. 간격은 6px다. 기기 머리는 Wide부터 새 방 단추를 76px로 넓혀 이름을 붙인다. 하단 44px 트레이는 고정하고 Wide부터 기기 추가의 연결 설명을 함께 표시한다.
- 방 머리는 54px를 유지한다. Wide부터 이름 줄 오른쪽에 작업·확인 수를 표시하고 제목 폭을 최소 100px 예약하고 요약과 12px를 띄운다. 폴더·접힌 방 요약과 펼치기·닫기·단축키는 기존 위치를 따른다.
- 배치도는 실제 칸의 배치를 보존한다. 기본 높이 `clamp(36 + 13 × 칸 수, 46, 150)`에 Wide부터 `사이드바 폭 / 240`(최대 2.2)을 곱한다. 칸 폭 80px·높이 60px 이상이면 아래 18px를 제목에 주고 얼굴 상한을 Wide 40px·Spacious 48px로 늘린다. 칸 제목은 10.5pt, 좌우 6px이며 아래 탭 점·진행 눈금 10px를 남긴다.
- 별도창은 좁을 때 최대 폭 40px·행 높이 30px, Wide부터 최소 폭 120px·행 높이 64px 타일로 가능한 열 수를 채운다. 타일 간격 3px, 넘치는 칸은 다음 줄로 보내며 높이·스크롤·히트 영역을 같이 늘린다.
- 보관 행·창 밖 셸은 기본 22px, Wide부터 40px로 제목과 보관 사유 또는 폴더·실행 상태를 나눈다. 좁은 폭에서는 장식·부제부터 접고 닫기·펼치기 동작은 남긴다. 창 밖 셸의 일괄 닫기는 168px 미만에서 26px 아이콘 단추다.
- 로컬 방·원격 방은 같은 높이 계산을 쓴다. 스크롤 한계·렌더·클릭은 같은 폭의 측정값을 공유하며, 폭 변경 시 숨겨진 히트 영역을 남기지 않는다.

### 끊긴 기기 (`sidebar_navigation.rs` 기기 절 · `statusbar.rs` 기기 연결 · `info.rs` 기기 메뉴)

연결 기록의 판정·이유는 [machine-link.md](machine-link.md). 여기엔 모양만.

- 명부에 있는 기기는 끊겨도 기기 절을 지우지 않는다. 머리 둘째 줄(9.5pt `text_dim`)은 「끊김 · 이유 · 마지막으로 닿은
  시각」 — 하루 안이면 `15:32`, 그 전이면 `2일 전 15:32`, 닿은 적이 없으면 「닿은 적 없음」. 폭이 모자라면 잘린다.
- 본문은 방 대신 줄 하나(44, `PANE_H`): 위 8 에 이유 전문(11pt `text_dim`), 위 25 에 「15:32까지 · 방 N개는 붙으면 돌아와요」
  (10pt `text_mute`, 기본 폭 240 에서 안 잘리는 길이). 재시작 전에 보던 그 기기 방이 다시 열리기를 기다리면 그 줄은
  「보기 방 N개는 붙으면 다시 열려요」. 지난 방을 흐리게 남기지 않는다 — 누르면 닿지 않는 기기에 거울을 열게 된다.
  다시 붙으면 폴링이 방을 저절로 되돌린다.
- 명부에서 빠진 기기(손님 기한·명부 파일 못 읽음·계정 동기화 주소 못 풂)도 같은 모양으로 남는다. 설정에서 사람이 지운
  기기만 바로 사라진다.
- 머리의 이름·상태 자리(+ 단추 왼쪽까지)에 올리면 연결 기록 툴팁 — 사이드바 툴팁과 같은 판(`draw_hover_tip`). 첫 줄
  「<기기> 연결 기록」, 그 아래 새 것부터 8개(「15:32 끊김 · 이유」·「15:40 붙음」), 끝에 「원문: …」 한 줄.
- 하단바 기기 연결 칸은 끊긴 기기도 센다 — 「직통 2·끊김 1」, 다 끊기면 「끊김 N」. 점 색은 붙은 길의 질만 본다(다 끊겼을
  때만 나쁨) — 늘 꺼져 있는 기기 하나가 점을 늘 빨갛게 두지 않게. 팝오버의 끊긴 줄은 오른쪽에 「끊김 · 15:32」(11pt
  `text_mute`), 그 아래 14 를 더 써서 이유 한 줄(10pt `text_mute`, 이름과 같은 x 32).
- 기기 메뉴(머리의 …)의 끊긴 기기 줄도 같은 「끊김 · 이유 · 시각」.

### 일하는 중 표시 — 테두리 한 바퀴 (`theme::activity_edge` · `gpu.activity_outline` · 폰 `OrbitEdge`)

끝을 모르는 「일하는 중」은 쓸려 지나가는 막대가 아니라 **칸 윤곽을 빛 조각이 한 바퀴씩 돈다**(2026-10-07 「아웃라인 PC 랑
모바일 둘 다 프로세스바 걷어내고」, 같은 날 「숨쉬는 거 헷갈리는데 선택이랑. 한 바퀴 도는 거로 하자 아웃라인을」). 숨쉬던
테두리는 가장 진할 때 초점 테두리와 같아 고른 칸이 어디인지 흐려졌다. 이제 **멈춘 실선 = 지금 보는 칸, 움직이는 윤곽 =
도는 중**이다. 끝이 있는 compact 진행 눈금·%는 그대로다.

- 일하는 중: 학생색 빛 조각 하나가 왼쪽 위에서 시계 방향으로 **2초에 한 바퀴**. 머리가 가장 굵고 진하며 꼬리 끝으로 가며
  1 까지 가늘어지고 직선으로 옅어진다. 꼬리는 둘레의 **0.2**(칸 크기와 상관없이 같은 모양). 모든 칸이 같은 위상으로 돈다.
- 뒤에서 도는 중(백그라운드 셸·Monitor·서브에이전트): 같은 윤곽을 **점선**(선 몫 0.6)으로 긋고 무늬가 **2초에 한 칸**씩
  시계 방향으로 흐른다. 이 칸은 프레임을 펌프하지 않아 무늬가 자주 멈춰 서는데, 멈춘 점선도 실선(초점)과 갈린다.

  | | 모양 | 굵기 | 점선 한 칸 | 알파 초점 / 아님 |
  |---|---|---|---|---|
  | 일하는 중 · pane | 한 바퀴 2초 · 꼬리 0.2 | 머리 3 → 꼬리 1 (초점 아님 2.5 → 1) | | `ff` / `b3` |
  | 뒤에서 도는 중 · pane | 점선 2초 한 칸 | 1.5 (초점 아님 1) | 8 | `cc` / `80` |
  | 일하는 중 · 배치도 칸·목록 줄 | 한 바퀴 2초 · 꼬리 0.2 | 머리 2.5 → 1 (아님 2 → 1) | | `ff` / `cc` |
  | 뒤에서 도는 중 · 배치도 칸·목록 줄 | 점선 2초 한 칸 | 1 | 6 | `cc` / `99` |

  배치도 칸·목록 줄은 작아서 초점 아닌 쪽도 pane 보다 진하다.
- 초점: 분할의 초점 학생 칸(1.5)·줌(2)·배치도의 고른 칸(1.5)은 도는 중에도 **멈춘 실선**을 그대로 두고, 움직이는 윤곽은 그
  **안쪽**을 돈다. 같은 색이면 실선과 한 줄로 뭉쳐 꼬리가 묻히므로 안쪽 윤곽은 글자색 쪽으로 40% 옮긴 색이다
  (`theme::beside_still_edge` — 어두운 판에선 밝게, 밝은 판에선 진하게). 하단바는 실선 + 가장 굵은 자리만큼 물러선다.
- 색: pane 은 그 학생색(`character_accent_n`), 학생 없는 칸·목록 보기는 `accent`. 배치도 칸·목록 줄은 `accent`.
- 모서리: pane 0, 배치도 칸 2, 목록 줄 `radius_sm`. 윤곽은 칸 안쪽으로 그린다.
- 손을 기다리는 칸은 도는 윤곽 대신 `attention` 깜빡임(1.1초) — 상태가 배타적이라 같이 서지 않는다.
- 셰이더가 `u.time` 으로 움직인다(`FLAG_EDGE_ORBIT`·`FLAG_EDGE_DASH`, 칸마다 쿼드 하나). CPU 는 위상을 안 세고, 일하는
  칸이 있는 동안의 프레임은 다시 짓지 않고 시간만 넘긴다(bar-only 프레임).
- 폰: 지도 칸은 그 학생색, 학생 줄은 `accent` 로 돈다(`Look.orbitLap` 2초 · `orbitHead` 2.5 → `orbitTailEnd` 1 ·
  `orbitTail` 0.2). 폰엔 초점이 없어 늘 또렷한 쪽. 동작 줄이기면 돌지 않고 윤곽 전체가 1 굵기 60% 로 서 있는다.

  다시 접기는 건너뛴다).
- 바닥: 진짜 화면에서 스피너·(풀스크린의 「◉ effort」 줄)·입력칸·상태줄을, 입력칸 대신 선택지 창(승인·질문)이 섰으면
  그 창 머리 가로줄부터(밀려 올라갔으면 화면 맨 위부터) 옮겨 붙인다. 가로줄은 칸 끝까지 다시 긋고 끝의 세션 이름표는
  오른쪽에 둔다. 원본 칸 폭이 다른 거울은 바닥도 이 칸 폭으로 다시 짓는다(`chat_view/bottom.rs` — 접힌 입력 줄·선택지를
  되이어 글머리 뒤로 다시 접고, 오른쪽에 붙은 글은 오른쪽에, 코덱스 입력칸 바탕은 칸 끝까지). 커서 블록·한글 조합 글자는
  옮겨 간 자리에 선다. 그래서 치기·한글 조합·`/` 명령·선택지 답은 터미널과 똑같이 학생 TUI 로 간다. 바닥을 못 찾거나(`/config` 같은 판) 칸의 60% 넘게
  덮으면 그동안 진짜 터미널을 그리고, 닫히면 돌아온다.
- 대화 줄(위에서 아래로, 덩이 사이 빈 줄 하나): 배너 — 진짜 화면에서 본 배너 줄(claude 로고 세 줄·코덱스 `>_` 두 줄)을
  기억해 그대로 세운다. 그래서 기록이 아직 없는 첫 말 전 새 세션도, 말이 쌓여 화면 밖으로 밀린 뒤에도 맨 위에 선다.
  못 본 칸(중간에 연 칸)은 기록의 판·모델·폴더로 짓는다(로고 174·바탕 16, `Claude Code` 굵게, 나머지 `text_mute`) → hook 줄 `  ⎿  <Hook> says: …`(`text_mute`, 이어진 것끼리 빈 줄 없음) → 내 말 `❯ ` + 글(`text`, 백틱
  코드는 153, 줄 전폭 바탕 237 — 카사텀 띠 꾸밈이 덮는다, 이어지는 줄 들여 2) → 답(학생 얼굴이 있으면 턴 첫 답은 4×2,
  같은 턴 도구 뒤 답은 2×1 얼굴 + 한 칸, 없으면 `⏺ `(`text`); 마크다운은 얼굴 폭+1 들여, 문단·표·코드 사이 빈 줄,
  목록 `- `·`1. `, 굵게·기울임, 글 속 코드 153, 표는 `┌┬┐ ├┼┤ └┴┘` 칸마다 가름선, 칸 폭보다 넓으면 claude 처럼 칸 안에서 접고 머리글은 가운데·짧은 칸은 세로 가운데 — 코덱스 꼴 표도 같이 접는다) → 도구 `⏺ Name(인자)`(성공
  `success`·실패 `danger`·도는 중 `text_mute`, 이름 굵게) + `  ⎿  ` 결과 세 줄 + `     … +N lines (ctrl+o to expand)`
  (흐리게). 읽기 도구(Read·Grep·Glob·LS, `cat`·`ls`·`grep` 꼴 Bash)는 `  Read 1 file, searched for 1 pattern (ctrl+o to
  expand)`(`text_mute`, 수 굵게) 한 줄로 접는다. Write 는 `Wrote N lines to <경로>` + 줄 번호 붙은 열 줄, Edit 는

- 손: 휠·PgUp·PgDn 은 대화 줄을 넘긴다(앱에 안 넘긴다). 그 밖의 키는 학생 TUI 로 가고, 치기 시작하면 맨 아래로 돌아온다.

  그린 격자에서 고른다. Info 「내 프롬프트」를 누르면 그 질문이 이 보기 맨 위에 선다.

  펴 두고(바뀐 덩이만 다시) 보이는 만큼만 격자로 옮긴다.

  `KASATERM_AUTOCHAT="75000:toggle=%0;90000:scroll=999999;95000:jump=0"`.

### claude 스크롤바·프롬프트 눈금 (`prompt_nav.rs`)

풀스크린(대체 화면) claude 칸에 선다. 정본은 칸 안 mod(`collab-hooks/claude-mods/prompt-nav`)가 잰 행이다. claude·codex 는

  또는 「선택」. 켠 칸은 강조 18% 물, 끈 칸은 얼굴을 흐리게(45%) — 얼굴 위에 체크를 얹지 않는다(미리보기를 가린다).
  후보(테마·이름·얼굴)는 붙은 데스크톱 `settings/characters`·`theme-roster`·`character-face` 에서 받는다 — 폰엔 테마 폴더가 없다.
  그 데스크톱에 없는 테마의 이름은 지우지 않고 「이 데스크톱에 없는 테마」 판에 글로만 보인다.
- **기기 색·아이콘**: 데스크톱 설정 「기기 색」「기기 아이콘」 그대로 — 색은 기준 기기 `settings/values` 의
  `appearance.device_colors`, 아이콘은 계정 설정 `device_icons`, 없으면 데스크톱과 같은 이름 규칙. 폰의 밝게·어둡게와
  상관없이 같은 색이고, 기기색 글자만 바탕과 대비 4.5 로 민다(데스크톱 머리 글자와 같은 보정).
- **학생 상태 낱말**: 판정은 데스크톱과 같다(내 차례 = 승인·질문 기다림뿐, `MachinesColRow::needs_you`). 「승인」「질문」
  (`attention`) · 「하는 중 · 사정」(`accent`) · 「쉬는 중」 · 「닫힘」. 방치(`idle`)·종류 모를 기다림은 쉬는 중이다.
- **입력줄**(나쵸·터미널): 최소 44, 여러 줄은 6줄까지 자라고 그 뒤 스크롤. 여러 칸 입력은 이름표를 칸 **위**에, 칸 사이 12
  (떠 있는 이름표 금지 — 칸 테에 걸린다).
- **학생 화면 첫 쪽·보기 단추**(2026-10-07 「대화를 기본으로 하고 x 옆에 터미널 아이콘으로 터미널 보기」): 열면 늘 둘째 쪽 —
  학생 칸은 대화, 데스크톱 셸 칸은 명령 묶음 — 이 먼저다. 지난번에 고른 쪽을 이어받지 않는다(한 번 터미널을 고르면 모든 칸이
  터미널로 열려 「대화 기본」이 사라진다). 폰이 연 웹 셸은 둘째 쪽이 없어 터미널뿐이고 단추도 없다. 앱바 맨 오른쪽 닫기(`close`)
  바로 왼쪽에 보기 단추 하나(누름 44, 아이콘 `Look.iconSize` 기본) — 아이콘은 **누르면 갈 쪽**이다: 대화·명령 쪽에선 `terminal`,
  터미널 쪽에선 `forum`(학생)·`view_agenda`(셸). 자판이 떠도 같은 자리에 그대로 있다. 앱바 밑 「터미널 | 대화」 전환 줄(44)과
  자판 때의 점 둘은 걷었다 — 그 높이만큼 글이 더 보인다. 스크롤 자리를 든 링크(`scroll=`)만 터미널 쪽으로 연다.
  앱바 오른쪽은 이 보기 단추와 닫기 **둘뿐**이다(2026-10-07 「상단 버튼은 전환 버튼만 남겨 두자」). 터미널 쪽에 있던
  「글자 선택·복사」(지난 줄 수천 줄을 맨 위부터 따로 띄운 시트라 보던 자리가 안 나왔다)와 「격자 그대로 보기」(데스크톱 폭
  그대로라 줄 오른쪽이 잘렸다)는 걷었다. 글자는 아래 「터미널 글자 고르기」로 터미널 위에서 바로 고른다.
- **터미널 글자 고르기**(`grid_select.dart`): 대화 보기의 마크다운 글과 같은 손맛 — 길게 누르면 낱말이 잡히고 손잡이가
  뜬다. 누른 채 끌면 낱말 단위로 넓히고(위로 끌어도 처음 낱말은 남는다), 놓으면 메뉴 「복사 · 전체 선택」(복사하면
  「복사했어요」). 손잡이를 끌면 글자 단위. 터미널 위·아래 가장자리 너머로 끌면 지난 줄로 굴러간다. 경계는 칸 단위라 한글
  두 칸 글자는 반으로 갈리지 않는다(가운데를 넘으면 그 뒤). 낱말은 글자·숫자·한글에 `_-./~:@%+=?&#` 까지 — 경로·주소가
  한 번에 잡힌다. 복사하는 글은 폰 폭으로 접힌 줄을 다시 잇고(접으며 버린 빈칸은 되살리고 글머리 들여쓰기는 뺀다) 줄 끝
  빈칸은 걷는다. 고르기는 초점을 잡지 않는다 — 잡으면 터미널을 누를 때마다 입력칸이 초점을 잃어 자판이 내려간다. 대신
  치기·보내기·입력칸 초점·쪽 넘김에 고름을 걷는다. 주소 위 탭은 그대로 열기·복사 시트이고, 나머지 탭은 고름을 걷는다.
  밀기 판정은 고르기 영역 안쪽에 한 벌 더 둬서 고른 채로도 가로로 밀면 쪽이 넘어간다. 바닥에 붙잡아 둔 입력상자(스크롤을
  올린 동안)는 사본이라 고르지 않는다.
- **터미널**: 자판이 뜨면 머리를 앱바 한 줄로 접는다. 자판이 뜬 채로 글 보이는 높이가 **자판 위 공간**의 절반 이상
  (전체 화면 기준이 아니다 — 아이폰 자판이 약 40% 를 먹어 전체의 절반은 앱바·입력줄을 없애야만 된다. 2026-09-29 실측 62%).

  세로 끌기를 데스크톱 휠과 같은 SGR(64 위·65 아래, 보이는 한 줄 끌 때마다 하나)로 넘긴다. 셸처럼 스크롤백이 있는
  화면은 폰이 지난 줄을 굴린다.
  대체 화면인 동안은 지난 줄을 아예 안 보인다 — 원본이 그 화면을 줄일 때 밀려 올라간 윗줄이 옛 머리말로 겹쳐 보였다.
  대체 화면에서 나오면 원본의 지난 줄을 다시 받는다. 대체 화면이 폰 화면보다 짧으면(폰이 보기만 해 원본 크기 그대로일 때)

  「원본 크기는 쓰는 쪽이 쥔다」.
- **터미널 한글**: 한글·한자·가나는 그 글꼴의 1em 을 두 칸에 맞춰 키워 칸 왼쪽에서 그린다(데스크톱 D2Coding 과

  - 받는 밀기: 본문(격자·말풍선 칸)에서 시작해 가로가 세로의 **1.5배 이상**(약 34° 안)인 것만. 세로 스크롤은 세로 18 에서

    키 줄 가로 스크롤). 코드 칸·표처럼
    안쪽에 가로 스크롤이 있으면 그 칸이 먼저 가져간다(밀 거리가 없으면 쪽 넘김이 받는다).

## 4. 형태 규칙 — 목업에서 온 것

**OS 스타일의 표면과 조작 상태를 공유한다.** Nava OS 외형 설정 영상의 부드러운 표면·색 견본·즉시 미리보기를 참고한다.

- 버튼·세그먼트·스테퍼·입력칸은 테마 표면색을 채운다. 주 동작·선택은 강조색 채움과 대비를 확보한 글자, 일반 동작은 중립 표면과 얇은 경계다. 전면 개편 요청에 따라 이전의 채움 금지 규칙을 대체한다.
- **토글**: 꺼짐은 중립 트랙, 켜짐은 강조색 트랙과 대비를 확보한 손잡이다.
- **행**: 왼쪽 이름(+보조글), 오른쪽 조작, 아래 얇은 선. 조작은 오른쪽 끝에 붙는다.
- **입력**: 한 줄은 이름 왼쪽·칸 오른쪽의 한 행. 여러 줄은 이름 위·칸 아래.
- **묶음 제목**: 작은 흐림 글자 하나(11pt `text_dim`). 설명은 제목에 붙이지 말고 행마다 보조글로.
- **옆 목록(nav)**: 구분선 없이 배경만 다르게. 머리글은 작은 흐림 글자.
- 테마·색처럼 고르는 대상은 미리보기 타일로 표현한다. 일반 설정은 같은 읽기 열에 묶고 항목마다 장식 카드를 반복하지 않는다.

### OS 스타일 반응형 설정

- 기본 표면 팔레트는 Frost Light와 Frost Dark를 추가하고, 기존 팔레트·커스텀 색은 함께 유지한다. 색은 `theme.rs`의 같은 역할 토큰으로 설정·작업 방·문서에 전파한다.
- 설정 패널 바깥 여백은 12px, 둥근 패널 반경은 `radius_md`다. 넓은 화면의 탐색은 208px, 760px 미만은 154px다.
- 패널 폭 600px 미만은 옆 탐색을 상단의 3~4열 선택 목록으로 바꾼다. 각 항목은 32px, 간격 4px이며 돌아가기는 머리에 둔다. 탐색과 본문은 서로 다른 뷰포트다.
- 본문 좌우 여백은 넓을 때 24px, 760px 미만 16px, 상단 탐색에서는 12px다. 가용 폭에 최소 180px를 강제로 더하지 않는다.
- 분할 선택은 라벨과 선택지가 한 줄에 들어가지 않으면 라벨 아래로 이동한다. 설명이 있는 토글은 설명을 줄바꿈하고 행 높이도 함께 늘린다.
- 강조색은 36px 색 견본과 이름으로 고른다. 색 선택 면과 색상 띠는 각 한 GPU 인스턴스에서 HSV를 연속 계산한다. 348개의 작은 사각형과 색 경계를 없애고 터미널 채도·글자 보정은 적용하지 않는다. 움직이는 장식·화면 전체 블러는 기본 렌더 루프에 추가하지 않는다.

## 5. 배치 규칙

- **읽기 열은 가운데 세운다.** 열이 `CONTENT_MAX_W` 에서 멈추므로 넓은 창에서 남는 폭을
  좌우로 갈라야 한다. 안 그러면 전부 오른쪽에 쌓여 글이 왼쪽 벽에 붙는다
  (2560 창에서 우여백 1026px 였다). → `content_column()`, 회귀 테스트 둘.
- **세로로 남는 공백은 채우지 않는다.** 항목이 적은 페이지 아래가 비는 것은 정상이다.
  페이지마다 다른 양을 내리면 카테고리를 바꿀 때 본문이 튀고, 이름은 헤더에 고정이라
  본문만 내려가면 이름이 떠 보인다.
- **개수를 고정하지 말고 폭에 맞춰 채워라.** 미리보기 얼굴·격자 열 수는 상자 폭에서 계산한다.
  고정 개수는 상자가 넓어진 날 가운데가 빈다.
- **없는 동작의 자리는 비우지 말고 이유를 적어라.** 번들 테마에는 이름 바꾸기·열기·지우기가
  없는데 그 모서리를 비워 두니 카드마다 줄이 어긋나 보였다. 못 쓰는 단추를 세우는 대신
  「기본」 알약을 같은 자리에 놓았다.
- **선택은 강조로 말하지, 요소를 빼서 말하지 마라.** 고른 카드에서 단추가 사라지면 격자가 깨진다.
- **창 칸은 크기가 같은 벤토 격자다.** 칸이 열리거나 닫힐 때마다 방 전체를 다시 짠다(`layout.rs rebento_window`).
  칸 하한은 셸 격자로 40칸×16줄(`BENTO_MIN_COLS`·`MIN_PANE_ROWS`) — 이보다 작아질 때만 새 칸을 연 칸의 탭으로
  보낸다. 터미널이 아닌 것(웹·문서·이미지)은 칸을 차지하지 않고 연 칸의 탭으로 연다.

## 6. 글자

### 팔레트 미리보기

- 첫 선택 줄은 Frost Light·Frost Dark·Graphite·Paper 네 개만 색 미리보기로 보여 준다. 폭 560px 이상은 4열, 그 미만은 2열이며 간격은 8px이다.
- 각 선택은 높이 96px로, 실제 pane·sidebar 토큰을 쓰는 54px 미리보기와 이름·선택 표지으로 구성한다.
- 선택 중인 기존·커스텀 팔레트는 현재 이름을 계속 표시한다. 나머지 프리셋은 기본 접힘 「다른 팔레트」에서 고르며 삭제하지 않는다.
- 설정의 앱 미리보기는 Rust 네이티브로 높이 224px에 헤더·사이드바·분할 터미널·우측 패널을 그린다. 영역을 누르면 같은 색 편집기에 연결한다.
- `bg`는 창 바탕, `pane_bg`는 터미널 기본 배경, `header_bg`는 타이틀·pane 헤더, `sidebar_bg`는 사이드바·좌우 패널이다. 후자의 세 값이 없으면 기존 팔레트 값에서 유도한다.
- 기존 기본색 11칸·ANSI 16칸의 순서를 유지하고 역할색 세 칸은 마지막에 추가한다. 저장·미리보기·실제 렌더가 같은 값을 읽는다.
- 미리보기는 12pt 본문·10.5pt 보조글과 26px 헤더를 사용한다. 색 이름을 항상 함께 보여 주며, 선택은 강조색 테두리로 표시한다.
- Graphite·Ink·Paper·Mist는 본문·보조글을 창·입력·패널 바탕에 대조한 대비가 모두 4.5:1 이상이다. 새 색 조합은 같은 역할별 대비 검사로 검증한다.

- 본문 12 · 보조글 10.5 · 묶음 제목 11 · 페이지 이름 20 · 카드 이름 14 · 알약 9.5 (pt, 논리)
- 넘치는 글자는 `fit(g, text, 가용폭, 크기, 굵게)` 로 자른다. 직접 자르지 마라.
- UI 글꼴은 `theme::ui_font()`. 미지정 시 시스템 고딕을 사용한다. 터미널 글꼴과 다른 축이다.

## 7. 고칠 때 지킬 것

### 자체 브랜드와 다음 시각 방향

- 모바일의 표시 이름은 `KASA Mobile`이다. 내부 bundle ID·Keychain 식별자는 바꾸지 않는다.
- 제품 로고·기본 배경·기본 캐릭터는 KASA 자체 에셋을 사용한다. 특정 작품의 로고·학교·교실 그림을 제품 기본 얼굴로 배포하지 않는다. 사용자 소유 테마 파일과 기존 세션의 이름·주소는 보존한다.
- 자체 캐릭터의 기준은 하늘색 긴 트윈테일과 차분한 눈의 언니, 호박색 경단머리와 활발한 표정의 동생, 두 색의 우산이다. 기존 시안은 보존하며 새 제작물의 입력·모델·원본 위치를 함께 기록한다.
- 모바일 UI 글꼴은 Pretendard 400/600을 기준으로 한다. 터미널 격자는 별도 고정폭 글꼴과 한글 두 칸 규칙을 유지한다. 글꼴 이름·공통 테마는 계정 설정으로 동기화하고 로컬 글꼴 파일 경로는 보내지 않는다.
- 다음 디자인 방향은 **비에 젖은 유리**다: 은은한 투명 표면·절제된 물방울·하늘색과 호박색 빛. 이번 로그인/업데이트 구현의 완료 조건에는 유리 셰이더 구현을 포함하지 않는다.
- 유리 효과는 장식이며 가독성을 대신하지 않는다. 글자 뒤에는 안정된 표면을 두고 텍스트 대비 4.5:1, 상태 경계 3:1을 검증한다. 투명도 감소 설정과 저성능 환경에는 불투명 표면을 제공한다. 입력·스크롤 중 지속적으로 움직이는 물방울은 기본값으로 넣지 않는다.

### 공통 조작 부품과 닫기

- 구현 정본은 `native_controls.rs`다. 설정·문서 창·우측 패널은 같은 버튼 페인터를 쓴다.
- 일반 텍스트 버튼은 높이 32px, 본문 13px, 좌우 여백 12px다. 아이콘 버튼도 기본 32×32px다. 좁은 도구 모음은 높이 26px·본문 12px·좌우 여백 10px로 줄이며, 주어진 칸을 넘기지 않는다.
- 설정 행의 이름·보조글과 토글에도 같은 10px 안쪽 여백을 둔다. 포커스 테두리가 글자나 토글 외곽과 겹치지 않아야 한다.
- 우측 패널 머리의 아이콘 버튼 간격은 8px, 줄바꿈 탭의 줄 높이는 38px다. 다음 줄의 클릭 영역이 윗줄 버튼에 겹치지 않는다.
- 보이는 버튼과 클릭 영역은 같은 사각형이다. 선택·주 동작은 강조색 채움, 일반은 테마 표면, 호버는 표면 명도와 경계로 구분한다. 채움 위 글자는 최소 4.5:1 대비를 확보한다.
- 설정의 Tab·Shift+Tab은 전체가 보이는 활성 조작을 순환한다. Enter·Space는 한 번만 실행하고, PageUp·PageDown은 본문을 이동한다.
- 스크롤·카테고리·팝업 변경 후 이전 좌표로 조작하지 않는다. 잘린 색 선택기는 원래 색판 좌표로 값을 계산하고, 한 줄 입력 커서는 실제 그린 글리프 경계를 사용한다.
- 비활성 버튼은 흐린 글자이며 클릭 영역에 등록하지 않는다. 위험한 동작은 위험색과 동작 이름을 함께 쓴다.
- 마우스를 켠 TUI(DECSET 1003, Claude Code 전체화면) 위에서는 버튼 없이 움직여도 칸이 바뀔 때마다 이동을 넘긴다 —
  앱의 호버 효과(×가 밝아지는 것 등)는 이걸 받아야 그려진다. 넘긴 칸을 앱이 같은 글자로 모양만 바꿔 그리면
  누를 수 있는 것으로 보고 손가락 커서를 띄운다. 앱이 포인터 모양 신호(OSC 22)를 안 보내서 이것이 유일한 단서다.
- 키보드 포커스는 실제 클릭 영역 안쪽에 2px 강조색 테두리와 1px 대비색 안쪽 선으로 표시한다. 강조색 채움 위에서도 포커스가 남아야 한다. Tab/Shift+Tab은 활성 조작 사이를 이동하며 Enter/Space는 한 번만 실행한다.
- 문서 편집의 Tab 들여쓰기는 유지한다. F6으로 문서 도구모음에 진입하고, 도구모음에서 Tab으로 이동하며 F6/Esc로 문서에 돌아간다.
- `x`는 오른쪽 위에서 **현재 화면을 닫기**다. 패널 닫기는 패널만 숨기고 실행 중인 작업을 종료하지 않는다.
- 세션 종료는 `세션 종료` 또는 `작업 종료`로 표시한다. 패널의 `x`와 같은 이름·설명을 사용하지 않는다.
- 문서 창의 `x`는 저장하지 않은 편집 확인을 거친다. 팝오버 바깥 클릭·Esc는 팝오버만 닫는다. 종료 확인을 자동 승인하지 않는다.
- 칸·탭의 닫기는 원본과 거울에 같은 동작이다. 원본/거울 선택창이나 「저쪽 칸은 남김」 메뉴는 두지 않는다.
  원격 요청 중에는 진행 상태만, 실패하면 까닭과 「다시 시도」「취소」를 표시한다. 앱 종료·패널 닫기는 이 규칙과 별개다.
- 설정의 Esc는 열린 선택 목록, 편집 중인 입력, 버튼 포커스를 먼저 해제한다. 해제할 대상이 없을 때만 설정을 닫는다. Enter·Esc를 계속 누르고 있어도 닫힌 확인창 뒤로 입력이 전달되지 않는다.
- 확인창이 열려 있으면 키보드와 IME 입력은 맨 위 확인창만 소유한다. Git 커밋 확인창의 Enter는 화면에 선택한 포함 범위를 지킨다.
- 새 화면은 공통 부품을 사용하고, 기존 화면을 수정할 때 같은 역할의 사설 페인터를 함께 걷는다.

1. 값이 필요하면 **여기서 찾고**, 없으면 여기 추가한 뒤 쓴다.
2. 치수를 파일 안 `const` 로 새로 만들지 마라 — 위의 「아직 정돈 안 된 곳」이 그렇게 생겼다.
3. 눈으로 판정하기 전에 **px 로 재라.** 판독은 틀린다(2026-09-22: 「여러 페이지 하단이 비었다」가
   실제로는 한 페이지뿐이었고, 「카드 오른쪽 절반이 빈다」는 카드는 실제로 차 있었다).
   재는 법은 [`verify-app.md`](verify-app.md).
4. 배치 계산은 순수 함수로 빼고 테스트를 걸어라. 걸었으면 **한 번 깨뜨려** 잡히는지 확인해라.

### 계정 메일 표지

- 설정·다른 기기 계정 목록·계정 메뉴·현재 선택 칩은 공통 `account_brand`로 메일 제공자를 표시한다. 실제 이메일의 `gmail.com`/`googlemail.com`, `naver.com`, `sionic.ai`만 판정하며 슬롯 별명·조직명으로 추측하지 않는다. 알 수 없는 주소는 기본 메일 아이콘이다.
- 목록은 14px, 상태줄은 12px, 아이콘과 글 사이 6px이다. 공식 Gmail·NAVER·Sionic 자산의 색·비율은 보존한다. NAVER 가로 로고는 14px 행 안에서 높이 8px 비율로 놓고 실제 폭을 먼저 예약해 글자와 겹치지 않게 한다.
- 브랜드 그림은 식별 보조이며 로그인 상태·계정 이름을 대신하지 않는다. 작은 폭에서는 아이콘을 위한 폭이 있을 때만 표시한다.
- Claude 계정 메뉴 아래에는 현재 선택의 기기별 동기화 결과를 남긴다. 요약·기기별 상세는 10.5pt·줄높이 18px로 감싸며 상태 아이콘 14px와 6px 간격을 둔다. 실제 줄 수를 팝오버의 스크롤 높이에 더하고, 결과 글을 눌러 계정이 바뀌지 않게 선택 영역과 분리한다. 실패 토스트가 사라져도 이 상세를 읽을 수 있다.
- 현재 Claude 계정의 「다른 기기에 다시 보내기」는 리셋 시각·관리 동작 아래 별도 26px 버튼 행에 둔다. 행 높이에 버튼 26px와 아래 간격 4px를 더하고, 기존 리셋·관리 줄은 원래 높이에 남긴다. 버튼 폭은 글자 실측 폭과 좌우 10px 여백이며 목록 안쪽 폭을 넘지 않는다. 버튼 하나만 재전송 히트이고 Codex·다른 계정·로그아웃 슬롯에는 만들지 않는다.

### 폰 Claude 재로그인

- 설정과 만료 알림은 같은 계정 목록을 연다. 위에는 대상 기기, 바로 아래에는 등록된 계정·상태·「다시 로그인」을 둔다. 로그인 시작 뒤 대상 기기·슬롯은 고정한다.
- 기존 `Look`·`SettingsGroup`·공통 버튼과 글꼴을 쓴다. 좌우 16px·묶음 간격 24px, 터치 영역 최소 44px, 인증코드 입력 글자는 16px 이상이다. 390×844에서 첫 계정 행은 189px, 로그인 버튼은 48px다.
- 진행 화면은 선택 계정 → 브라우저 승인 → 인증코드 입력 → 결과 순서다. 코드 입력은 가림·붙여넣기 허용·자동완성 없음이며 자동 클립보드 읽기는 하지 않는다. 320px 폭·200% 글자·336px 자판에서도 조작을 스크롤해 닿을 수 있어야 한다.
- 신원 미확인 슬롯의 명시 확인에는 실제 이메일·조직을 보여 준다. 저장 성공, 현재 칸 반영 보류, 취소 미확인, 연결 끊김, 업데이트 필요를 서로 다른 상태로 표시한다. 알림을 여는 것만으로 로그인이나 계정 교체를 실행하지 않는다.

### 사용자 지정 색 편집

- 강조색은 프리셋 이름 또는 정규화한 `#rrggbb` 값으로 저장한다. 모든 임의 RGB를 미리보기·저장·재시작·원격 디자인 토큰에 그대로 반영한다.
- 외형의 강조색은 채도/명도 면·색상 띠·선택 색 견본을 먼저 보여 준다. HEX는 기본 접힌 「색상 값 직접 입력」에 둔다. 색판 높이 144px, 색상 띠 18px, 사이 12px이며 폭 440px 미만에서는 56×48px 견본과 스포이드를 아래로 옮긴다. 기존 다섯 견본은 빠른 선택이다. 상태줄도 같은 편집기를 쓰며 「색 고르기」와 「기본색 사용 중」으로 상태를 표시한다. 값 펼침은 현재 색 편집과 취소 기록을 유지한다.
- 입력·미리보기·스포이드의 대상은 색 입력 필드 타입으로 구분한다. 다른 편집기의 색을 덮지 않는다. 드래그 중에는 메모리만 갱신하고 손을 놓을 때 저장한다. 취소는 이전 색 또는 기본색 상속 상태를 복원한다.
- 잘못된 HEX는 적용하지 않는다. 편집기 아래에서 형식을 안내하고 완료·Enter는 유효한 색일 때만 닫는다.
- Info는 실행 정보를 바로 표시한다. 공유폴더 페이지·전환 버튼은 두지 않는다.

### 터미널 링크와 결과 이미지

- 일반 클릭·드래그는 텍스트 선택과 TUI 조작에 남긴다. 웹 주소와 파일 경로는 macOS Cmd+클릭, 다른 데스크톱 Ctrl+클릭으로 연다. 수정키를 누를 때 손 커서와 링크 전체 밑줄을 표시한다. 누른 뒤 드래그하거나 수정키를 놓거나 내용이 바뀌면 열지 않는다.
- 주소의 괄호는 균형을 검사하고 URL 바깥의 닫는 괄호·후행 문장을 제외한다. 줄바꿈·TUI의 링크 여백·한글 두 칸을 실제 화면 좌표로 잇는다. 따옴표·각괄호로 감싼 공백 경로, 현재 작업 폴더 기준 상대 경로, 홈 경로, file URI를 지원한다. 원격 파일은 원본 기기에서 받아 연다.
- 결과 사진은 아래 CLI 공통 표시 블록으로 본문에 그린다. 자동 SendUserFile 훅은 이력만 기록하고 탭을 열지 않는다. 셸 `imgopen`은 현재 터미널 폭에서 좌우 2칸을 빼고 최대 80열, 화면 높이의 절반·최대 24행 안에 비율을 유지해 표시한다. `imgopen --tab`만 명시적 미리보기 탭을 연다.
- 하네스가 가로채는 파이프에 그래픽 escape를 출력하지 않는다. 표시 블록의 일반 텍스트 행으로 하네스가 자리를 확보하고 카사텀이 그림으로 합성한다.

### CLI 공통 인라인 결과 이미지

- Claude Code·Codex 결과는 `imgopen --block FILE`이 반환한 fenced 표시 블록을 답변에 그대로 넣는다. 하네스의 이미지 출력 지원 여부와 무관하게 카사텀이 등록된 PNG를 그린다. 일반 셸 TTY의 Kitty 출력은 그대로다.
- 표식 한 줄은 29자이며 이미지 식별자·행 번호·전체 행 수를 함께 가진다. 기본 영역은 64열과 셀 비율 2.2 기준으로 계산한 6~18행이다. 미리보기는 최대 1600px로 저장한다. 원본 경로는 표식에 넣지 않는다.
- 완전한 표식만 있는 행에만 그림을 그린다. 접힌 도구 출력·다른 문장·입력칸을 지우지 않는다. 위쪽이 스크롤되어 사라져도 남은 행 번호로 같은 그림의 위치를 복원한다. 모르는 식별자는 일반 텍스트로 남긴다.

- 모바일 대화는 같은 이미지 표시 블록을 원본 기기의 인증된 `/term/inline-result` 이미지로 바꾼다. 식별자·행 순서가 완전한 블록만 변환하며 앞뒤 마크다운을 보존한다. 본문 이미지 높이는 최대 360px, 로딩 영역은 96px이고 390px 폭을 넘지 않는다.

- 모바일 대화의 파일 링크는 원본 기기의 작업 폴더·홈 경로를 기준으로 해석한다. 탭하면 열기·복사 시트를 표시하고, 열기를 선택했을 때만 인증된 파일 읽기로 최대 32MiB를 받아 iOS Quick Look으로 연다. 실패하면 대화 위치를 유지한 채 오류를 표시한다.

### PC 미러의 기본 보기

모든 PC 미러는 원본 TUI의 글자·색·커서 배치를 그대로 그리는 터미널 보기로 시작한다. 대화 기록과 명령 구간의 재구성은 ⋮에서 직접 고른 칸에만 적용한다. 원본 크기 제어·반환 규칙은 `docs/mirror-render.md`를 따른다. 모바일의 대화 기본값과 독립된 선택이다.
