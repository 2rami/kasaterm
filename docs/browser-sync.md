# 북마크·탭 동기화 (kasaterm 쪽)

카사브라우저의 북마크를 같은 계정의 기기끼리 합치고, 열린 탭은 기기마다 보낸다. 설계 전체와 브라우저 쪽 창구는
kasabrowser `docs/browser-sync.md`, 금고 열쇠와 관문 규칙은 [웹 로그인 동기화](login-vault-sync.md)다.
코드는 `kasa-device` `browser_sync`, 관문 `gateway_login_vault.rs` 의 `store_routes`, 화면은 카사브라우저 설정 「동기화」.

## 열쇠

- 금고 열쇠 `K` 를 그대로 쓰지 않고 `VaultKey::subkey("browser-sync")`(HKDF 정보 `subkey:browser-sync`)로 가른 열쇠를 쓴다.
  표식(`key_id`)·쓰기 서명·봉인·항목 이름이 모두 금고와 달라, 한쪽 덩어리나 서명을 다른 쪽에 끼워 넣지 못한다.
- 따로 등록하지 않는다. 금고 열쇠가 있고 사람이 지문을 확인한(`unconfirmed-<계정>` 이 없는) 기기만 일한다.
  `K` 원본은 밖으로 내보내지 않고 갈래만 쓴다.

## 늘 켜짐

- 금고 열쇠가 있고 지문을 확인한 기기는 북마크와 탭을 늘 맞춘다. 켜고 끄던 단추는 걷었다 — 기기마다 켜 줘야 해서 안 맞춰진 채로
  남았다(2026-11-18).
- 켜고 끄던 때의 `~/.config/kasaterm/browser-sync/settings-<계정>.json` 은 첫 바퀴에 지운다. 거기 북마크가 꺼져 있었으면 다시 켤
  때처럼 관문을 처음부터 받는다(꺼 둔 사이의 변경을 놓치지 않게). 그 첫 바퀴에 이 기기에서 사라진 것은 지운 때가 아니라 알아챈
  때라 다른 기기의 나중 고침을 이길 수 있어, 하나라도 사람 확인까지 보류한다.

## 브라우저 설정 페이지

- 바퀴마다(그리고 브라우저가 꺼져 있으면 건너뛰고) 다리 명령 `sync.state.put {"state"}` 로 카사브라우저 설정 「동기화」에 보일 한 장을
  넘긴다(`browser_sync::display`). 금고와 북마크·탭 상태를 묶고, 글은 여기서 다 쓴다 — 브라우저는 그대로 그린다.
  `{at_ms, phase(on·starting·needs_you·off·error), headline, detail, rows[{label,value,detail?}], note, asks[{id,title,detail,button,tone}]}`.
  개수·지문·기기 이름만 있고 주소·사이트·아이디는 없다.
- `asks` 는 사람이 정해야 하는 일: `create_vault`·`confirm_login_deletions`·`confirm_bookmark_deletions`. 새 기기는 누를 것 없이
  관문에 맡긴 금고 열쇠를 받는다(`waiting_for_key` → `joined`, [login-vault-sync.md](login-vault-sync.md)). 브라우저 단추는 `POST 127.0.0.1:<~/.config/kasaterm/mcp_port>/browser-sync/ask {"id"}` 를 부른다. 바깥 peer 와
  `Origin` 이 붙은 요청(웹 페이지의 fetch)은 거절한다.
- 그 부름은 아무것도 확정하지 않는다. 카사텀이 지금 상태에서 물을 수 있는 일인지 다시 보고, 카사텀 창에 확인 시트를 띄워
  사람이 거기서 누를 때만 지우기·금고 만들기를 한다(`native_login_vault.rs`). 소켓·CLI 에는 이 길을 두지 않는다.

## 한 바퀴 (15초, 켜기·끄기는 앞당김)

1. 관문(`/relay/browser-sync`)에서 새 항목을 받는다. 기록이 없으면 갈래의 표식·서명 공개키로 만든다(처음 온 기기).
   관문 시계·차례 되돌림·안 풀리는 덩어리 규칙은 금고와 같다.
2. 브라우저 창구(`sync.read`)로 모음과 탭을 읽는다. 브라우저가 꺼져 있으면 그 바퀴는 상태를 건드리지 않고 넘어간다
   (끈 탭의 묘비만은 올린다). 관문에 이름이 이메일인 모음이 있는데 읽은 모음에 없으면 `sync.accounts.put {accounts}` 로
   빈 계정 폴더를 만들게 하고 1초 뒤 다음 바퀴를 돈다 — 그 바퀴의 처음 합류가 폴더를 채워, 새 기기에서 사람이 계정 폴더를
   만들 일이 없다. 그 명령을 모르는 옛 브라우저의 오류는 무시한다.
3. 모음마다 로컬 변경(내용·자리·삭제)을 찾고 관문 판과 묶음별로 합친 뒤, 계산한 트리가 되도록 `sync.apply`(읽은 rev 위)로 고친다.
   그사이 사람이 고쳤으면(`SYNC_STALE`) 그 모음은 아무것도 안 바꾸고 다음 바퀴로 미루며 관문 차례도 앞당기지 않는다.
4. 바뀐 기록을 200개·768KB 씩 서명해 올린다. 아는 판에는 「아직 못 올림」(`dirty`) 표식이 붙고 `Ok` 를 받을 때만 내린다 —
   끊긴 바퀴의 변경·묘비도 다음 바퀴에 다시 올라간다. 관문 차례가 0 인 판(관문이 비거나 되돌아간 뒤)도 다시 올린다.
   부딪히면 다음 바퀴가 새 판을 받아 다시 합치고, 관문에서 걷혀 없어졌으면 「아직 없음」으로 다시 올린다.
   봉인 한도(6KB)를 넘는 북마크는 「너무 커서 못 보낸 북마크 N개」로 설정에 보인다.
5. 탭은 30초 묶어 내 항목 하나로 올리고, 다른 기기 탭이 바뀌었으면 `sync.tabs.put` 으로 넘긴다.
6. 180일 지난 묘비를 걷는다. 로그는 `[browser-sync] 올림 N · 브라우저 고침 N · …` 개수만.

## 큰 삭제 보류

- 한 바퀴에 20개와 아는 것의 4분의 1 중 큰 쪽을 넘게 사라지거나, 모음의 살아 있는 것이 전부 사라지면(작은 모음도) 묘비를
  올리지 않고 「지우기 N개 보류」로 사람 확인을 기다린다. 이 기기에서 되돌려 놓지도 않는다.
- 「지우기 확인」은 누른 때 보류 중이던 그 목록(동기화 id)만 지운다. 그 뒤 더 사라진 것은 다시 묻는다. 확인은 그 목록을
  처리한 바퀴(브라우저 있음·미룸 없음·실패 없음)가 끝날 때까지 남는다.
- 보류한 지우기는 정한 것이 아니다 — 그사이 다른 기기가 그 항목을 고쳤으면 그 고침을 따라 이 기기에 되살린다.
- 상태를 잃은 기기(기기 id 바뀜 등)가 다시 붙을 때는, 전에 이 기기가 올린 것(로컬 id 가 곧 동기화 id)을 제목이 바뀌었어도
  그대로 짝지어 같은 북마크가 두 벌 되지 않게 한다.

## 브라우저 창구

- kb 와 같은 길이다. 맥은 데이터 폴더(`~/Library/Application Support/Kasa Browser OSR`)의 `agent.sock`(남이 쓸 수 있는 폴더면
  붙지 않음), Windows 는 `%APPDATA%\Kasa Browser OSR\agent.endpoint` 의 루프백 주소에 토큰을 보내지 않고 HMAC 으로 서로
  증명한다(`kasa-browser-bridge-v1`). 시험·격리 실행만 `KASATERM_BROWSER_DATA_DIR` 로 폴더를 바꾼다.

## 관문

- 금고의 받기·만들기·쓰기 창구를 `store_routes(경로, 보관소)` 로 나눠 같은 꼴로 연다. 보관소는 `browser-sync/<계정>.json`,
  한도 `RELAY_LIMITS`(항목 2만·덩어리 96KB·파일 64MB). 등록 창구는 없다. 금고 보관소의 한도·동작은 그대로다.

## 시험

- `cargo test -p kasa-device --lib browser_sync` — 가짜 브라우저(kasabrowser `bookmarks.Tree.Apply` 규칙)와 시험 관문으로 두 기기
  수렴, 이름 바꿈+옮김, 삭제 대 나중 고침, 지운 폴더에 더한 것, 서로 안으로 옮긴 폴더, 같은 가져오기, 큰 삭제 보류, STALE,
  탭 켜고 끄기, 브라우저 꺼짐, 하나 옮기면 하나만 올림, 다른 열쇠 거절, 450개 나눠 올리기, 자리 글자열 길이. 모음·주소는
  `kasatest-`·`kasa-test.example` 만.
- 진짜 Go 창구: kasabrowser `bridge.Listen` 으로 가짜 sync 서버를 띄우고
  `KASATERM_BROWSER_DATA_DIR=<폴더> cargo test -p kasa-device --lib browser_sync::bridge -- --ignored`.
- 관문: `cargo test -p kasa-gateway login_vault`(갈래 보관소가 금고와 따로이고 금고 서명으로는 못 쓰는지).
- 검수에서 온 재현: 올리기만 끊기는 관문으로 한 바퀴 뒤 변경·묘비가 다음 바퀴에 올라가는지, 관문 기록을 비운 뒤
  새 기기가 다 받는지, 탭을 끄자마자 다른 기기에서 사라지는지, 작은 모음이 통째로 비면 보류하는지, 다시 켠 첫 바퀴의
  지우기 보류, 상태를 잃은 기기의 같은 정체, 너무 큰 북마크.

## 남는 틈

- 관문 보관소 비용: `Store::load` 가 받기·쓰기마다 계정 기록 전체를 복사하고 쓰기마다 파일 전체를 다시 쓰며, 모든 계정이
  잠금 하나를 쓴다. 탭은 기기마다 30초에 한 번 쓴다. 북마크 1천 개 ≈ 1MB 에선 괜찮지만 한도 64MB 가 그만큼을 허락한다 —
  파일 한도를 낮추거나 잠금 안에서 빌려 쓰기로 바꾸는 것은 나중 일(쓰기는 갈래 열쇠 서명이 있어야 해 보안 문제는 아니다).
- Windows 창구의 폴더 검사 없음: 맥은 데이터 폴더가 남이 쓸 수 있으면 안 붙지만 Windows 는 `agent.endpoint` 의 소유자·ACL 을
  안 본다. `%APPDATA%` 기본 ACL 이면 같은 사용자만 쓰고 kb 와 같은 수준이다. 읽은 토큰은 메모리에서 지우지 않는다.
- 갈래 보관소의 key_id 를 되돌릴 길이 없다: 관문 기록이 낯선 key_id 를 들면 `key_mismatch` 로 멈추는데, 로그인 동기화를 다시
  등록해도 `/relay/browser-sync` 의 key_id 는 안 바뀐다(지우기·다시 만들기 창구 없음). 금고 열쇠가 계정당 하나라 드물다.
