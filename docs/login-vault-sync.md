# 웹 로그인 동기화

카사 키체인의 웹 로그인(`web:<host>`, 값 `{"username","password"}`)을 같은 카사텀 계정의 기기끼리 맞춘다.
서버에는 잠긴 덩어리와, 열쇠를 가진 기기가 맡긴 금고 열쇠를 둔다. 브라우저는 지금처럼 로컬 키체인만 읽고, 맞추는 일은 kasaterm 이 한다
(`kasa-device` `login_vault`, 관문 `gateway_login_vault.rs`, 상태는 카사브라우저 설정 「동기화」, 확인은 카사텀 창의 시트 —
[브라우저 설정 페이지](browser-sync.md#브라우저-설정-페이지)).

같은 KASA 계정으로 로그인한 데스크톱은 폰 승인·지문 확인 없이 관문에서 금고 열쇠를 받아 바로 맞춘다(2026-11-20 사람이
「로그인만으로」를 골랐다 — 대가는 아래 「위협 모델」).

## 위협 모델

- 관문은 금고 열쇠를 갖는다. 관문 운영자, 관문 서버를 뚫은 사람, 관문 저장소(`login-vault/<계정>.json`)를 읽은 사람은 그 계정의
  모든 동기화 비밀번호를 풀 수 있다. 북마크·탭 동기화 열쇠도 금고 열쇠에서 가르니 같이 풀린다.
- 데스크톱 기기 토큰을 가진 사람(훔친 토큰, 로그인된 채 잃어버린 기기)은 열쇠를 받아 간다. 토큰을 거두면(기기 빼기) 그 뒤로는 못 받지만
  이미 받은 열쇠는 거둘 수 없다. 열쇠 바꾸기는 다음 판에 넣는다.
- 폰은 열쇠를 받지 못한다(데스크톱만). 관문은 열쇠에서 표식·서명 공개키를 다시 만들어 금고와 같을 때만 맡기를 받는다 —
  열쇠 없는 기기가 다른 열쇠를 끼워 새 기기들을 엉뚱한 열쇠로 돌게 하지 못한다. 받는 기기도 받은 열쇠의 표식이 금고 표식과
  같을 때만 키체인에 둔다.
- 여전히 지키는 것: 덩어리는 잠긴 채 올라가고, 항목 이름은 HMAC 이며, 쓰기는 금고 서명이 있어야 한다. 관문 로그에는 아무것도
  남기지 않는다. 기기 사이 판정·시계 규칙은 그대로다.

## 열쇠

- 금고 열쇠 `K`(무작위 32바이트)는 기기 키체인과 관문의 맡긴 칸에 있다. 맥은 일반 암호 서비스 `kasaterm.login-vault`(믿는 앱 kasaterm 만),
  Windows 는 대상 `kasaterm.login-vault/<계정>`(`CRED_PERSIST_LOCAL_MACHINE`). 로그·기기 파일에는 나가지 않는다.
- `K` 를 HKDF-SHA256 으로 갈라 쓴다: 암호 키, 항목 이름 키, 상태 키, 쓰기 서명 열쇠(Ed25519), 열쇠 표식 `key_id`,
  사람이 보는 열쇠 지문(80비트, `XXXX-XXXX-XXXX-XXXX`).
- 관문은 금고를 만들 때 `key_id` 와 쓰기 서명 공개키를 받는다. 항목 쓰기는 그 서명이 맞을 때만 받는다 —
  `key_id` 는 누구나 받아 볼 수 있어, 같은 계정이라도 열쇠 없는 데스크톱이 덩어리를 덮지 못하게.
- 풀어 낸 평문·비밀번호·`K` 는 놓을 때 지워지는 그릇(`zeroize`)에 둔다. 복호는 제자리에서 하고 사본을 만들지 않는다.
- 첫 기기: 서버에 금고가 없으면 `K` 를 만들고 키체인에 먼저 둔 뒤 `init` 하고 맡긴다. 둘이 동시에 만들면 먼저 들어간 쪽이 이기고,
  진 쪽은 제 열쇠를 지우고 맡긴 열쇠를 받는다.

## 열쇠 맡기기와 받기

1. 첫 기기: 사람이 카사브라우저 설정 「동기화」의 [시작하기]를 누르면 `K` 를 만들어 키체인에 먼저 두고 `init` 한 뒤 바로 맡긴다.
2. 열쇠를 가진 기기는 금고 바퀴가 성공할 때마다(프로세스마다 한 번) `PUT escrow {key}` 로 맡긴다. 관문은 같은 열쇠면 그대로 둔다 —
   이미 맞추던 기기(회사 맥북·집 PC)는 새 판으로 올라가는 순간 맡기고 끊기지 않고 이어 간다.
3. 열쇠가 없는 기기는 금고가 있으면 `GET escrow` 로 받아, 표식이 금고와 같으면 키체인에 두고 1초 뒤 맞추기 시작한다. 아직 아무도
   맡기지 않았으면 「열쇠를 기다리는 중」(`waiting_for_key`)으로 두고 15초마다 다시 본다.
4. 옛 판에서 폰 등록으로 받고 지문 확인을 기다리던 표식(`unconfirmed-<계정>`)은 보이면 걷는다. 폰 Face ID 등록·지문 확인·
   「직접 믿기」는 없앴다.

## 서버 API·저장

- 저장: `login-vault/<계정>.json` = `{key_id, sign_pub, created_by, created_ms, revision, items: {id: {rev, at_ms, blob}}}`
  (`created_by` 는 금고를 만든 데스크톱의 관문 기기 이름).
  `at_ms` 는 기록일 뿐 — 기기는 시각을 봉인 안에서만 읽는다.
- `POST /relay/login-vault/init {key_id, sign_pub}` → 200 · 409 `vault_exists`
- `GET /relay/login-vault?since=<rev>` → `{key_id, revision, items, now_ms, created_by, created_ms}`
- `PUT /relay/login-vault/items {key_id, puts: [{id, expected_rev, blob|null}], sig}` → 항목마다 ok 또는 conflict `{current}` ·
  서명이 틀리면 403 `bad_signature`
- 열쇠: `PUT /relay/login-vault/escrow {key}` → 200 · 404 `not_found`(금고 없음) · 409 `key_mismatch` ·
  `GET /relay/login-vault/escrow` → `{key}` · 404(아직 아무도 맡기지 않음). 데스크톱만, 계정은 기기 토큰이 정한다.
  열쇠는 금고 파일의 `escrow` 칸에 둔다(항목 받기 `GET /relay/login-vault` 에는 섞이지 않는다).
- `id` = HMAC(이름 키, `web:<host>\n<소문자 아이디>`). 서버는 사이트·아이디를 모른다.
- `blob` = nonce + AES-GCM(암호 키, 평문, AAD `kasa.login-vault.v1:<계정>:<id>`). 평문 `{host, username, password,
  changed_at_ms, deleted, device}` 는 256바이트 단위로 채워 비밀번호 길이를 숨긴다.
- 한도: 항목 2000·blob 4KB·한 번에 200. 관문 로그는 남기지 않는다.

## 동기화

- 금고 열쇠가 있는 기기에서만 15초마다(`poke` 로 앞당김) 돈다.
- 로컬 목록은 **속성만** 읽는다(맥은 값을 안 읽으면 창이 안 뜬다, Windows 는 OS 가 준 값 칸을 읽지 않고 지운다).
  수정 시각이 바뀐 항목만 값을 읽는다.
- 로컬 상태 `~/.config/kasaterm/login-vault/state-<계정>.json`(0600): 만든 기기, `id → {rev, 봉인 안의 (시각, 기기), 삭제 여부,
  HMAC(상태 키, 값), 로컬 수정 시각}`. 평문은 없다. 다른 기기에서 옮겨 온 상태면 버리고 처음부터 맞춘다.
- 판정은 봉인 안의 `(changed_at_ms, device)` 로만 한다(같으면 기기 이름 순).
  - 관문 시계(`now_ms`)가 기기 시계보다 5분 넘게 뒤지면(어느 쪽 시계가 틀렸든) 그 바퀴를 「시계가 맞지 않아요」로 멈춘다.
    관문 시계로 제 시각을 깎게 두면 관문이 시계를 속여 옛 판을 이기게 할 수 있다. 5분 안이면 제 시각을 관문 시계 + 5분으로
    깎고, 이 기기가 본 판보다는 늘 뒤로 한 뒤 봉인한다.
  - 받은 항목은 이 기기가 아는 판보다 새것일 때만 적용한다. 낡은 것(관문이 옛 덩어리·옛 묘비를 새 차례로 내민 것)은 버리고
    아는 판을 그 시각·기기 그대로 다시 올린다. 관문 차례가 되돌아가도 차례만 다시 받고 아는 판은 바닥으로 남긴다.
- 삭제: 로컬에서 사라지면 묘비를 올린다. 한 바퀴에 5개 또는 아는 항목의 10% 중 큰 쪽을 넘게 사라지면 올리지 않고
  「지우기 N개 보류 — 확인」을 기다린다(목록을 잘못 읽어 비면 모든 기기에서 지워지는 것을 막는다). 묘비는 봉인 시각으로 180일 뒤 걷는다.
- 로컬에 못 쓴 관문 항목은 다음 바퀴에 다시 쓴다. 그사이 사람이 그 항목을 고쳤거나 지웠으면 재시도를 버리고 사람 것을 올린다.
  못 썼을 때의 로컬 값을 읽지 못했으면 고쳤는지 알 수 없어 재시도를 그대로 둔다. 값 지문의 아이디는 소문자로 넣는다.
- 값은 앱이 스스로 읽어 암호화에만 쓴다. 소켓 메서드로 내보내지 않는다(에이전트는 지금처럼 `kb login` + 폰 Face ID).
- 로그는 `[login-vault] 올림 N · 받음 N · 묘비 N · 보류 N · 지우기 대기 N · 실패 N · 안 풀림 N · 열쇠 넘김 N` 개수만.

## 맥 접근 목록

- kasaterm 이 **새로 만드는** 항목: `SecAccessCreate` 로 믿는 앱 [kasaterm, 매일 브라우저], 소유자(ChangeACL) [둘 다].
  매일 브라우저(`~/Applications/Kasa Browser OSR.app`)는 그 자리의 앱이 요구조건
  `identifier "dev.kasa.browser-osr" and anchor apple generic and certificate leaf[subject.OU] = "L366799VND"` 을 채우고, 만든 믿는 앱
  기록의 요구조건(`SecTrustedApplicationCopyRequirement`)이 확인을 통과한 그 코드의 지정 요구조건(`SecCodeCopyDesignatedRequirement`)과
  컴파일된 바이트(`SecRequirementCopyData`)까지 같을 때만 넣는다 — 글로 견주면 「… or identifier "다른 것"」 꼬리에 속고,
  확인과 기록 사이에 번들을 바꿔치기해도 여기서 걸린다. 안 채우면 kasaterm 만 믿는 항목이 되고, 브라우저가 처음 읽을 때 허용 창이 뜬다.
- 브라우저가 만든 **기존** 항목(소유자 = 브라우저)은 kasaterm 이 지우지 못한다(`errSecInvalidOwnerEdit` -25244).
- 실측(2026-11-16, `kasatest-` 접두사, kasaterm 과 같은 식별자·팀으로 서명한 대역):
  - 브라우저 소유 항목의 값을 kasaterm 이 `SecItemUpdate` 로 바꿔도 접근 목록은 그대로이고, 브라우저가 창 없이 다시 읽는다.
  - kasaterm 이 위 접근 목록으로 만든 항목은 브라우저가 창 없이 읽고 바꾸고 지운다.
  - 소유자 판정은 실행 파일 경로라, 진짜 `kasaterm.app` 이 제가 만든 항목을 지울 수 있는지는 대역으로 못 쟀다.
- 그래서 바꾸기는 제자리에서 하고 브라우저는 고치지 않는다. 키체인이 지우기를 거절하면 그 묘비는 「보류」로 세고
  브라우저에서 지우도록 안내한다(로컬 값이 그대로인 동안은 되살리지 않는다).
- Windows 자격 증명 관리자는 접근 목록이 없다. 자리는 브라우저 규칙 그대로(`web:<host>` 가 비었거나 같은 아이디면 거기,
  아니면 `<아이디>@web:<host>`, 대상 이름은 대소문자를 안 가린다).

## 실패했을 때

- 서버가 안 닿음: 로컬은 그대로, 다음 바퀴를 늦춘다. 브라우저는 영향이 없다.
- 덮어쓰기 충돌: 다시 받아 판을 견준 뒤 재시도한다.
- 안 풀리는 blob: 건너뛰고 센다. 전부 안 풀리거나 서명이 거절되면 동기화를 멈추고 `key_mismatch` 로 둔다(로컬을 덮지 않는다).
- 키체인 쓰기 실패·창 거절: 그 항목만 다음 바퀴로 미룬다.
- 열쇠를 가진 기기를 모두 잃음: 관문에 맡긴 열쇠가 있으면 새 기기가 로그인해 받는다. 맡기기 전에 잃었으면 서버 사본은 못 푼다 —
  새 금고를 만들어 남은 로컬 로그인을 다시 올린다. 사람이 누를 때만.
- 기기 빼기: 그 토큰으로는 더 받지 못하지만, 이미 받은 열쇠는 거둘 수 없다. 열쇠 바꾸기는 다음 판에 넣는다.
- 시계가 맞지 않음: 그 바퀴를 멈추고 설정에 알린다. 기기 시계를 맞추면 다음 바퀴에 이어서 맞춘다.
- 남는 틈: 기기 시계가 앞선 채 꺼져 있다 고친 것은 고친 순간을 알 수 없어, 관문 시계 + 5분 안에서는 나중 것으로 남을 수 있다.

## 시험

- 서비스·대상 접두사 `kasatest-web:` 만 쓴다. 접두사 바꾸기는 `cfg(test)`·`test-isolation` 에서만 받는다. 진짜 `web:` 은 건드리지 않는다.
- 엔진: `login_vault/tests.rs` 의 두 기기·시험 관문(옛 덩어리·옛 묘비 재전송, 목록이 갑자기 빈 바퀴, 남의 상태 파일, 재시도 중 사람
  수정, 앞선 시계, 가짜 열쇠). 열쇠 맡기기: `server.rs` 의 금고 것만 받기·다른 계정 분리·항목 받기에 안 섞임.
- 관문: `gateway_login_vault.rs` 의 HTTP 시험과 두 데스크톱 HTTP 동기화.
- 진짜 키체인 시험은 `#[ignore]` 로 손으로 돌린다: `cargo test -p kasa-device --lib windows_store -- --ignored`, 맥은 `macos_store`.
