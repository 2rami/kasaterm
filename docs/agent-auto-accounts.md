# 새 세션의 전체 계정 선택

`kasaterm-cli summon`의 기본/`--cmd auto`와 자동 디스패처는 도착 기기의 모든 Claude·Codex 계정 슬롯을 비교한다. `kasaterm-cli agent-plan [--machine ID]`는 세션을 만들지 않고 그 선택을 조회한다.

로그인이 확인됐고 사용량이 최신인 계정 중 사용률이 가장 낮은 계정을 고른다. 같은 사용률이면 선호 제공자, 그 제공자의 현재 계정, 슬롯 ID 순이다. 로그아웃·인증이 풀린 슬롯·100% 소진 슬롯은 제외한다. 조회 실패·오래된 값·미확인을 0%로 보지 않는다. 알려진 사용량이 하나도 없으면 로그인된 현재 계정만 선호 순으로 사용할 수 있고, 그때는 `used_percent:null`, `reason:usage_unavailable`을 돌려준다. 확인된 현재 로그인도 없으면 자동 실행을 거부한다.

선택 결과는 제공자와 `account_id`, 표시 이름, 사용률, 선택 사유다. 활성 Claude만 47%, 활성 Codex가 17%여도 대기 Claude 계정이 0%라면 그 대기 계정이 선택된다. 구형 `agent.choice`는 제공자 이름만 쓰는 이전 CLI가 다른 슬롯의 수치로 현재 계정을 실행하지 않도록 종전의 현재 계정 비교를 유지한다. 전체 계정 실행은 새 `agent.plan`과 `/agents/plan`의 `account_selection:1` 계약을 사용한다. 원격 응답의 기기 ID도 대조한다.

실행은 `kasaterm-cli account-run PROVIDER ACCOUNT -- COMMAND…`가 맡는다. 기본 Codex 슬롯은 셸에서 빈 인자가 사라지지 않도록 `@default`로 전달한다. 이 내부 실행기는 커널이 확인한 소켓 상대 PID와 자기 칸의 실제 프로세스를 대조하고 선택 슬롯의 존재·로그인·소진 상태를 다시 검사한다. Claude는 현재 정본 저장소(`runtime_dir_for`), Codex는 선택한 `auth.json` 디렉터리를 자식 환경에만 지정한다. 전역 선택값·진행 중인 다른 세션·인증 파일을 옮기거나 덮지 않는다. 명시적인 API 자격증명이나 다른 Claude API 실행 통로가 있으면 구독 계정 선택과 섞지 않고 명시 실행을 요구한다.

Codex TUI는 기존 pane 홈의 세션·설정·캐시 구조를 유지하고 인증 링크만 선택 계정으로 만든다. ACP도 같은 홈 준비 경로를 사용하고 file 인증 저장소를 지정한다. Windows에서 홈 준비 결과는 `cygpath`로 네이티브 경로로 반환한다. 선택 계정이 사라지거나 로그인 상태가 바뀌면 다른 계정으로 몰래 폴백하지 않는다. 원격 구판이 이 계약을 지원하지 않으면 업데이트가 필요하다.

같은 기기의 앱 복원에는 실행 중인 세션의 계정 선택을 함께 보관한다. 복원은 새 사용량 비교가 아니므로 등록된 원래 계정의 부팅 직후 확인 중 상태나 사용량 소진만으로 막지 않는다. 명시적으로 로그아웃됐거나 삭제된 슬롯은 실행하지 않는다. 다른 기기로 옮기는 기록에서는 출발 기기의 슬롯 번호를 적용하지 않는다. 명시적인 `--cmd claude`, `--cmd codex`, 사용자 래퍼·모델 지정·기존 대화 재사용은 자동 제공자 선택으로 바꾸지 않는다. 한도에 따른 기존 전역 계정 전환 기능은 별도다. 전역 계정 전환이 실행되면 그 의도가 우선하므로 해당 제공자의 자동 선택 복원 기록을 해제한다.

검증: 선택/예외/동률·구판 계약은 `kasa-socket` 시험, TUI/ACP 계획은 `kasa-students` 시험, Codex 인증 링크는 앱 shim 시험이다. `CARGO_TARGET_DIR=… python3 app/kasaterm/src/account_launch/tests/native.py`는 완전히 격리한 앱과 합성 계정·가짜 실행기로 선택한 계정의 자식 환경·복원 기록·전역 선택 불변을 확인한다. 실제 공급자 로그인이나 모델 요청을 만들지 않는다.
