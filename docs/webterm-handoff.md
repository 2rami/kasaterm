# 웹 터미널 인계 — 골격은 섰고, 여기서부터

브라우저에서 독립으로 열리는 터미널. 골격(`26dae6d`, `49865d0`)은 **동작 확인까지
끝났다** — 브라우저에서 셸이 뜨고, 명령이 실행되고, 한글·색이 정상이다.

## 지금 되는 것

**평소 경로는 kasaterm 자신이다.** kasaterm 이 떠 있으면 그 서버가 `/term` 을 연다 —
따로 띄울 게 없다.

```
open "http://127.0.0.1:8765/term"
```

⚠️ **8765 를 하드코딩하지 마라.** 그 포트가 점유돼 있으면 서버는 조용히 임의 포트로
간다(`bind(("127.0.0.1", 8765)).or_else(bind(("127.0.0.1", 0)))`). 붙는 쪽은 실제
포트를 찾아야 한다:

```sh
# 마지막 콜론 뒤를 자른다 — 콜론으로 split 하면 IPv6 에서 조용히 빈 값이 나온다
# (`[::1]:8765` → a[1]="[", a[2]=""). 빈 포트는 「서버가 없다」는 엉뚱한 결론이 된다.
PORT=$(lsof -nP -iTCP -sTCP:LISTEN -a -c kasaterm 2>/dev/null \
       | awk 'NR>1{sub(/.*:/,"",$9); print $9; exit}')
```

**실패를 둘로 갈라서 안내할 것** — 할 일이 다르다:
`PORT` 가 비었으면 「kasaterm 이 안 떠 있다」(켜면 된다), `PORT` 는 잡혔는데
`/term` 이 404 면 「도는 프로세스가 옛 바이너리다」(설치만으론 안 바뀌고 재시작이
필요하다 — 실행 중 바이너리를 덮으면 SIGKILL 이라 mv 로 갈아치우기 때문에, 파일이
최신이어도 프로세스는 옛 inode 를 문다).

kasaterm 없이 서버만 띄울 수도 있다(포트는 임의로 골라 쓴다):

```
cargo build -p kasa-mcp --bin kasa-serve-web
./target/debug/kasa-serve-web --port 8799   # 8799 는 예시일 뿐, 약속된 포트가 아니다
```

| 라우트 | 하는 일 |
|---|---|
| `GET /term` | xterm.js 페이지 |
| `GET /term/ws` | **웹 전용 셸을 새로 띄운다.** 연결이 끊기면 셸도 끝난다 |
| `GET /term/ws?pane=%1` | 기존 kasaterm pane 을 **미러**한다 (아래 ⚠️) |
| `GET /term/panes` | 살아 있는 pane 목록(미러 대상 고르기용) |
| `GET /term/ws?cwd=/path` | 새 셸의 시작 디렉터리 |

⚠️ **pane id 는 `%` 로 시작한다.** `?pane=%116` 을 그대로 치면 서버가 퍼센트
인코딩으로 읽어 `%11`(제어문자) + `6` 이 되고, 조회가 실패해 **화면 없이 연결만
끊긴다**(원인을 짐작하기 어려운 종류다). 스크립트에서는 인코딩해라 —
`?pane=%25116`. 사람이 흔히 밟는 함정이라 서버가 원문으로 한 번 더 조회하니
주소창에 그대로 쳐도 열리기는 한다.

**같은 함정이 클라이언트에도 한 번 더 있었다**(2026-08-11). `index.html` 이
`new URLSearchParams(location.search).get('pane')` 으로 읽었는데, 그러면 `%151` 이
`0x15` + `'1'`(코드포인트 `[21,49]`)이 된다. 서버는 raw 폴백이 있어 **화면은 멀쩡히
뜨고**, 대신 그 값으로 하는 것만 조용히 실패한다 — pane 목록 매칭(`p.id === here`)이
어긋나 드롭다운이 「새 셸」로 남고 이름 칩에는 제어문자를 뺀 `1` 만 찍힌다. 그래서
「이름 기능이 원래 없나 보다」로 읽혔다. 지금은 raw 쿼리에서 직접 잘라 쓴다
(`location.search` 를 재조립하지 않고 WS URL 에 그대로 넘기는 것도 같은 이유).
**교훈: `%` 로 시작하는 id 에 `URLSearchParams` 를 대지 마라.**

프로토콜은 채널을 갈라 두었다 — **binary = PTY 바이트**(양방향), **text = 제어**.
그래서 받는 쪽에 파싱이 필요 없다. 서버는 붙자마자
`{"t":"size","cols":N,"rows":M,"mirror":bool}` 를 한 번 보낸다.

## 설계에서 건드리면 안 되는 것

**① reader 를 블로킹하지 마라.** `state.rs` 의 tee 는 `try_send` 이고, 밀린 구독자는
**버리는 게 아니라 끊는다**. VT 스트림은 연속이라 중간 청크를 흘리면 받는 쪽 화면이
복구 불능으로 깨진다 — 조용히 깨뜨리느니 재연결시키는 게 낫다. 여기서 blocking
`send` 를 쓰면 셸 전체가 backpressure 를 먹어 터미널이 느려진다(카탈로그에 박제된
같은 병).

**② 미러 모드에서 resize 를 PTY 에 **자동으로** 먹이지 마라.** 같은 PTY 를 보고 있는
kasaterm pane 의 화면이 같이 깨진다. 창 크기 변화는 무시하고 서버가 알려준 격자에
클라가 맞춘다.

예외는 **사용자가 누른 순간뿐**이다(`{"t":"resize",…,"force":true}`, 하단 바의 ⤢).
폰에서 193열 pane 은 축소로 안 들어가서 — 읽을 만한 크기면 1158px 가 필요한데
화면은 374px 다 — 이 규칙을 깨야만 읽을 수 있다. 자동이면 폰으로 잠깐 들여다본
것만으로 데스크톱 화면이 줄어드니, **누른 순간에만** 열어 둔다.

**③ pane 을 만드는 새 경로는 `self.pty.insert` 가 아니라 `insert_pty`.** 레지스트리
등록이 거기 묶여 있다. 빠뜨리면 **그 pane 만 조용히 웹에서 안 보인다** — 찾기 어려운
종류의 구멍이라 통로를 하나로 모아 놨다.

**④ 레지스트리는 프로세스 전역이다.** `kasa-serve-web` 은 별도 프로세스라 kasaterm 의
pane 을 볼 수 없다(`/term/panes` 가 `[]`). **미러는 kasaterm 자체 서버(8765)에서만**
동작한다. 이건 버그가 아니라 구조다 — 별도 프로세스에서 미러하려면 IPC 가 따로 필요.

## 폰에서 쓰기 (2026-08-10)

기본은 여전히 loopback 이다. **여는 것은 명시적 선택**이어야 한다:

```sh
# ① 열기 — 둘 중 하나. GUI 앱은 env 를 물려받지 않으므로 앱에서는 파일 쪽을 쓴다.
echo '{ "bind": "0.0.0.0" }' > ~/.config/kasaterm/remote.json
KASATERM_BIND=0.0.0.0 ./target/debug/kasa-serve-web --port 8799   # CLI 는 env 도 됨

# ② 폰에서 한 번 열면 그 뒤로는 쿠키로 다닌다
open "http://<이 기기 주소>:8765/term?t=$(cat ~/.config/kasaterm/remote-token)"
```

- **loopback 밖에서 온 연결에는 토큰이 필수**다(`origin_guard_mw`, peer 주소로 판정).
  로컬 규칙은 하나도 안 바뀌었다 — 「Origin 이 없으면 로컬 CLI 라 통과」의 근거가
  "이미 같은 사용자 권한"인데 원격에는 그게 성립하지 않아서, 원격만 따로 가른다.
- 토큰은 `~/.config/kasaterm/remote-token`(0600)에 **남는다**. 프로세스마다 새로
  만들면 폰 북마크가 앱을 껐다 켤 때마다 깨진다.
- `?t=` 로 한 번 들어오면 `/term` 이 HttpOnly·SameSite=Strict 쿠키로 바꿔 심는다.
  WebSocket 은 커스텀 헤더를 못 붙이므로 그 다음부터는 쿠키가 유일한 경로다.
- 하단 바(pane 고르기 + esc·⇥·^C·↑·↓)는 `(hover: none)` 에서만 뜬다. 물리 키보드가
  있으면 자리만 먹는다.
- ⚠️ **실사용에서는 ⤢ 가 선택이 아니라 사실상 필수다.** 실제 pane 은 150~151열이라
  폰트를 5px 하한까지 줄여도 455px 로 폰 화면(374px)을 넘고, 그대로면 가로 스크롤이
  생긴다(2026-08-11 실측). 그래서 넓은 pane 을 폰에서 읽으려면 ⤢ 를 눌러 PTY 를 폰
  격자로 줄여야 하는데, **그 순간 같은 PTY 를 보는 데스크톱 pane 도 같이 줄어든다.**
  자동화하지 않은 이유가 이것이고, 이 트레이드오프는 없앨 수 없다 — 하나의 PTY 를
  두 화면이 공유하는 한 격자는 하나다.

**밖에서 붙기 — 터널.** Orca 의 릴레이는 클라이언트만 오픈소스라 참고본이 없다.
`cloudflared` 가 같은 결과를 준다(무료, 인바운드 포트 0, WebSocket 지원):

```sh
cloudflared tunnel --url http://127.0.0.1:8765
```

⚠️⚠️ **터널은 바인딩을 안 건드리므로 「127.0.0.1 이니 원격이 못 온다」가 깨진다.**
`cloudflared` 는 **같은 머신에서 loopback 으로** 붙는다. 그래서 peer 주소만 보던
원래 판정에서는 밖에서 들어온 요청이 전부 로컬로 보였고, **토큰 관문을 통째로
건너뛰었다** — 바인딩이 `127.0.0.1` 그대로인데도 터널 주소를 아는 사람이 무인증으로
셸에 닿는 상태였다. 그래서 `is_remote_peer` 는 peer 에 더해 **프록시가 붙이는
`CF-Connecting-IP`·`X-Forwarded-For` 도 원격 신호로 본다.** 이 판정은 한쪽으로만
틀린다: 브라우저도 우리 코드도 그 헤더를 안 보내니 로컬은 그대로고, 로컬에서 위조해
붙여도 토큰을 더 요구받을 뿐이다. **다른 터널을 쓸 거면 그게 이 헤더를 붙이는지 먼저
확인해라** — 안 붙이는 터널은 이 관문을 그대로 통과한다.
실측으로 **cloudflared 와 ngrok 은 둘 다 붙인다**(양쪽 다 무토큰 403·토큰 200 확인).

**고정 주소 (named tunnel, 2026-08-10 구축).** quick tunnel 은 주소가 매번 바뀌어
폰 북마크가 깨진다. 이름 붙은 터널이 그걸 없앤다 — 설정은 `~/.cloudflared/config.yml`
에 있고, 주소는 **`https://kasaterm.debimarlene.com`** 이다.

```sh
cloudflared tunnel run kasaterm     # 켜기. 끄면 그 주소는 530 이 된다
```

- 만드는 절차는 한 번만 하면 된다: `tunnel login`(브라우저에서 도메인 선택 — **사람이
  해야 하는 유일한 단계**) → `tunnel create <이름>` → `tunnel route dns <이름> <호스트>`
  → config 작성. 도메인이 Cloudflare 에 등록돼 있어야 한다.
- **껐다 켜도 같은 주소**임을 확인했다(내리면 530, 올리면 같은 주소로 200).
- 부팅 자동 시작(`cloudflared service install`)은 **일부러 안 걸었다.** 상시 노출은
  그때그때 켜는 것과 위험의 성격이 다르다 — 켤지는 그때 정한다.
- ⚠️ ngrok 무료 플랜은 고정 도메인이 유료 전용이다(`ERR_NGROK_313`). 도메인 없이
  고정 주소가 필요하면 Tailscale 쪽이 답이고, 그건 아예 공개 노출이 없다.

⚠️ 무료 플랜은 **유휴 WebSocket 을 ~100초에 끊는다.** 터미널은 조용한 시간이 길어
반드시 걸리므로 서버가 30초마다 ping 을 끼운다(`term_ws_run`).

**터널 실측 (2026-08-10, quick tunnel 경유 · 로컬 대조):** 130초 무입력 뒤에도 양쪽 다
살아 있고 명령이 닿는다(서버 PING 4 / PONG 4, 30초×4=120초와 일치). 폰 UI 에서 친
한글 명령이 터널을 건너 실제 pane 에 들어가고 미러로 되읽히는 것까지 확인했다.

> ⚠️ **여기서 테스트가 먼저 거짓말한다 — 「유휴 뒤 죽었다」로 보이면 프레임 종류부터 봐라.**
> 키 입력은 **바이너리 프레임만** 셸로 간다(`Message::Binary` → `send_bytes`). 텍스트
> 프레임은 resize JSON 으로만 해석되고 **조용히 버려진다** — `index.html` 이 `enc.encode()`
> 로 보내는 이유다. python `websockets` 에서 `ws.send("문자열")` 은 텍스트라, 생존 확인용
> echo 가 셸에 닿은 적도 없이 "응답 없음"이 된다. 실제로 이걸로 한 번 「터널이 100초에
> 끊었다」는 오진을 했다 — ping 은 멀쩡히 오고 있었는데도. `ws.send(b"...")` 로 보내라.

   프레임 하나로 보낸다(`tap_bytes_with_snapshot`). 클라이언트는 수정 0줄이었다.
   ⚠️ 구독 등록과 스냅샷 채취는 **`term` 락 하나 안에서** 끝나야 한다 — 갈라 놓으면
   그 사이 출력이 양쪽 어디에도 없이 사라진다(옛 순서에서 실제로 재현됐다).
   지금은 뷰포트만 담는다. 스크롤백까지 넣으려면 alacritty `Grid` 의 음수 라인
   인덱스로 history 를 훑어야 한다.

   에서도 같은 게 나오는데 폰트 차이로 덜 띄었을 뿐이다. 굳이 지우려면 셸 쪽
   `unsetopt PROMPT_SP` 지 터미널이 할 일이 아니다.

4. ~~세션 지속성~~ → **웹 전용 셸은 해결.** `keep_session` 이 강한 Arc 를 붙들어
   연결과 수명을 갈랐다. 탭을 닫아도 살아 있고, 셸이 `exit` 하면 EOF 를 보고 스스로
   빠진다. TTL 은 안 뒀다 — 「덮었다 다시 여는」 용도라 시간으로 끊으면 그 목적이
   사라진다.

   ⚠️ **아직 안 된 것: kasaterm GUI pane 의 지속.** PTY 소유권이 `App.pty`
   (`main.rs`)에 있어서 앱이 죽으면 그 pane 들은 함께 죽는다. 프로세스 전역
   레지스트리는 `Weak` 라 **접근만 분리하고 수명은 분리하지 못한다.** 살리려면 PTY 를
   GUI 밖 프로세스가 소유해야 하고(`kasa-serve-web` 이 그 자리다), GUI 가 거기에
   붙는 경로를 새로 내야 한다 — 렌더 경로까지 건드리는 별도 작업이다.
   ⚠️ 그때도 **layout·session·docked 는 GUI 가 계속 소유**해야 한다. 2026-06 에
   걷어낸 데몬이 죽은 이유가 layout 권한 이중화(부활·증식·drag먹통·덮어쓰기)였고,
   PTY 수명만 밖으로 내면 그 실패 메커니즘은 구조적으로 재현되지 않는다.

5. ~~pane 목록 UI~~ → **해결.** 하단 바의 드롭다운이 `/term/panes` 를 채운다.
   여러 탭 열기는 아직 없다(주소를 따로 열면 된다).

   `/term/panes` 는 이제 id 만이 아니라 `{id, name, title, status}` 를 준다 —
   board(`collab_board`)가 이미 알던 것을 얹었을 뿐이다. 그전에는 폰에서 `%86` 만
   보여 **누가 무슨 일을 하던 pane 인지 알 수가 없었다.** 답을 기다리는 pane 은
   `●` 를 달고 목록 맨 위로 온다(폰을 여는 이유가 대개 그것이다).
   ⚠️ 목록의 정본은 여전히 `live_sessions()` 다. board 에만 있고 PTY 가 없는 행을
   섞으면 골랐을 때 연결이 그냥 끊긴다.
   ⚠️ 이 이름 표시는 **넣자마자는 실제로 안 보였다** — 클라이언트의 `%` 디코딩
   버그(위 라우트 절)로 `p.id === here` 가 어긋나 있었다. 코드가 있는 것과 화면에
   뜨는 것은 다르니, 고친 뒤엔 **실제로 그 pane 을 열어** 칩과 드롭다운을 봐라.

6. ~~폰트~~ → **해결.** 번들 `CascadiaCodeNF` 를 실제 쓰는 범위만 서브셋해 woff2 로
   서빙한다(`/term/font.woff2`, 2.4MB → 356KB, 1년 immutable 캐시).
   그전에는 claude code 화면의 **Nerd Font 아이콘이 폰에서 두부(□)로** 나왔다 —
   그 글리프가 사설영역(U+E000–F8FF)에 있어 시스템 폰트에 없기 때문이다.
   PUA 2323자를 통째로 넣었다: 하나 빼면 그게 다시 두부가 된다.
   **한글은 일부러 뺐다** — 이 폰트에 애초에 없고 넣으면 몇 MB가 된다. 폰이 가진
   한글 폰트로 폴백되며, 그래서 한글 폭이 2셀보다 좁아 보이는 것은 그대로 남는다.
   ⚠️ 웹폰트는 늦게 온다. xterm 은 그 사이 폴백 폰트로 글자 폭을 재서 격자를 잡아
   두므로, **로드 후 다시 재지 않으면 글자가 칸에서 어긋난다**(`document.fonts.load`
   뒤에 `syncSize`).

   ⚠️ **화면에서 한글 자간이 벌어져 보이는 것은 이것 때문이지 스냅샷 버그가 아니다.**
   한글 글리프가 Menlo/SFMono 에 없어 시스템 폰트로 폴백되는데 그 폭이 2셀보다 좁아
   남는 자리가 생긴다. 스냅샷 쪽 실제 버그(`'\0'` 스페이서를 공백으로 흘리던 것)는
   따로 있었고 고쳤다 — **의심되면 스샷 말고 바이트를 봐라**: WS 로 붙어 첫 바이너리
   프레임을 디코드하면 `'가나다라 ABC 마바사'` 처럼 원문 그대로여야 한다.

7. **폰 세로가 남는다 — 격자 종횡비다.** 미러는 pane 격자를 그대로 따라야 하는데,
   데스크톱 pane 은 196×33 처럼 가로로 길고(≈6:1) 폰은 세로로 길다(≈1:2). 폭을
   맞추려 폰트를 5px 까지 줄이면 33행이 화면의 **30%** 만 채운다(실측: 폭 374px 에서
   격자 234px / 컨테이너 784px). 아래 550px 이 배경으로 남는다.
   ⚠️ **rows 를 늘려 채우려 하지 마라.** claude code TUI 는 절대 커서 좌표를 쓰므로
   격자를 서버보다 크게 잡으면 스크롤 시퀀스가 어긋나 화면이 밀린다. 남는 자리는
   여전히 남고 대신 화면이 깨진다.
   실질적인 답은 둘뿐이다 — **⤢**(PTY 를 폰 격자로. 대가는 데스크톱 pane 도 같이
   줄어드는 것), 또는 **스크롤백 스냅샷**(1번). 후자는 아래를 채우는 게 아니라 위에
   히스토리를 붙이는 것이라, 「빈 아래」는 그대로고 대신 읽을 것이 늘어난다.

## 보안 — 왜 「127.0.0.1 이니까 안전」이 여기선 틀렸나

다른 라우트들은 wildcard CORS 를 쓰면서 "서버가 127.0.0.1 에만 바인드하니 열린
origin 도 로컬 한정"이라는 논리로 정당화한다. **웹소켓에는 그 논리가 통하지 않는다.**

- 웹소켓은 same-origin 정책의 보호를 받지 않는다. 브라우저는 임의 출처 페이지가
  `ws://127.0.0.1:<port>` 로 연결하는 걸 막지 않고, CORS preflight 도 없다.
- 그래서 127.0.0.1 바인딩이 막는 건 **다른 기기**뿐이다. 사용자가 방문한 아무
  웹페이지가 이 소켓을 열어 **임의 명령을 실행하는** 경로는 그대로 열려 있었다.
- 읽기 전용 JSON 과 셸은 위험의 급이 다르다. 셸에는 별도 방어가 필요하다.

지금은 `ws_origin_ok` 가 Origin 을 직접 검사한다 — 브라우저가 보낸 Origin 은 우리
Host 와 정확히 같아야 하고, 호스트명은 `127.0.0.1`/`localhost` 여야 한다. 호스트명은
**정확히 대조**한다(`starts_with` 로 봤다면 `127.0.0.1.evil.com` 이 통과한다).
Origin 이 아예 없으면 브라우저가 아닌 로컬 클라이언트라 통과시킨다 — 이미 같은
사용자 권한으로 도는 프로세스라 막아도 얻는 게 없다.

실측(`curl` 로 헤더 위조):

| Origin | 결과 |
|---|---|
| `https://evil.example.com` | **403** |
| `http://127.0.0.1:8799` (우리 페이지) | 101 Switching Protocols |
| `http://127.0.0.1.evil.com:8799` | **403** |

**새 라우트를 추가할 때**: 부작용이 있는 웹소켓에는 반드시 `ws_origin_ok` 를 통과시켜라.

## 밟았던 함정

- **UMD 두 개를 concat 할 땐 사이에 세미콜론.** xterm.js 가 세미콜론 없이 끝나
  addon-fit 의 `!function(){}` 이 인자로 먹혔고, `FitAddon is not defined` 로 죽었다.
  `Terminal` 은 떠 있는데 addon 만 없으면 이걸 의심할 것.
- **xterm 기본 스크롤바는 밝다** — 어두운 배경에서 흰 띠로 튄다. CSS 로 눌러 놨다.
- 브라우저 자동화로 `\033` 을 타이핑하면 실제 ESC 로 전송된다. 검증할 땐
  `echo` 같은 단순 명령으로 확인하는 게 확실하다.
