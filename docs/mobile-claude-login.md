# 폰에서 Claude 재로그인

KASA 자체 Google·GitHub 로그인과 별개다. 이미 데스크톱에 등록된 Claude 계정의 로그인이
만료되었을 때 폰에서 승인하고, 그 데스크톱의 해당 슬롯만 복구한다.

## 사용 흐름

1. 폰 설정의 **Claude 계정**, 또는 Claude 로그인 만료 알림을 연다.
2. 로그인할 기기와 등록된 계정을 확인하고 **다시 로그인**을 누른다.
3. **Safari에서 로그인**으로 공식 Claude 승인 페이지를 연다.
4. 승인 화면의 인증코드를 복사해 KASA로 돌아와 붙여 넣고 보낸다.
5. 기존 계정 UUID 증명이 없는 슬롯은 실제 이메일·조직을 확인한 뒤 저장을 승인한다.

알림은 계정 목록만 연다. 로그인은 사람이 버튼을 누른 뒤에만 시작한다. 기기를 이름이나
목록 순서로 추측하지 않으며 시작 요청에도 안정 기기 ID를 넣어 수신기가 확인한다.

선택한 슬롯에 저장한 것과 현재 실행 중인 Claude에 반영한 것은 구분한다. 그 슬롯을 이미
쓰고 있고 작업대 소유를 확인할 수 있을 때만 실행 자격도 갱신한다. 다른 계정을 자동으로
선택하지 않는다. 저장은 됐지만 작업대가 달라졌으면 폰에 적용 보류를 표시한다.
다른 기기로의 토큰 공유는 기존 관문 사슬 동기화를 따르며, 폰 화면이 모든 기기의 적용
완료를 대신 보증하지 않는다.

## 지원과 실패 표시

- 새 폰 앱과 새 데스크톱 앱이 모두 필요하다. 옛 데스크톱의 `action_unknown`은 업데이트 필요로 표시한다.
- 원본 로그인 프로세스는 macOS·Linux·Windows의 설치된 Claude CLI를 사용한다. Windows 판 CLI는 `BROWSER`가
  있으면 그 명령만 부르고 `rundll32`(기본 브라우저)로 넘어가지 않으므로(2.1.309 실측), 단계 폴더 안의 없는 경로를
  준다. 원본 컴퓨터에는 아무 창도 뜨지 않고 수동 승인 URL만 출력된다. CLI와 그 자식은 작업 객체에 묶어 취소·실패
  때 함께 끝낸다. Windows 자격은 키체인 없이 `<설정 폴더>\.credentials.json` 파일이다(아래 파일 규칙).
- CLI 2.1.30x는 승인 URL을 `https://claude.com/cai/oauth/authorize`로 낸다. 옛 `claude.ai`·`console.anthropic.com`·
  `platform.claude.com`의 `oauth/authorize`와 함께 이 주소만 받는다.
- 원본 데스크톱이 켜져 있고 같은 KASA 계정으로 연결돼 있어야 한다. 기기 연결이 바뀌면
  예전 응답으로 새 화면을 갱신하거나 다른 기기에 코드를 보내지 않는다.
- 대상은 등록된 이름 있는 슬롯이다. 빈 기본 슬롯을 다른 계정으로 추측하거나 슬롯을 자동 생성하지 않는다.
- 요청 시간은 10분이다. 응답을 잃은 시작은 같은 nonce로 확인·취소하며, 확인 전에는 기기·슬롯을 바꿔
  요청의 행방을 잃지 않는다. 연결이 닫혀 취소를 확인할 수 없으면 미확인임을 표시한다.
- 폰이 배경에 있으면 상태 폴링을 멈추고 돌아왔을 때 다시 확인한다. 인증코드 자동 클립보드 읽기는 없다.

## 인증과 저장 경계

CLI는 임시 전용 설정·홈·자격 저장소에서 실행한다. 원본 컴퓨터의 브라우저는 열지 않는다.
CLI가 출력한 공식 HTTPS 수동 승인 URL만 전달하고 `redirect_uri`, `state`, PKCE 값을 바꾸지 않는다.
코드 붙여넣기는 [Claude CLI가 지원하는 수동 인증 경로](https://code.claude.com/docs/en/whats-new/2026-w18)다.

인증 뒤 실제 접근 토큰으로 공급자 프로필을 확인한다. 알려진 계정·조직 UUID와 다르면 거부한다.
UUID가 없을 때 이메일·조직명은 모순을 거부하는 데만 쓰고, 두 문자열이 같아도 자동 저장하지 않는다.
명시 확인도 확인한 프로필·해당 로그인 흐름에만 유효하다.

최종 저장은 현재 KASA 로그인 표식, 슬롯 존재·연결, 시작할 때 읽은 원본 자격을 다시 대조한다.
`claudeAiOauth`만 바꾸고 기존 MCP 자격 등 다른 항목은 보존한다. macOS는 제한 시간 있는
`security -i` 표준입력으로 쓰며 토큰을 프로세스 인자에 넣지 않는다. 파일은 소유자 전용 자격 파일을
원자 교체하고, 심볼릭 링크·다른 소유자·타인의 쓰기 권한은 거부한다.

폰 저장과 관문 사슬의 로컬 쓰기는 같은 기기 로그인 잠금 안에서 최종 비교한다. 지연된 pull·seal이
새 로그인 문서를 덮거나 새 갱신 토큰을 지우지 못한다. 키체인 API나 파일 rename 자체에는 내용 기반
조건부 쓰기가 없어, 앱 밖의 독립 Claude 프로세스와 마지막 확인·쓰기 사이를 완전히 원자화할 수는 없다.
불확실한 쓰기를 원본 삭제나 복원 덮어쓰기로 우회하지 않는다.

취소·만료·실패·로그인 주인 변경 시 후속 완료는 반영하지 않는다. CLI를 종료·수거하고 임시 저장소 정리를
끝낼 때까지 새 로그인 점유권을 주지 않는다. 임시 키체인 정리는 이 실행이 만든 정확한 서비스·사용자만
대상으로 하며 OS 정리 실패는 best-effort다. 사용자 원본 슬롯을 정리 대상으로 쓰지 않는다.

## 전송 계약

기존 인증된 `POST /settings/action`을 사용하며 손님 폰 주소는 거부한다. 응답은 `no-store`이고 요청별
회신 채널에 직접 싣는다. 공유 설정 메타데이터 셀을 거치지 않아 다른 요청에 승인 URL이나 흐름 ID가 섞이지 않는다.

| action 접미사 (`claude-phone-login-…`) | `id` | `label` |
|---|---|---|
| `start` | 슬롯 ID | JSON 문자열 `{nonce: UUID, machine_id: 안정 ID}` |
| `status` | 흐름 ID | 없음 |
| `code` | 흐름 ID | 승인 코드 |
| `confirm` | 흐름 ID | 확인 nonce |
| `cancel` | 흐름 ID | 없음 |

성공적인 요청의 봉투는 `{ok:true, phone_login:{…}}`다. 로그인 자체의 실패는 `state:failed`로,
잘못된 요청은 `{ok:false, error_code:…}`로 구분한다. `succeeded`는 프로필 확인·슬롯 저장 확인 뒤에만
반환한다. `runtime_updated`와 `runtime_error_code`는 현재 실행 자격의 별도 결과다.
인증코드·URL·토큰·지문은 로그와 오류문에 넣지 않으며 GUI 요청 인자의 `Debug`도 가린다.

## 검증 범위

회귀 시험은 가짜 CLI·가짜 공급자·메모리 또는 임시 저장소만 쓴다. 실제 권한 입구는 시험·격리 환경에서
꺼져 있고, 시험용 권한 우회는 없다. 앱과 시험이 같은 상태 전이를 사용한다.
실제 사람의 Claude 승인·실제 로그인 갱신, iOS Safari에서 돌아오는 조작은 가짜 시험으로 증명하지 않는다.
