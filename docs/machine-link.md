# 기기 연결 기록 — 끊긴 기기를 지우지 않고 「왜」를 남긴다

다른 기기가 사이드바 기기 목록에서 통째로 사라질 때가 있었는데 이유를 볼 곳이 없었다(2026-10-15 지적). 폴링은 실패
사유를 버렸고(`fetch_panes` 의 `.ok()?`), 명부에서 빠진 기기는 흔적 없이 지워졌다. 코드는
`crates/kasa-mcp/src/machines/link.rs`, 화면 모양은 [design.md](design.md) 「끊긴 기기」.

## 기기가 목록에서 빠지던 길 (코드로 확인)

| 길 | 어디서 | 언제 타나 |
| --- | --- | --- |
| 손님 기한 | `machines.rs guest_machines` (`GUEST_FORGET` 10분) | 명부에 없고 그쪽이 알려 와서(`/machines/announce`) 생긴 기기가 10분 넘게 안 알려 오면. 그쪽이 잠들거나 꺼지거나, 그쪽에서 이쪽으로 오는 길이 끊기면 탄다 |
| 명부 파일을 못 읽음 | `machines.rs listed_entries` (`unwrap_or_default`) | `machines.json` 이 깨지거나 못 읽히면 명부의 기기가 한꺼번에 빠진다. 앱과 계정 동기화의 쓰기는 임시 파일+이름 바꾸기라 반쯤 쓴 파일을 읽는 일은 없다 — 손으로 고치다 깨뜨렸을 때 |
| 계정 동기화 주소 못 풂 | `machines.rs parse` (`account_sync_unresolved`) | 다른 기기에서 받은 연결의 ssh 주소를 이 기기에서 못 풀면 그 행을 건너뛴다 — 명부엔 있는데 목록엔 없다 |
| 계정 동기화 삭제 | `account_sync/local.rs merge_files` | 다른 기기에서 지운 연결(계정 소유·로컬 필드 없음)을 이 기기 명부에서도 지운다 |
| 같은 기기 합치기 | `machines.rs canonical_roster` | 기기 id 가 같은 두 항목(명부의 「나쵸네코」와 그 기기가 스스로 알린 「nachoneko」)을 하나로 — 기기는 남고 별칭만 빠진다. 의도된 것. 알린 이름은 `/version` 으로 id 를 배우기 전 첫 바퀴(5초 남짓)만 따로 선다. 연결 기록은 합쳐진 별칭을 「목록에서 빠짐」으로 적지 않는다(`drop_merged`) |
| 끊긴 기기의 방 | `snapshot_machine` (`panes: []`) | 기기 머리는 남고 방 카드만 전부 빠졌다(「기기에 연결할 수 없음」 한 줄) |
| 재시작 뒤 보기 방 | `session/local_restore.rs state` (2026-10-14~) | 보기 창은 저장에서 걸러져 재시작하면 보던 기기 방이 전부 닫혔다(2026-10-15 맥미니 보기 방 4 → 0). 이제 보던 방만 기억했다가 다시 연다 — [mirror-render.md](mirror-render.md) 「세션 복원과 기기 화면」 |
| 하단바 기기 연결 | `machinescol::status_links` (`online` 만) | 끊긴 기기는 수에서 빠지고, 다 끊기면 칸이 통째로 사라졌다 |

후보였으나 기기 묶음을 빼지 않는 것: 보기 방이 닫혀 묶음이 비는 것(「열린 pane 없음」으로 남는다), 카사넷 동료 표 만료(보드
`sources` 는 학생 줄·`collab.reach` 에만 쓰이고 기기 묶음은 `machines::snapshot` 이다), 관문 끊김(이 기기 스냅샷은 업링크를
안 본다 — `snapshot()` = `snapshot_with_uplinks(&[])`, 관문 생존은 폰 `/machines` 에만), `display_identity`(표시 이름만 고른다).

**실제로 본 것(2026-10-15):** 개인맥북 로그에서 「건호의 MacBook Pro」가 손님으로 붙었다 빠졌다를 되풀이했다
(`3 곳 폴링` ↔ `2 곳 폴링`) — 개인맥북 명부엔 이 맥북이 없고, 이 맥북이 알려 와서만 선다. 같은 때 이 맥북 쪽 로그엔
개인맥북으로 가는 되돌아오는 길이 `연속 72번째` 끊김이었다.

## 판정

- 붙음·끊김은 화면과 같은 규칙이다 — 마지막으로 닿은 지 20초(`STALE_AFTER`). 폴링 한 바퀴가 끝날 때마다(`settle`) 바뀐
  것만 적는다. 부팅 뒤 20초는 첫 끊김을 안 적는다(터널이 서기 전이라 누구나 잠깐 안 닿는다).
- 실패 이유는 끊김으로 바뀌기 전부터 적어 둔다 — 화면이 끊김으로 바뀌는 순간 이유가 함께 선다.
- 카사넷 직통으로 물었다가 길이 안 닿으면 원래 길(ssh 터널·명부 주소)로 한 번 더 묻는다. 직통은 저쪽 앱이 꺼져도
  시간 초과로만 끝나 까닭을 못 가른다. 원래 길이 살아 있으면 끊김으로 치지 않는다.

| 이유 | 언제 |
| --- | --- |
| ssh 길 끊김 / ssh 인증 거절 / ssh 주소를 못 찾음 | 이 앱이 든 터널의 ssh 가 죽었다. 원문은 ssh stderr 마지막 줄 |
| 그 기기 앱이 꺼짐·재시작 중 | 연결은 됐는데 답 없이 닫혔다(터널 너머 8765 가 없다), 또는 거부 |
| 연결 거부 · 터널이나 그 기기 앱이 꺼짐 | 루프백 주소(손으로 든 터널·리그)가 거부 — 너머가 터널인지 앱인지 모른다 |
| 그쪽이 열어 둔 되돌아오는 길(-R)이 끊김 | 손님 기기의 주소(그쪽 ssh 의 -R)가 거부 |
| 응답 없음 | 시간 초과(4초) |
| 직통·중계 둘 다 응답 없음 / · 관문 중계로는 닿음 / · 관문 중계도 안 닿음 | 관문을 쓰는 기기(로그인·id 앎)면 보드의 관문 우회 길(`board_service::known_route`)도 함께 본다 |
| 인증 거절 | HTTP 401·403 |
| 옛 판이라 방 목록 길 없음 | HTTP 404·405 (`/term/panes` 없음) |
| 오류 응답 HTTP n / 답 모양이 다름 | 그 밖의 상태·본문 |
| 모름 | 위에 안 걸린 것 — 원문 한 줄을 함께 |
| 알려 오던 길이 10분 넘게 끊겨 목록에서 빠짐 · 명부 파일을 못 읽음 · 명부(machines.json)에서 빠짐 · 계정 동기화로 받은 연결 주소를 이 기기에서 못 풀었음 | 명부에서 빠진 기기(아래) |

## 명부에서 빠진 기기

목록에 있던 기기가 다음 바퀴에 없으면 이유를 달아 남긴다(`ghosts`, 스냅샷 끝의 `gone: true` 행). 다시 들어오면 걷히고
「목록에 다시 들어옴 · 붙음」이 남는다. 같은 기기 id 로 합쳐진 별칭은 남기지 않고, 설정에서 사람이 지우거나 이름을 바꾼
기기(`save_entries` → `forget`)도 바로 사라진다. 이 기기 화면(사이드바·하단바·기기 메뉴·CLI)에만 싣고 `/machines`(폰·다른
기기)엔 안 싣는다. 기록은 메모리에만 있어 앱을 다시 켜면 처음부터다.

## 보는 곳

- 사이드바 기기 머리 둘째 줄 「끊김 · 이유 · 시각」, 본문에 이유 전문과 마지막으로 닿은 때. 머리에 올리면 최근 8개 기록.
- 하단바 기기 연결 칸 「직통 2·끊김 1」, 팝오버의 끊긴 줄 아래 이유.
- `kasaterm-cli machines` — 기기마다 최근 셋과 끊긴 기기의 원문. `--history` 면 기기마다 20개 전부와 원문, `--json` 의
  `roster[].link` 에 `state`·`reason`·`detail`·`last_ok_ms`·`rooms`·`gone`·`events`.

## 리그 재현 (2026-10-15, 격리 앱 둘, 같은 맥)

A 는 `KASATERM_MACHINES_FILE` 로 명부 파일을 따로 두고(손으로 고쳐 빠짐·깨짐을 만든다), B 는 A 를 명부에 두어 카사넷이
양쪽에서 선다(`KASATERM_KASANET_BIND=127.0.0.1:0`). A 의 명부에서 B 주소는 끊었다 이을 수 있는 TCP 중계 포트로 두고,
403·404 를 돌려주는 가짜 기기와 한 번만 알려 오는 손님 가짜 기기를 함께 둔다.

| 한 것 | A 에 뜬 이유 | 다시 켜면 |
| --- | --- | --- |
| B 앱 끄기 (직통 1ms 로 붙어 있을 때) | 그 기기 앱이 꺼짐·재시작 중 (직통 실패 → 원래 길 `connection reset`), 끊김 판정 순간 이유 함께 | 3초 안에 붙음 |
| 중계 포트만 막기 | 끊김 없음 — 카사넷 직통으로 계속 붙어 있다 | — |
| B 를 새 카사넷 키로 다시 켜고 중계 포트도 막기 | 응답 없음 (원문: 원래 길 시간 초과) | 3초 안에 붙음, 새 키로 직통 다시 섬 |
| 403 기기 | 인증 거절 | — |
| 404 기기 | 옛 판이라 방 목록 길 없음 | — |
| 명부 파일에서 한 줄 지우기 | 명부(machines.json)에서 빠짐 — 사라지지 않고 남음 | — |
| 명부 파일 깨기 | 명부 파일을 못 읽음 (원문: 파싱 오류) — 기기 모두 남음 | 되돌리면 목록에 다시 들어옴 · 붙음 |
| 손님 알림 끊고 10분 | 알려 오던 길이 10분 넘게 끊겨 목록에서 빠짐 | 다시 알리면 목록에 다시 들어옴 · 붙음 |
