# 인라인 음성·영상

결과 파일은 프로젝트·출력 폴더에 저장한다. Claude Code와 Codex는 완성한 음성·영상 결과를 전달하기 전에 `mediaopen --block FILE`을 실행하고, 반환 블록 전체를 답변에 그대로 넣고 블록 밖에 파일 링크를 남긴다. 경로만 보고하거나 도구 출력에만 블록을 두는 것은 카드 전달이 아니다. 공유폴더 목록·의무 복사는 사용하지 않는다. 본문 카드를 누르면 앱 미리보기에서 재생하며, 결과를 출력한 것만으로 소리·별도 창·외부 앱을 열지 않는다. 같은 전달 규칙의 정본은 `crates/kasa-socket/src/inline_outputs/instructions.md`이며 실행 지침과 새 작업 브리프가 이를 함께 쓴다.

## 표시와 재생

표식은 fenced text 안의 `[[km:<16자리 소문자 hex>:00/12]]`다. 음성은 4행, 영상은 12행을 쓴다. 각 행은 같은 ID·전체 행 수와 순차 행 번호를 가진다. 이미지 `[[ki:…]]`와 독립이다. PC는 화면에 남은 행 번호로 스크롤 클리핑을 복원하며 다른 문장에 포함된 표식은 치환하지 않는다. 폰 대화는 완전한 fenced 블록만 카드로 바꾼다.

카드는 파일명·길이·영상 썸네일을 표시한다. 재생은 명시적 클릭 뒤 시작한다. PC는 AVFoundation의 음성 시계와 영상 프레임을 사용하고 wgpu 텍스처를 갱신한다. macOS가 지원하는 코덱만 재생할 수 있다. 비 macOS PC의 플레이어는 지원하지 않는다는 오류를 반환한다. iOS는 네이티브 미디어 재생을 사용한다.

재생·정지, 탐색, 음소거, 종료는 미리보기 안에서 처리한다. PC Space는 재생·정지, 좌우는 5초 이동, Esc는 닫기다. 미리보기의 키·IME·클릭을 뒤 터미널에 보내지 않는다. 드래그가 4px를 넘으면 기존 텍스트 선택으로 돌려준다. 창이 초점을 잃으면 멈추고, 닫기·방 전환·별도 터미널 창 제거는 디코더와 구간 읽기를 종료한다. 초기에는 준비·버퍼링을 표시하며 전체 파일 다운로드 진행률로 재생을 막지 않는다.

PC는 AVPlayer의 끊김 최소화 대기를 유지한다. 재생을 요청했지만 기다리는 중이면 영상은 현재 위치 앞으로 3초가 준비됐을 때, 음성은 1초 기다린 뒤 시작한다. 음성 전용 점진 전송에서는 기본 대기가 전체 파일을 받을 때까지 풀리지 않았고, 대기를 아예 끄면 원본이 잠시 멈춘 뒤 재생이 회복되지 않았다. 플레이어는 재생을 시작한 뒤에도 앞부분을 버퍼링할 수 있으며, 스트리밍은 총 전송량 제한이 아니라 전체 수신을 기다리지 않는 재생이다.

## 등록과 원격 읽기

`kasa_socket::inline_media`가 파일을 스트리밍 복사·해시 계산한 뒤 기기 전용 캐시에 등록한다. 등록 중 파일이 바뀌면 실패한다. 원본을 옮기거나 지워도 등록된 내용은 보관 기간 동안 남는다. 기본 경로는 설정 폴더의 `inline-media`, 격리 실행은 `KASATERM_INLINE_MEDIA_DIR`를 사용한다. 이 저장소는 공유폴더 화면이나 동기화 대상 목록이 아니다.

원본 파일은 SHA-256 내용 주소, 카드는 이름·종류·길이·포스터 등을 포함한 메타데이터 주소를 가진다. **카드 ID는 파일 SHA-256의 접두사가 아니다.** 등록은 로컬 CLI만 수행한다. HTTP는 경로 대신 이미 등록된 ID만 받으며 일반 원격 인증과 소유자 권한을 요구한다. 게스트는 읽을 수 없다.

| 요청 | 반환 |
|---|---|
| `GET /term/inline-media?id=ID` | 버전·ID·종류·이름·MIME·크기·파일 SHA-256·길이·해상도·포스터 유무 |
| `GET /term/inline-media/poster?id=ID` | 제한된 PNG 썸네일 |
| `GET /term/inline-media/file?id=ID&offset=N&len=N` | 원본 파일 조각 |

파일 상한은 1GiB, 서버 조각 상한은 8MiB, 스트리밍 클라이언트 요청은 512KiB다. 포스터는 12MiB·긴 변 1600px 이하다. 잘못된 ID·범위는 400, 없거나 변형된 등록물은 404로 처리한다. 응답에 기기 내부 경로를 넣지 않는다.

미러·폰은 대화의 원본 기기에 메타데이터를 요청한다. 카드 클릭 뒤 플레이어가 필요한 구간만 받아 재생하며 전체 파일을 먼저 다운로드하거나 새 `.part`·완성 파일 캐시에 모으지 않는다. 기존 일반 파일 링크의 32MiB 한도와 별개다.

PC·폰의 네이티브 플레이어는 그 기기의 `127.0.0.1` 임의 포트에 있는 수명 제한 중계에 붙는다. 중계는 예측할 수 없는 경로에서 GET·HEAD와 단일 HTTP Range를 처리하고, 메타데이터에 고정된 원본·ID·SHA·크기로 위 인증된 조각 API를 요청한다. 계정 토큰·원본 기기 주소를 재생 URL에 넣지 않는다. Range 단위는 대소문자를 구분하지 않고 HEAD의 Range는 무시한다. 200·206·416과 Content-Length·Content-Range·Accept-Ranges·MIME을 맞추며 전송 메모리는 조각 단위로 제한한다. 탐색하면 새 위치의 구간을 요청하고, 클라이언트가 버린 응답과 플레이어 종료에 따라 원격 요청도 취소한다. 여러 구간 요청이 동시에 필요한 플레이어 동작은 허용한다.

원본 쪽은 등록 SHA와 파일 내용의 검증을 파일 정체·크기·수정 시각에 묶어 재사용한다. 검증되지 않았거나 바뀐 파일은 원본 로컬 디스크에서 확인한 뒤 구간을 내보내며, 매 요청마다 파일 전체를 해시하지 않는다. 인증·게스트 거부·등록 경로 검사와 읽는 도중 변경 거부는 유지한다. 원본이 끊기면 재생 실패를 알리고 다시 시도할 수 있다. 이미 받아 둔 완성 캐시를 재사용하는 경우에도 새 미디어를 전체 받기 경로로 자동 전환하지 않는다.

## 보관

이 기기가 자기가 만든 카드의 서버다 — 다른 기기는 카드 id 로 이 기기에 와서 받는다(관문은 길만 잇고 저장하지 않는다).
그래서 캐시는 **만든 날부터 30일** 두고 걷는다(2026-10-20 결정, `inline_media::KEEP`). 앱을 켤 때 한 번, 그 뒤 여섯 시간마다 돈다
(`bootstrap::spawn_inline_prune`, `KASATERM_INLINE_KEEP_DAYS` 로 바꾼다).

- 만든 때 = 카드 기록(`meta/<id>.json`)·결과 그림(`inline-results/<id>.png`)의 수정 시각. 같은 결과물을 다시 등록하면 새로 센다.
- 원본(`blobs/`)·포스터는 여러 카드가 함께 쓴다 — 남은 카드가 하나도 안 가리키고 하루 넘게 손 안 탄 것만 지운다. 등록 중 막 공개해
  아직 기록이 없는 파일을 지우지 않으려는 것이다. `tmp/`·받다 만 `.part` 는 하루 뒤.
- 이전 PC 판이 다른 기기에서 받아 둔 사본(`inline-media/remote/`)은 받은 지 30일. 새 스트리밍은 이 사본을 만들지 않는다.
- 폰은 새 전체 사본을 만들지 않는다. 예전 완성 캐시는 재사용할 수 있고, 저장소를 열 때 남은 `.part`와 30일 동안 열지 않은 완성본을 정리한다.
- 원본 보관 기간이 지나면 그 카드는 더 이상 스트리밍할 수 없다(404). 사용자가 만든 프로젝트·출력 폴더의 원래 파일은 이 정리 대상이 아니다.

## 검증

`docs/verify-app.md`의 격리 앱 환경에 미디어 캐시 경로도 따로 지정한다. 무음 오디오·색이 바뀌는 짧은 영상·회전 영상으로 카드, 재생 진행, 일시정지, 탐색, 종료, 방향을 검사한다. 원격은 느린 원본을 둬 전체 전송 전 첫 재생·첫 프레임을 확인하고, 끝부분 탐색 때 요청 범위가 바뀌는지 기록한다. 32MiB를 넘는 파일, 후미 메타데이터·긴 GOP, 멈춘 채 탐색, 같은 크기의 원본 변조, 연결 끊김, 닫은 뒤 요청 중단, 새 전체 파일 캐시가 생기지 않는 것, 게스트·무인증 거절을 포함한다. 사용자 세션이나 운영 앱을 재시작하지 않는다.

네이티브 재생기는 `cargo run -p kasaterm --example media_player_check`의 `stream:` 검사로 느린 Range 원본·후미 메타데이터·음성·탐색·중단 후 회복을 확인한다. `stream-trace`와 `stream-buffer`는 실제 요청 구간과 받은 양을 기록한다. 폰은 `dart run tool/inline_media_fixture_server.dart 8791 150 long.mp4`와 `flutter drive`의 `--dart-define=KASA_MEDIA_LONG=true`로 느린 원본을 사용한다.
