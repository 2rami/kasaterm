# 대화 보관과 오프라인 저장

원본 기기·계정 관문·폰 저장본의 수명을 분리한다. 원본 기기가 꺼져도 계정에 동기화한 대화를 받을 수 있고,
폰 인터넷이 끊겨도 이 기기에 저장한 대화를 읽는다. 저장 화면은 기존 말풍선·코드·도구 묶음을 재사용하는
읽기 전용 화면이며 입력줄·권한 승인·실시간 작업 상태를 붙이지 않는다.

## 사용 흐름

- 대화 아래 경로 줄의 `오프라인 저장`으로 현재 대화를 저장한다. 중간 실패·취소는 이전 저장본을 보존한다.
- 허브와 계정의 `기기 연결` 대기 화면에서 `저장한 대화`를 연다. 앱 재시작 후 온라인 확인을 기다리는 동안에도
  들어갈 수 있다. 폰의 목록을 먼저 보여주고 계정 목록은 뒤에서 확인한다.
- `이 기기에 저장됨`은 폰의 파일, `계정 기록`은 원본 기기와 무관하게 관문에 남은 기록이다. 계정 기록을 누르면
  폰에 받아 읽기 전용으로 연다. 마지막 동기화 시각을 표시한다.
- `기기 대화 동기화`는 계정별 명시 선택이며 기본은 꺼짐이다. 켜면 로그인한 데스크톱이 자기 앱에 묶인 대화만
  처음부터 보내고 이후 내용을 이어 보낸다. 홈의 모든 과거 세션을 훑지 않는다. 끄면 추가 동기화가 멈추며 이미
  보관한 기록은 남는다.
- 보관함을 열거나 연결·앱 복귀 시 저장본을 갱신한다. 같은 세대는 추가 내용만 받고, 완성한 뒤 교체한다.
  원본 기기가 다시 연결됐다는 이유로 읽고 있던 저장 화면을 닫지 않는다.
- 폰 사본 삭제와 계정 기록 삭제를 구분한다. 계정 삭제는 확인 뒤 계정과 이 폰의 사본을 지우며 다른 폰의 사본은
  남을 수 있다. 삭제 표식은 자동 재업로드를 막는다. 남은 폰 사본의 `계정에 다시 동기화`는 원본의 재전송을 허용한다.

보관 대상은 **대화 텍스트·코드·도구 요약**이다. 사람 말과 답변은 화면용 길이 제한으로 자르지 않는다.
대화 화면에 표시하지 않는 세션 메타·개발자 문맥·주입 메시지·다른 하위 대화는 보관하지 않는다.
한 행이 업로드 한도를 넘으면 실패로 알린다. 도구 입력·결과는 2 KiB, 생각은 4 KiB, Edit diff는 80줄을 사용한다.
외부 이미지·영상·음성·파일은 포함하지 않는다. 사진만 보낸 턴도 첨부 표시를 남기고, 저장본은 외부 첨부나
원본 기기를 자동 요청하지 않는다.

## 원본 기기와 커서

`Backend::transcript_archive`는 화면의 꼬리 읽기와 별개이며 구판 백엔드는 거절한다.
`chat_view/history.rs::read_archive`는 처음부터 완전한 JSONL 행을 읽고 통상 512 KiB씩 반환한다.
원본 스캔은 통상 8 MiB, 원본 한 행은 64 MiB, 정리된 한 행은 4 MiB까지다. 쓰다 만 마지막 행은 다음에 읽는다.
`offset`은 정리한 문자열의 길이가 아니라 원본 파일의 개행 다음 위치다.

`GET /conversation-archive?surface=&offset=&source=`는 `archive_version:1`, `raw`, `offset`, `reset`, `source`,
`address`, `machine_name`을 반환한다. 읽기 전후 신원을 대조하고, 폰도 기기·surface key·기록 파일이 바뀌면
저장을 취소한다. 구판의 일반 꼬리 API를 저장 성공으로 대체하지 않는다.

GUI가 등록한 `conversation_archive/sync.rs` 워커가 계정 선택을 확인한 뒤 이 경로를 사용한다. 검증 앱은 등록하지
않는다. 자격 세대를 읽기·전송 전후에 대조하고, 원격 거울을 자기 기록으로 올리지 않는다. 기록 ID는 안정된
기기 ID와 원본 파일 이름의 SHA-256이며 재사용되는 pane 번호가 아니다. 처음 따라잡을 때는 1초, 완료 후에는
15초 간격이다. 연결이 끊기기 전에 아직 동기화되지 않은 글까지 복구한다고 보장하지 않는다.

## 계정 관문

계정과 업로더 기기는 Bearer 자격에서 정하며 요청 본문으로 고르지 않는다. 업로드는 desktop 자격만 가능하다.
폰·데스크톱은 자기 계정만 읽고 관리한다. 느린 업로드 중 폐기된 자격은 커밋하지 않으며 저장소가 없으면 503이다.

| 경로 | 의미 |
|---|---|
| `GET /relay/conversations` | 동기화 선택과 기록 목록 |
| `PUT /relay/conversations/settings` | `enabled` 변경 |
| `POST /relay/conversations` | 원본 커서·revision을 대조한 추가/리셋 |
| `GET /relay/conversations/{id}?generation=&offset=&end=` | 선택한 세대와 끝 위치까지 UTF-8 조각 읽기 |
| `DELETE /relay/conversations/{id}` | 데이터 삭제와 재업로드 방지 표식 |
| `POST /relay/conversations/{id}/restore` | 원본의 재동기화 허용 |

원본 `cursor`와 관문의 `bytes`는 다르다. 내려받기는 관문 바이트 위치를 사용하고 목록에서 잡은 `generation`과
`end`를 고정한다. 추가만 된 기록은 기존 접두를 읽을 수 있고 리셋한 세대는 409로 거절한다. revision CAS는
응답을 잃은 업로드의 중복을 막는다.

디스크는 `--state` 옆 `conversation-archives/<account>/`의 0700/0600 파일이다. 본문 쓰기·fsync 후 manifest를
원자 교체하며 커밋한 길이까지만 공개한다. 미커밋 꼬리·고아 세대를 복구/정리하고 손상된 manifest를 빈 기록으로
덮지 않는다. 단일 저장 워커와 제한된 큐를 쓰며 업로드는 동시에 4개다. 한 기록은 32 MiB, 계정 본문은 512 MiB,
목록은 삭제 표식을 포함해 2048개까지다. 폰에 보내는 조각은 최대 256 KiB이며 UTF-8 문자 경계를 지킨다.

## 폰 파일과 계정 전환

OS가 비우는 Cache 대신 Application Support의 `offline-conversations/<scope-hash>/`를 쓴다. 계정 scope는
관문 origin과 계정, 기존 주소는 그 주소이며 경로에는 해시만 쓴다. 토큰은 파일명·manifest에 넣지 않는다.
본문 해시·길이를 확인한 뒤 임시 파일을 완성본으로 승격한다. 취소·계정 전환·삭제 후 늦게 끝난 받기가 기록을
되살리지 못하게 한다. 로그아웃하면 읽는 화면과 API가 잠기며 다른 계정의 캐시를 가져오지 않는다.
폰 한 기록은 32 MiB, 합계는 256 MiB까지다. 사용자가 저장한 정상 파일을 시간만 지났다고 지우지 않는다.

## 검증과 배포

Rust 저장소·관문 시험은 계정 분리, 자격 폐기, desktop 전용 업로드, CAS, 재시작, UTF-8 경계, 커서/길이 차이,
세대 변경, 삭제 후 재업로드 방지와 처음부터 읽기를 검사한다. Flutter `archive_*_test.dart`는 파일 재개방,
끊김·취소·계정 교체, 삭제와 받기의 경합, 읽기 전용 화면, 320/390/430px 목록과 연결 대기 중 진입을 검사한다.

`integration_test/offline_archive_test.dart`는 전용 iOS 시뮬레이터에서 두 번 실행한다. 첫 실행은 루프백 가짜
계정에서 UI로 다운로드하고 실제 Keychain과 Application Support에 남긴다. 앱을 종료한 뒤 **재설치 없이**
같은 앱을 다시 실행하면 서버 없이 연결 대기 화면에서 저장본을 열고, 같은 주소의 서버를 복구해 추가 바이트만
받는지 확인한다. 푸시 등록만 제외하며 결과는 앱 지원 폴더의 `offline-archive-native-test.json`에 남긴다.
`flutter drive --keep-app-running --driver test_driver/integration_test.dart --target integration_test/offline_archive_test.dart`
뒤 전용 기기의 앱을 종료·재실행하고 `--use-existing-app=<VM service URL>`로 두 번째 driver를 붙인다.
`KASA_SHOT_DIR`에 다운로드·콜드 재시작·재연결의 실제 화면 세 장을 남긴다. 사용자 폰·계정·세션은 쓰지 않는다.

관문 교체, 데스크톱 preview, 모바일 Ad Hoc 설치판을 각각 게시한다. 기존 관문 상태 형식을 바꾸지 않으며
이전 바이너리로 되돌려도 새 보관 폴더는 보존한다. `gateway.sh`의 상태 복사 목록에 새 폴더를 포함한다.
