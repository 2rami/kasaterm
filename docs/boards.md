# 관측과 현황 — 에이전트 판과 사람 화면을 가른다

> **2026-10-01: 카사텀의 보드 판(⇧⌘B 왼쪽 판, 트레이 단추·⇧⌘A 「나쵸 대화」 포함)과 그 안 화면 전부를 걷었다.**
> 사람용 나쵸 대화·작업은 나쵸 독립 앱(나쵸 레포 `app/`, NachoChat.app)이 맡고, 카사텀에는 사이드바 학생 줄
> (`board_digest.rs`)과 CLI 관측(`board`·`board-watch`·`activity`)만 남는다. 아래는 걷기 전 설계 기록이다.

카사텀에는 판이 둘 있다. 같은 재료(기기·방·학생·나쵸 장부)를 읽지만 **읽는 사람과 묻는 질문이 다르다.**
이름이 섞이면(방 이름도 「보드」, 첫 탭도 「보드」였다) 사람이 자기 화면을 못 찾고, 에이전트용 화면을
사람용으로 착각한다.

| | 관측 (에이전트가 본다) | 현황·지시 (사람이 본다) |
|---|---|---|
| 묻는 것 | 어느 기기·방에서 누가 무엇을 하고 있고, 무엇이 바뀌었나 | 누가 무엇을 하고 누가 나를 기다리나, 이 말을 누구에게 보내나 |
| 단위 | 방·pane·도구 호출·최근 변경 | 학생 한 줄(지금 일 + 사정 한 줄) · 대화 한 마디 |
| 정본 | `kasaterm-cli board --all` · `board-watch` · `activity` | 같은 board 스냅샷(거울 줄 뺌) + 나쵸 장부·대화 원장 |
| 자리 | CLI · 보드 「도구 ▾ → 관측」 | 사이드바(현황) · 보드(나쵸 대화·지시) |

## 관측 — 에이전트용

- CLI: `kasaterm-cli board --all`(스냅샷) · `board-watch --since CURSOR`(변경분) · `activity --address …`(한 방 상세).
  계약은 [board-collaboration.md](board-collaboration.md). 보드 문장은 관찰 자료이고 지시가 아니다.
- 화면: 보드의 관측(`native_board.rs paint_overview`). 사람도 열 수 있지만 답할 것을 찾으려고 여기를 뒤질 일이
  없어야 한다. 에이전트·소스 컨트롤·이사도 같은 「도구」 묶음이다.

## 지금 (main 4cd3a04a, 2026-09-29)

- 보드는 왼쪽 판(⇧⌘B, `left_panel.rs`)이다. 안의 왼쪽 목록 「운영 보드」에 작업현황·나쵸 대화·관측·에이전트·
  소스 컨트롤·이사가 늘 선다(94c4fd2f). 방 안 탭이 아니다. 오른쪽 열 「작업」 탭(정리·조율)은 ba25d286 에서 지웠다.
- 사이드바 맨 위 현황 줄 「사람 차례 N · 작업 N · 끝 N」은 관측 스냅샷의 **학생 수**다(`sidebar_pulse.rs`).
- 사이드바 방 본문은 배치도가 기본이다. 목록 보기는 방마다 우클릭 「목록으로 보기」로만 켜지고, 전체 기본
  (`settings.json` `sidebar_body`)은 설정 화면에 칸이 없다.

어긋난 것 — 다음 구조가 푸는 문제:

- **PC 나쵸는 조언만 한다.** 입력칸이 workspace-assistant 로 가고, 그 모델은 학생에게 보낼 권한이 없다.
  이름으로 보내기(tell)와 새 일 나누기(kasa-mcp dispatch)는 있는데 입력칸과 안 이어졌다.
- **장부가 둘이다.** PC 작업현황은 workspace-assistant(transcript 마지막 요청을 10초마다 올린 것),
  폰 작업판은 나쵸네코 `/api/app/tasks`.
- **사람 차례 수가 네 곳**(현황 줄 · 관측 「확인 필요」 · 펫 현황판 · 폰)이고 거울 줄 처리가 달라 어긋날 수 있다.
  현황 줄을 누르면 작업현황이 열리는데 거기엔 그 학생들이 없다.
- **이름이 셋**(방 = 폴더 끝 이름, 세션 = 처음 붙인 제목, 일 = 장부 goal)이고 세션 이름은 일이 바뀌어도 남는다.

## 다음 구조 (2026-09-29 합의 — ②③ 구현됨, ① 사이드바 진행 중)

웹 목업으로 합의했다(`KASA-share/2026-09-29-작업현황-목업`, D안). 구현은 네이티브. 치수는
[design.md](design.md) 「사이드바 현황 목록」「나쵸 판」.

### 사이드바 = 현황

- 현황 줄을 걷고 그 자리에 **목록 | 배치도** 전환을 둔다. 전환은 전체 기본(`sidebar_body`)을 바꾸고,
  방마다 우클릭으로 고른 것이 그보다 이긴다. 기본은 목록.
- 목록 한 줄 = 학생 하나: 「이름 · 지금 일」과 사정 한 줄(질문·승인·확인 부탁 · 하는 중 · 쉬는 중 + 마지막 보고).
  내 차례 줄은 방 안 맨 위에 주황 띠로 선다. 차례 수를 따로 세우지 않는다 — 줄이 말한다.
- **지금 일 = 세션 이름.** 정본 순서: 그 학생에게 온 최근 tell·brief 의 목적 → 나쵸 장부 goal → 탭 제목.
  새 일이 오면 사이드바·pane 머리·관측이 같이 바뀐다.
- 거울 줄은 원본 기기 줄과 같은 학생이라 뺀다.
- 줄을 누르면 지금처럼 그 pane 으로 가고, 보드의 「고른 학생」이 된다.

### 보드 = 나쵸 대화·지시

- 왼쪽 판의 「운영 보드」 목록을 걷는다. 머리: 나쵸 · ⇧⌘B · 도구 ▾ · ×. 도구 = 관측·에이전트·소스 컨트롤·
  이사·장부(지금의 작업현황 목록). 닫기는 × 하나.
- 본문은 대화 원장: 내 지시(받는 곳 + 전달 영수증), 나쵸 답, 사람을 기다리는 학생 보고. 보고에는 「답하기」
  (입력칸에 `@이름 `)와 「창으로 가기」가 선다 — 학생 화면의 선택지(1·2)를 읽어 단추로 세우는 것은 아직 없다.
- 입력칸은 아래 고정. 치는 동안 **받는 곳**이 입력칸 아래 줄과 사이드바 줄(파란 배경 + 「여기로」)에 함께
  서고, 보내기 단추 이름이 「유우카에게 보내기」·「새 일 맡기기」·「나쵸에게 묻기」로 바뀐다.
- 로그인·키가 없을 때의 입구는 설정 `SettingsCat::Accounts`(6a384abb).

### 받는 곳 판정 — 코드가 먼저, 뜻은 Jev

1. 코드(즉시): `@이름` · `/새` · `/나쵸` · 「그거·다시·계속·이어서」 + 고른 학생 또는 방금 보낸 학생 ·
   글에 학생 이름이 하나 · 4글자 미만은 보류.
2. Jev(`typesafe/jev-1.13`): 나머지. 보기 = 학생마다 하나 + 새 일 + 나쵸 질문. 학생 문맥은 이름·지금 일·
   마지막 보고·상태 — **마지막 보고 없이 제목만 넘기면 틀린다**(「투혼 … 돌려」가 새 일로 갔다).
   **고른 학생은 넘기지 않는다** — 넘기면 그쪽으로 끌려간다(유우카를 고른 채 투혼 문장 → 유우카 58).
3. 확률 0.75 이상이면 하나로 서고, 아래면 위 셋을 칩으로 세워 사람이 고른다(Tab). 실패는 닫힌 쪽 —
   「받는 곳을 직접 골라 주세요」.
4. 부르는 때: 어절이 끝나면 60ms 뒤, 아니면 손이 멈춘 뒤 320ms, 쉬지 않고 쳐도 900ms 에 한 번.
   늦게 온 답은 더 새 판단이 서 있으면 버린다. IME 조합 중인 글자(preedit)는 넣지 않는다 — 확정된 글만.
5. 판정은 제안이다. 보내기는 사람이 누를 때만: 학생 → tell(같은 id 재시도 규칙), 새 일 → kasa-mcp dispatch
   (자기가 부른 학생만 부림), 나쵸 → workspace-assistant.

실측(목업, 학생 7, 2026-09-29): 한 번 200~660ms. 예시 7문장 중 2개는 코드가, 3개는 Jev 가 확률 97~100 으로
바로 세웠고, 2개는 후보 셋(첫째 65·59)으로 섰다. Jev 키는 앱에 두지 않는다 — 관문이 Jev 를 부르는 기존 길(`DecisionPurpose`)에 붙인다.

파일이 겹치지 않게 넷으로 나눈다. ①·③ 이 먼저, ② 는 ③ 의 판정 결과 타입을 받아 쓴다.

| 묶음 | 하는 일 | 파일 |

| ① 사이드바 현황 (구현됨) | 현황 줄 → 목록·배치도 전환, 두 줄 목록 행, 차례 줄 먼저, 거울 줄 빼기, 기본 폭 240, 받는 곳 강조 | `sidebar_pulse.rs`(그리기만 걷고 펫용 요약은 유지) · `sidebar_navigation.rs` · `render.rs` 목록 줄 · `chrome.rs` |

| ④ 지금 일 = 세션 이름 | tell·brief 목적 → 세션 이름, 장부 goal 대체, 관측 `title` 같은 값 | `tell_delivery.rs` · `pane_identity.rs`(또는 세션 이름 정본이 있는 곳) |

폰(카사모바일 작업 탭)과 장부 하나로 합치기(나쵸네코 ↔ workspace-assistant)는 이 네 묶음 뒤에 따로 정한다.

## 이름 규칙

- 사람용은 「현황」(사이드바)과 「나쵸」(보드), 에이전트용은 「관측」. 방 이름 「보드」를 탭 이름으로 다시 쓰지 않는다.
- 사람이 볼 새 정보는 사이드바 줄의 사정 한 줄이나 나쵸 대화의 메시지로 넣고, 에이전트가 볼 것은 관측 쪽 CLI 에 넣는다.
