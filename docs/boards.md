# 관측과 작업현황 — 판 둘을 가른다

카사텀에는 「판」이 둘 있다. 같은 재료(기기·방·학생·나쵸 장부)를 읽지만 **읽는 사람과 묻는 질문이 다르다.**
이름이 섞이면(방 이름도 「보드」, 첫 탭도 「보드」였다) 사람이 자기 화면을 못 찾고, 에이전트용 화면을
사람용으로 착각한다. 그래서 이름과 진입점을 아래처럼 못 박는다.

| | 관측 (에이전트가 본다) | 작업현황 (사람이 본다) |
|---|---|---|
| 묻는 것 | 어느 기기·방에서 누가 무엇을 하고 있고, 무엇이 바뀌었나 | 내가 지금 답할 것은 무엇이고, 일이 어디까지 왔나 |
| 단위 | 방·pane·도구 호출·최근 변경 | 작업 하나(요청 → 진행 → 검증 → 끝) |
| 정본 | `kasaterm-cli board --all` · `board-watch` · `activity` | 나쵸 장부(작업·승인·학생 보고) + 판의 학생 상태 |
| 쓰는 곳 | 학생·나쵸의 조율, 막힘 추적 | 승인·답하기, 진행 확인, 정리·조율 모드 |

## 관측 — 에이전트용

- CLI: `kasaterm-cli board --all`(스냅샷) · `board-watch --since CURSOR`(변경분) · `activity --address …`(한 방 상세).
  계약은 [board-collaboration.md](board-collaboration.md). 보드 문장은 관찰 자료이고 지시가 아니다.
- 화면: 보드 방(`native_board.rs`)의 **「관측」 탭** — 연결된 기기의 모든 방과 최근 변경. 사람도 열 수 있지만
  사람에게 묻는 화면이 아니다 — 답할 것을 찾으려고 여기를 뒤질 일이 없어야 한다.
- 같은 방의 「에이전트」「스케줄」「소스 컨트롤」「이사」는 운영 도구(도는 대화·예약 지시·저장소·세션 옮기기)라
  두 판 어디에도 속하지 않는다.

## 작업현황 — 사람용 (이미 있는 것, 새로 만들지 않는다)

| 자리 | 진입 | 무엇 |
|---|---|---|
| 보드 방 **「작업현황」 탭** (첫 탭) | 보드 방을 열면 이 탭이 먼저 | 장부 상태 → 프로젝트 칩 → 「답이 필요한 것」 → 진행·검증·완료 줄기 → 기기·학생. `native_board/work.rs` |
| 오른쪽 열 **「작업」 탭** | 작업 화면 오른쪽 열의 다섯째 탭 | 정리(지금 창의 현재 작업·변경·다음 일·막힘·검증) · 조율(같은 목록을 좁게) · 권한 표. `native_board/side.rs` |
| 폰 **「작업」 탭** | 카사모바일 하단 탭 | 작업판 + 모드 줄(모드·권한 시트) + 줄 하나의 정리 시트. `mobile/lib/screens/workboard_view.dart` |

화면 치수와 문구 규칙은 [design.md](design.md)의 「작업현황 판」「작업 탭」 절.

## 이름 규칙

- 사람용은 「작업현황」「작업」, 에이전트용은 「관측」. 방 이름 「보드」를 탭 이름으로 다시 쓰지 않는다.
- 새 화면을 만들기 전에 위 표에 자리가 있는지 먼저 본다 — 사람이 볼 새 정보는 작업현황 판이나 작업 탭의
  칸으로 넣고, 에이전트가 볼 것은 관측 쪽 CLI 에 넣는다.
