# 계정 공통 설정과 모바일 로그인

데스크톱과 모바일은 같은 관문 계정으로 로그인한다. 비밀번호는 보관하지 않고 기기별 토큰을 사용한다. 서버는 토큰에서 계정을 결정하며 요청 본문의 계정 이름이나 파일 경로를 믿지 않는다.

## 동기화 범위

허용 목록의 정본은 `crates/kasa-mcp/src/account_sync/schema.rs`다. 서버와 클라이언트가 같은 검증을 적용한다.

- 공통 설정: 언어, 색·커스텀 팔레트, UI 글꼴 이름·크기, 커서 모양, 캐릭터 외형/페르소나 켜기, 상태줄과 패널의 표시 선호. 모바일 밝기 선택은 `mobile_theme_mode`(`system`·`light`·`dark`)로 같은 계정에 저장한다.
- 기기 연결: 이름, 기계 id, SSH의 공개 host/user/port, 기본 아이콘·표시 색.
- 제외: SSH 개인키, 비밀번호, API 키, 기기 토큰, 셸·명령·환경변수, ProxyCommand, 파일 내용, 로컬 경로·세션·터널 포트, 권한 위임, 업데이트 채널과 자동 설치 선택.

나중에 추가하는 키는 `OPT_IN_KEYS`(현재 `weather`)에 둔다. 서버와 클라이언트 검증은 모르는 키가 하나라도 있으면 스냅숏 전체를 거부하므로, 관문은 `x-kasa-sync-keys` 머리글로 그 키를 이름 댄 요청에만 보여 주고 나머지 기기(옛 데스크톱·폰)에는 뺀다. 클라이언트는 받은 스냅숏에서 모르는 키를 먼저 버린다. 관문이 그 키보다 오래되어 패치를 400으로 거부하면 클라이언트는 그 키만 빼고 다시 보내고, 10분 동안 그 키를 로컬에만 둔다 — 관문을 다시 배포하면 동기화가 이어진다.

SSH 별칭은 실행 없이 단순 `Host`·`HostName`·`User`·`Port`를 해석할 수 있을 때만 공개 연결 정보로 바꾼다. `Include`·`Match`·프록시/실행 명령이 필요하면 자동으로 해석하거나 실행하지 않고 로컬 연결 설정 필요 상태로 둔다. 인증용 개인키는 받는 기기에 별도로 있어야 한다. 커스텀 SVG 파일은 이 첫 동기화 범위에 포함하지 않는다.

## 저장·충돌·계정 경계

- 서버: 상태 파일 옆 `account-sync/<계정>.json`, 폴더 0700·파일 0600, 원자적 교체. 손상 파일을 빈 값으로 덮어쓰지 않는다.
- 클라이언트: 계정별 마지막 원격 상태와 관측한 로컬 상태를 기록한다. 전체 설정 파일을 교체하지 않고 허용 항목의 변경분만 반영한다.
- 빈 계정의 최초 seed는 한 기기가 먼저 성공하면 끝이다. 다른 기기의 동시 초기 업로드는 기존 원격 값을 다시 덮지 않는다.
- 이후 변경은 revision 비교 후 적용한다. 충돌하면 최신 원격 값에 로컬에서 실제 바꾼 필드만 다시 합친다. 이미 같은 필드를 더 늦게 로컬에서 수정했다면 늦게 도착한 응답으로 덮지 않는다.
- 계정 전환 때 이전 계정의 설정을 새 빈 계정에 초기 업로드하지 않는다. 토큰·기기·인증 세대가 바뀐 응답은 적용하지 않는다.
- 삭제는 명시적 null 패치다. 기기별 키·경로 등을 가진 로컬 연결 항목을 원격 삭제만으로 없애지 않는다.
- GUI가 설정 적용을 소유한다. 입력 편집 중에는 적용을 미루고 다음 동기화에서 다시 확인한다. 별도 headless sidecar가 같은 설정 파일을 또 쓰지 않는다.

## API

`GET /relay/account-sync`는 `Authorization: Bearer <device-token>`으로 인증하며 다음 상태를 돌려준다.

```json
{"revision":1,"settings":{"theme":"graphite"},"machines":{"mini":{"label":"Mini","host":"mini.example","user":"user","port":22}}}
```

`PATCH /relay/account-sync`:

```json
{"expected_revision":1,"settings":{"font_size":14},"machines":{}}
```

충돌은 `409 {"error":"revision_conflict","current":{...}}`, 잘못된/금지된 값은 400, 인증 실패는 401이다. 본문은 128 KiB 이하이며 비밀 값이나 모르는 최상위 필드를 거부한다. 폐기·비활성 계정은 데스크톱·폰 모두 거부한다.

## 모바일 관문

- 로그인: `POST /relay/login {account,password,kind:"phone",label}`.
- 확인: `GET /relay/whoami`, `GET /relay/devices`.
- 앱 API 루트: `/relay/account/`. HTTP는 Bearer, WebSocket은 `kasa-relay-account`와 `kasa-auth.<device-token>` subprotocol을 사용한다. 토큰을 URL·쿼리·화면·로그에 넣지 않는다.
- 새 데스크톱 업링크는 공개가 켜진 자기 owner 주소를 `owner_slug`로 알린다. 관문은 같은 계정의 기기만 골라 내부 owner 경로로 연결하고 해당 주소나 인증 헤더를 폰/다른 기기로 노출하지 않는다.
- 계정에 없는 기계 id(`m/~<id>/`)는 로컬 프록시로 대신 보내지 않고 `503 account_device_unavailable`이다. 연결 가능한 자기 기기가 없을 때도 같다. 계정 로그인 성공과 기기 온라인 상태는 별개다.
- 이름 route(`m/<이름>/`)가 계정 기기와 맞지 않으면 계정 허브의 로컬 프록시로 넘긴다. 허브 명부(ssh·announce)의 기계는 계정에 로그인하지 않아도 `/machines`에 이름 route로 실리기 때문이다. 허브는 자기 명부만 찾으므로 다른 계정 기계에는 닿지 않는다(없으면 404). 나쵸 앱 경로는 여전히 503이다.
- 로그아웃: `POST /relay/logout`. 기기 토큰을 폐기하면 해당 계정 WebSocket도 닫힌다. 모바일은 서버가 끊겨 있어도 로컬 자격·연결·캐시를 먼저 정리한다.
- 기존 `/u/<slug>/` 직접 연결은 별도 보조 입구로 유지한다.

## 모바일 알림과 검증 경계

계정 연결에서는 APNs 등록을 중단한다. 기존 직접 연결의 알림 등록은 별도 클라이언트로 해제하며, 실패하면 재시도와 실패 상태를 남긴다. 오프라인·재시작을 거친 옛 등록의 서버 측 폐기까지 보장하려면 기기 토큰에 결속된 별도 알림 설계가 필요하다. 계정 로그인 지원을 계정 알림 지원으로 안내하지 않는다.

Codex 화면 검사는 합성 API·대화·터미널 자료로 진행·완료·승인, 밝고 어두운 테마, 320·390·430px 폭을 확인한다. 화면 안에 합성 QA임을 표시하며 실제 계정 응답이나 물리 iPhone의 한글 IME 검사로 취급하지 않는다. 자료 계약은 `mobile/test/fixtures/README.md`에 있다.
