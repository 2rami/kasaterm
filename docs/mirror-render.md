# 미러는 원본을 건드리지 않고 다시 그린다

정본 규칙 한 곳이다. 「원본 크기는 쓰는 쪽이 쥔다」(`webterm-handoff.md`)는 이 문서가 바꾼다.

화면에서 기기 이름·동일 기기를 판정할 때는 폴러가 갱신한 `machines::display_identity()`를 쓴다.
등록 파일을 매 프레임 다시 읽으면 거울 방 수만큼 디스크 읽기·JSON 해석이 누적돼 입력을 막는다.
등록 변경·권한 판정은 기존의 실등록 조회를 유지하며, 방 번호는 프레임마다 한 번에 계산한다.

## 원칙

- **원본 칸 크기는 원본 기기만 정한다.** 다른 기기(PC 거울·폰·웹)는 보기든 입력이든 원본 PTY 크기를 바꾸지 않는다.
- 미러는 원본이 내는 **데이터**를 받아 **제 폭**으로 다시 그린다. 원본 격자를 그대로 비추는 것은 마지막 수단이다.
- PC 거울과 폰은 같은 데이터·같은 규칙을 쓴다. 다른 것은 그리는 쪽뿐이다.
- **PC 거울은 처음엔 터미널로 뜬다**(원본 격자를 제 폭으로 다시 접은 것). 아래 대화형·명령 묶음은 ⋮ 「대화로 보기」·
  「명령으로 보기」로 칸마다 켠다(2026-10-13 「pc세션 미러링은 터미널을 기본으로」). 폰은 그대로 「대화」가 첫 얼굴이다.

## 세션 복원과 기기 화면

앱의 세션 복원은 **이 기기에서 실행하던 칸만** 대상으로 한다. 다른 기기 보기 창·미러 탭은
저장·복원 대상에서 제외하고, 기기 절의 실시간 목록에서 다시 연결한다. 예전 저장본도 같은 규칙으로
읽으며, 미러 칸 안의 로컬 탭은 따로 보존한다. 원격 칸을 로컬 셸로 대체하거나 다른 기기 에이전트를
재실행하지 않는다. 이 기기의 상주 PTY 데몬으로 승격한 세션은 원격 기기 미러가 아니므로 보존한다.

## 칸 닫기

칸·탭의 닫기는 원본과 거울을 나누지 않는다. 거울에서 닫아도 원본에 같은 닫기를 보내며,
원본의 종료 알림을 받은 다른 보기에서도 칸을 걷는다. 로컬 보기만 남기거나 원본만 남기는 선택지는 없다.
미저장 문서·실행 중인 작업의 기존 확인은 유지한다. 원격 요청은 UI 스레드 밖에서 보내고, 실패하면
거울을 남긴 채 까닭과 다시 시도를 표시한다. 앱 자체 종료·패널 숨기기는 칸 닫기가 아니며 원격 세션을 닫지 않는다.

## 승인은 TUI 와 같은 꼴로

PC 대화 보기는 원본의 승인·질문 창을 바닥에 그대로 옮겨 붙여 터미널과 똑같이 키로 답한다. 폰 대화형 미러에서 권한 요청은
TUI 의 승인 창과 같은 정보·같은 선택지로 그린다.

- 보여 줄 것: 도구 이름, 입력 원문(명령 전체·파일 경로·바뀔 내용 요약), TUI 가 내미는 선택지 그대로(예·이번 세션은 묻지 않기·아니오+까닭).
- 데이터: 연결 mod 의 `tool.check`(승인 대기·도구·입력) — 원격 승인 계약(`docs/claude-mod-bridge.md`)과 같은 요청 id 를 쓴다. 코덱스는 rollout 의 승인 요청 줄.
- 답: 고른 선택지를 원본에 그대로 보낸다(Claude 는 mod 의 결정, 코덱스는 승인 창 키). 한 곳에서 답하면 나머지 미러의 카드는 닫힌다.
- 같은 꼴로 그릴 것: 질문 창(선택지 묻기), 계획 승인, 작업 끝 요약.

## 지금 규칙에서 바뀌는 것

- 데스크톱 거울의 「초점·입력하면 크기를 빌린다」(`mirror_follow.rs` 의 acquire)와 폰 터미널 보기의 「칠 때만 쥔다」는 걷는다. 대화형·셸 묶음 보기에서는 쥘 일이 없다.
- 전체 화면 프로그램 칸을 미러에서 조작하는 길은 두지 않는다 — 휠만 예외다. 마우스를 받는 전체 화면 앱(claude
  `tui: "fullscreen"`·htop)은 지난 줄이 앱 안에만 있어 거울 파서엔 굴릴 줄이 0줄이다. 그때 휠은 SGR 로 원본 앱에 넘기고,
  원본 화면도 함께 굴러간다(`input.rs app_owns_wheel`, 떼어 낸 창 `auxterm.rs` 도 같다). 그 밖의 칸은 거울 안에서만 굴린다.
  앱이 마우스를 켜는 바이트는 거울이 붙기 전에 지나가므로, 붙을 때 받는 스냅샷이 앱의 입력 모드(마우스·SGR·커서 키·
  괄호 붙여넣기)를 다시 켠다(`kasa-screen ScreenUpdate::to_ansi`). 빠지면 늦게 붙은 거울은 마우스를 몰라 휠이 거울 안에서만
  돌고 원본은 안 굴렀다(2026-10-13). 줄 글 뒤 빈칸의 휠·클릭은 같은 원본 줄 칸으로 보낸다(`PaneViewShift::term_pos`).
- 셸 칸이 잠깐 전체 화면 프로그램(vim·less)에 들어간 동안은 줄여 보기지만 키는 원본으로 간다 — 거울에서 연 것을
  거울에서 닫을 수 있어야 한다. 크기는 그때도 안 빌린다.

## 셸 묶음 데이터 — `GET /term/blocks`

- `?pane=%N&since=<도장>&wait=<ms>&have=<id>` → `{ok, since, integration, alt, cols, rows, oldest, newest, blocks}`.
  `since` 가 지금 도장과 같으면 바뀔 때까지(최대 25초) 기다렸다 답한다(긴 폴링). 도장은 블록 바뀜 번호와 대체 화면 여부.
- `integration` 은 셸 통합 표지(OSC 133)를 한 번이라도 봤나, `alt` 는 지금 대체 화면인가 — 둘 중 하나라도 아니면 줄여 보기.
- 블록: `{id, cmd, start_ms, running, exit?, ms?, tui?, dropped?, count, lines, gap_at?, gap?}`. `have` 보다 큰 블록과 도는 블록만
  싣는다. `newest` 가 보는 쪽이 가진 것보다 작으면 원본 셸이 새로 떠 번호가 처음부터다.
- `lines` 는 셸이 낸 `\n` 에서만 끊은 논리 줄 — 접기는 보는 쪽이 제 폭으로 한다. 줄은 조각 `{t, f?, b?, s?}`(색 0~255 는 팔레트,
  `0x1000000|rgb` 는 트루컬러, `s` 는 격자 전송과 같은 꾸밈 비트). `\r` 덮어쓰기·커서 위로·줄 지우기를 따라 진행 막대는 마지막
  모습만 남고, 대체 화면 구간은 버린다(`kasa_pty::block_lines`). 160줄 넘으면 가운데를 비우고 `block=<id>` 로 통째로 받는다.
- 원본 저장소는 칸마다 50블록·블록마다 256KB, 넘치면 결과의 **앞**을 버린다(끝의 오류·시험 결과가 중요하다).
- 셸 통합은 카사텀이 띄운 zsh 만 낸다. bash·ssh 너머·셰임을 끈 칸은 줄여 보기다.
- 폴더 고리: zsh 셰임의 precmd 가 OSC 9;9 로 지금 폴더를 알리고, 블록은 C 순간의 그 값을 `cwd` 로 단다. 원본은 결과 줄의
  낱말(빈칸 든 이름은 줄 통째)을 그 폴더 기준으로 풀어 **실제로 있는 폴더만** `links: [[줄, 글자 시작, 글자 수, 절대 경로]]` 로
  싣는다(블록당 stat 400·고리 200 상한). 보는 쪽(PC 카드·폰)은 그 자리를 강조색 밑줄로 그리고, 누르면 쓰던 줄을 비우고
  `cd -- '<경로>'` 를 친다. 명령이 도는 동안은 안 보낸다 — 그 글이 도는 프로그램의 입력이 된다. 셰임 전에 뜬 셸은 폴더를 몰라
  절대 경로·`~` 만 고리가 된다.
- 창 밖 셸(`web-…`, 데스크톱 창에 안 앉은 셸)도 같은 묶음으로 본다. 폰은 허브의 「창 밖 셸」 상자에서 열고(첫 방에 섞지
  않는다), PC 는 사이드바 「창 밖 셸」 줄을 누르면 포커스된 칸의 보기 탭으로 붙는다. 이 기기 것은 명부에 제 자신이 없어
  제 HTTP 창구(`KASASPACE_MCP_PORT`)로 붙고, 하네스 판정도 명부 캐시 대신 세션을 직접 본다(`remote::cached_agent_running`).
- PC 셸 칸은 이 기기 칸이든 거울이든 ⋮ 「명령으로 보기」로 켠다(칸마다, 기본은 터미널). 같은 카드·같은 창구를 쓰고, 학생(claude·codex)이
  뜨면 터미널로 돌아갔다가 나가면 다시 카드다. 기본으로 켜지 않는 까닭: 카드 보기의 입력 줄은 커서 줄 하나뿐이라 zsh 완성
  목록처럼 프롬프트 아래 찍히는 것이 안 보인다.

## 구현 자리 (대화형)

- 진입: PC `mirror_render.rs` 의 `mirror_kind` — 거울이고 하네스(claude·codex)가 돌면 `Chat`, ⋮ 「대화로 보기」로 켤 때만
  대화(`chat_view`)로 연다(저절로 열던 것은 10-13 에 걷었다). 폰은 「대화」가 처음 얼굴이다(`PaneViewPrefs` 의 `pane.view.v2`). 하네스는 원본
  `/term/panes` 의 `harness` — 기록이 아직 없는 막 띄운 학생도 셸 밑 프로세스로 채운다.
- 크기: `mirror_kind` 가 `Chat` 이면 사람 손이 닿아도 `touch_source` 를 안 부른다(`mirror_follow.rs`, 「터미널로 보기」로 돌려도
  같다 — 줄여 보기). 폰 대화 보기는 쥐지 않는다.
- 풀스크린(alt-screen) Claude·코덱스 칸을 터미널로 볼 때, 거울 칸 크기로 다시 접은 화면이 칸을 다 못 채우면 다시 접지 않고
  원본 격자 그대로 칸에 맞춘다(`layout.rs mirror_source_fit`, 남는 자리는 칸 여백). 풀스크린 앱은 지난 줄을 앱 안에만
  두어, 원본보다 넓고 높은 칸에 다시 접으면 위를 채울 줄이 없다(2026-10-13 나쵸네코 60×44 원본을 118열 칸에서 보니 위 60% 가
  비었다). 원본보다 큰 칸은 키우고, 원본보다 좁은 칸(Info 를 열어 좁아진 칸)은 줄여서라도 원본을 다 보인다(10-13 지시
  「좁은 칸은 줄여서라도 원본 전체 보이게」). 원본보다 넓고 낮은 칸은 다시 접는 편이 글자가 커서 그대로 다시 접는다.
  판정은 칸·원본 크기·탭이 바뀔 때만 다시 잰다 — 글마다 재면 글자 크기가 오락가락한다.
- 기록: 거울은 원본의 `/transcript-raw` 를 받는다 — PC 는 `history=1` 로 처음부터, 대화 칸에 안 쓰이는 무게(그림·긴 도구
  결과·메타)를 원본이 걷어서(`chat_view/history.rs`, 135MB 기록이 5MB). 모르는 옛 원본은 꼬리 512KB 로 답한다.
  폰의 지금은 원본의 `GET /term/mod-live?surface=%N[&seq=&wait_ms=]` 를 받는다 —
  `{live, seq, session, turn_open, compacting, question, tools[{id,tool,label}], permissions[원격 승인 계약의 요청 그대로]}`.
  `seq` 를 주면 바뀔 때까지 쥔다. mod 없는 칸은 `live:false`. 도구 호출이 승인을 감싸므로 묻는 동안 같은 id 의 도구가
  `tools` 에도 있다.
- 승인 카드(폰): 화면의 TUI 창(`parse_prompt_menu`·`parsePromptMenu`)에서 창 안 줄(`context`: 도구·설명·명령 원문)·제목·선택지
  문구·선택지 설명을 그대로 옮긴다. 승인 창 맨 앞 「Yes」와 맨 끝 「No」는 `POST /term/mod-decide`
  `{surface, session, id, decision, message}` 로 그 요청 id 에 답한다(거절이면 입력칸 글이 까닭). 나머지(다시 묻지 않기·
  accept edits·계획 승인·질문)와 코덱스는 화면 키(↑↓ + Enter). 화면을 아직 못 받은 폰은 mod 요청만으로 도구·원문 +
  허락·거절을 묻는다. 어디서 답하든 원본 창이 닫히고 원본이 요청을 닫으니 다른 거울 카드도 사라진다.
- 입력(폰): `POST /term/chat-send {surface, text}` — 안전한 tell(입력칸이 빌 때 붙여넣고 Enter, 승인·질문 창·초안·한글 조합은
  기다린다)로 넣고, 신원이 아직 안 선 칸이면 옛 `/send`. 일하는 칸이면 사람이 일하는 중에 친 말처럼 진행 중인 턴 안으로 든다.
  2026-10-07 전에는 mod 칸을 mod 의 `$.prompt.submit` 에 맡겨 일하는 내내 묶였고, 엔진이 그 말을
  「The kasaterm-bridge plugin sent a message: …」로 감싸 기록했다 — 그 기록이 남아 있어 두 파서가 사람이 쓴 말만 남긴다.
