# 폰 대화 보기 안의 승인·로그인 카드

학생이 사람에게 낸 일을 그 학생의 대화 보기 안에서 끝낸다. 대화를 보다가 승인 화면·Safari 로 갈아타지 않는다.
카드는 입력줄 바로 위, 화면 선택지 카드와 같은 판(판 색 모서리 18 + 주의색 테)에 선다(`mobile/lib/screens/conversation_asks.dart`).
종 아이콘의 학생 쪽지도 승인 카드·선택지 카드를 쪽지 안에 같은 보기로 세운다(`ConversationView.asksOnly`, design.md 「학생 쪽지」).
로그인 카드는 대화 줄에서 요청을 찾으므로 쪽지 안에는 서지 않는다 — 쪽지를 눌러 대화로 간다.

## 승인 카드 — 비밀·도구 권한

원격 승인 창구([remote-approval.md](remote-approval.md))에 오른 요청 중 **이 칸에서 나온 것**만 세운다.

- 칸 맞추기: 요청의 `pane` 이 그 칸 id 이고, 요청한 기기(`device`)가 그 칸의 기계여야 한다. 폰은 관문의
  `GET /relay/devices` 로 기기 id → `machine_id` 를 배워 칸의 경로(`Pane.machine` = `~<machine_id>`)와 맞춘다. 옛 판 칸은
  표시 이름이 경로라 요청의 `machine`(기기 이름)과 맞춘다. 기기 목록은 처음 보는 기기의 요청이 올 때 한 번만 묻는다.
  비밀 요청은 칸·학생을 도전값에서 읽는다(관문이 실은 칸은 쓰지 않는다).
- 결정은 승인 화면과 **같은 길**(`ApprovalCenter.decide`)이다. 사람이 이 카드의 단추를 눌러야만 나가고, 앱 실행 동안만 있는 승인
  열쇠를 싣는다. 비밀 요청의 「Face ID 로 허락」은 Face ID 가 Secure Enclave 열쇠를 풀어 도전값 그대로에 서명해야 나간다 —
  취소·실패면 아무것도 안 보내고 카드에 까닭을 적는다. 비밀 값은 폰에 오지 않는다. 카드에는 참조·명령만 보인다.
- 「자세히」는 그 요청의 승인 화면(입력 칸 전부·폴더)을 연다. 카드는 원문 4줄까지.
- 결과: 여기서 답하면 「허락했어요 · 이번 한 번만 꺼내요」·「거절했어요」, 다른 곳에서 답했으면 「맥미니에서 거절했어요」처럼
  어디서 닫혔는지, 2분이 지나면 「원래 창으로 돌아갔어요」를 단추 대신 4초 보이고 걷는다.
- 이 폰에 승인 열쇠가 없으면 허락 자리에 「Face ID 로 연결」(설정의 비밀 승인 화면)을 둔다.
- 도구 권한은 화면 선택지 카드(TUI 승인 창을 읽은 것)나 mod 요청 카드가 떠 있으면 세우지 않는다 — 같은 요청이다. 그쪽에서
  답한 결과를 이 카드가 다시 말하지도 않는다. 그 카드들이 안 떠 있을 때(mod 는 알렸는데 화면에서 승인 창을 못 읽었을 때 등)는 관문 요청으로 묻는다.
- 그 대화가 보이는 동안(대화 쪽이 앞이고 그 화면이 맨 위)에는 위쪽 알림 띠를 겹쳐 세우지 않는다(`ApprovalCenter.shownInPlace`).
  터미널 쪽·다른 화면이면 띠가 그대로 선다.

## 로그인 카드 — CLI 로그인 주소

학생이 「이 로그인 주소를 Safari 에 붙여 넣고, 돌아온 `localhost:포트/?code=…` 를 보내 달라」고 하는 흐름(넷버드·gcloud 같은
CLI OAuth 루프백 로그인)을 버튼 한 번과 확인 한 번으로 끝낸다.

### 알아보는 신호

새 명령·표식을 두지 않았다. 학생이 이미 쓰는 말에서 읽는다(`mobile/lib/login_link.dart findLoginAsk`).

1. 학생 말 속 주소의 쿼리 `redirect_uri`(`redirect_url`·`callback`… 도)가 루프백(`http://localhost|127.0.0.1|[::1]:<포트>/…`)이면
   그 주소가 로그인 주소이고 돌아올 자리는 그 포트·경로다. OAuth 루프백 흐름(RFC 8252)은 포트가 실행마다 바뀌어 이것을 꼭 싣는다.
   한두 겹 싸인 주소(`return_to=/oauth/authorize?redirect_uri=…`)도 본다.
2. 주소를 줄여 redirect 가 안 보이면, 같은 말에 돌아올 자리를 `localhost:<포트>/…code…` 꼴로 적었을 때 첫 주소를 로그인 주소로 본다.

학생 말(사람이 아닌 학생의 답)만 보고, 사람이 그 뒤에 한 마디라도 했으면 끝난 요청으로 본다. 「×」로 접은 요청은 앱이 도는
동안 다시 안 선다. 학생이 지킬 것: 주소를 줄이지 말고 원문 그대로(대화 기록은 줄바꿈 없이 와서 길어도 된다), 줄였다면 돌아올 자리를
`localhost:<포트>/?code=…` 로 함께 적는다. 받은 주소는 맥에서 `curl -s '<주소>'` 로 그 포트에 돌려준다.

### 돌아온 주소 받기 — 고른 방법

| 길 | 판단 |
|---|---|
| `ASWebAuthenticationSession` 의 콜백으로 바로 받기 | 콜백은 앱 고유 스킴용이고, iOS 17.4 의 `Callback` 이 더한 것도 연결 도메인이 있는 `https` 뿐이다. `http://localhost:<포트>` 는 받는 공식 길이 없다 |
| 앱 안 웹뷰에서 그 주소로 넘어가는 순간 가로채기 | Google 등은 웹뷰 로그인을 막는다(`disallowed_useragent`). 카사텀 폰 앱은 웹뷰 의존도 걷었다(2026-11-06) |
| **폰 루프백에 그 포트를 열고 받기** | 고름. 시스템 로그인 창(`ASWebAuthenticationSession`, Safari 쿠키 공유)이 로그인 끝에 `http://localhost:<포트>/…` 로 넘어오면 폰에는 학생 CLI 가 없으니 그 자리를 이 앱이 연다. NetBird iOS 앱도 같은 루프백 길로 로그인을 받는다 |

흐름(`catchLoginRedirect`): 「앱에서 로그인」 → 그 포트를 IPv4·IPv6 루프백에 연다(다른 기기는 못 넣는다) → 시스템 로그인 창 →
그 경로로 쿼리를 단 GET 하나가 오면 「돌아온 주소를 받았어요」 쪽을 보이고 창을 거둔다(`kasaterm/web_auth` 의 `cancel`) → 자리를 닫는다.
받은 주소는 학생 CLI 가 기다리는 꼴 그대로(호스트·포트·경로·쿼리) 다시 짓는다.

카드는 「돌아온 주소를 <학생>에게 보낼까요?」와 주소(일회용 값은 앞뒤만)를 보이고, 사람이 「보내기」를 눌러야 대화 입력칸과 같은 길
(`TermSession.reply(chat: true)`)로 **주소만** 보낸다 — 학생의 claude 든 주소를 기다리는 CLI 든 그대로 먹는다. 보낸 말이 대화에
서면 카드는 걷힌다.

대안: 그 포트를 폰에서 못 열면(이미 쓰는 자리 등) 까닭을 적고, 「복사한 주소 붙여 넣기」로 사람이 복사해 온 루프백 http 주소를
같은 확인 단계에 올린다. iOS 가 아닌 기기는 브라우저로 열고 붙여 넣기만 된다.

### 한계

- 시스템 로그인 창은 Safari 쿠키를 함께 쓰므로 처음에 iOS 가 「로그인에 ○○ 을 사용하려고 합니다」를 한 번 묻는다.
- 로그인 끝이 루프백으로 안 오는 흐름(기기 코드·화면에 코드를 띄우는 흐름)은 대상이 아니다. 그 코드는 사람이 대화로 보낸다.
- 1024 아래 포트는 iOS 가 안 열어 줄 수 있다 — 그때는 붙여 넣기 길이다.

보냄·열쇠 없음·다른 칸·다른 기계·안 보일 때 띠·다른 곳에서 닫힘·선택지 카드와 겹침), 로그인 카드(열기→받기→확인→보내기, 사람이 이미
답한 요청·다른 학생 말·접기).
