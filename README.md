# kasaterm Browser

계정 독립 크롬 조작. Claude 계정을 바꿔도 끊기지 않고, **평소 쓰는 크롬 프로필과 열어둔 탭**을 그대로 조작한다.
조작 중에는 누가 어느 탭에서 무엇을 하고 있는지가 페이지 위와 확장 팝업에 그대로 드러난다.

```
MCP 서버 (stdio)  ──ws──▶  브리지 데몬 (127.0.0.1:8777)  ◀──ws──  MV3 확장  ──▶  크롬 탭
  터미널 창마다 1개                   1개                            1개
```

포트는 `extension/port.js` 한 곳에만 있다. 확장은 환경변수를 못 읽으므로 이 파일이 유일한 진실이고,
번호가 겹치면 여기 한 줄을 고친 뒤 확장을 재로드한다.

## 왜 이 구조인가

- **claude-in-chrome** 은 Claude 계정 OAuth 에 묶여 있어 계정을 바꾸면 끊긴다.
- **playwright + CDP** 는 Chrome 136+ 정책상 기본 프로필에 못 붙는다(`--remote-debugging-port` 무시). 전용 프로필로 새 창을 띄워야 해서 "지금 보고 있는 창"을 못 쓴다.
- **확장의 `chrome.debugger`** 는 그 정책과 무관한 별개 채널이다. 평소 프로필에 붙을 수 있는 유일한 길이라 확장을 직접 만들었다.
- MCP 는 `~/.claude.json` user scope 라 Claude 계정과 무관하다.
- 브리지를 데몬으로 분리한 이유: pane 마다 Claude 가 떠서 MCP 프로세스는 여러 개인데, 확장이 붙을 포트는 하나다.

## 설치

```bash
node scripts/install.mjs
```

의존성 설치 → 포트 점유 확인 → `claude mcp add-json … -s user` 등록까지 해 준다.
그다음 **한 단계만 사람이 직접** 해야 한다:

1. `chrome://extensions` 를 연다
2. 우상단 **개발자 모드**를 켠다
3. **압축해제된 확장 프로그램을 로드** → 이 레포의 `extension/` 폴더를 고른다 (경로는 스크립트가 클립보드에 복사해 준다)

```bash
node scripts/install.mjs --verify   # 브리지·확장이 붙었는지 확인
```

> **왜 3번은 자동화할 수 없나.** 크롬에는 확장을 설치하는 API 가 없다. `--load-extension` 플래그가 있긴 하지만
> 크롬을 새 프로필로 새로 띄울 때만 먹는데, 이 도구의 존재 이유가 바로 **평소 쓰던 그 프로필**이라 쓸 수 없다.

브리지는 MCP 가 뜰 때 자동으로 켜진다. 직접 켜려면 `npm run bridge`.
확장 아이콘 배지에 `off` 가 뜨면 브리지가 없는 것이고, 배지가 비어 있으면 붙어 있는 것이다.
툴바 아이콘에 마우스를 올리면 지금 누가 무슨 작업 중인지가 툴팁으로 나온다.
브리지 로그는 `~/.<패키지명>/bridge.log`(1MB 넘으면 한 세대만 남기고 갈아엎는다).

### kasaterm 을 쓴다면

`node scripts/install-kasaterm.mjs` 한 번이면 pane 안에서 새로 뜨는 `claude` 마다 이 MCP 가 저절로 붙는다.
kasaterm 이 `claude` 를 감쌀 때 `~/.config/kasaterm/claude-mcp.json` 을 `--mcp-config` 로 넘기는 구조라,
파일이 곧 claude 가 읽는 모양이고 갈아 끼우면 다음 `claude` 부터 반영된다(재빌드 불필요).
되돌리기는 `--remove`.

주입은 **인자 맨 뒤**로 간다 — `--mcp-config` 는 variadic 이라 뒤따르는 non-flag 를 값으로 삼키므로,
앞에 두면 사용자 프롬프트가 통째로 사라진다. `attach` 같은 서브커맨드와 `--strict-mcp-config`·`--` 가
있을 때는 붙지 않는다. 반복 지정은 누적되므로 사용자가 자기 `--mcp-config` 를 줘도 부딪히지 않는다.

> ⚠ 그 파일이 깨지면 **모든 pane 의 claude 가 부팅을 거부한다.** 그래서 스크립트는 임시 파일에 쓰고
> rename 하는 원자적 경로만 쓴다. 손으로 망가뜨렸다면 그 파일을 지우면 원복되고, claude 에러 메시지가
> 경로를 그대로 찍어 준다.

## 누가 조작 중인지 표시

여러 터미널 창에서 동시에 브라우저를 조작하면 "지금 이 탭을 움직이는 게 누구인가"가 바로 헷갈린다.
그래서 MCP 는 뜰 때 자기 신원을 해석해 브리지에 실어 보내고, 확장이 그것을 화면에 그린다.

신원 해석은 **절대 실패하지 않는다** — 아래 순서로 내려가며 이름을 정하고, 마지막엔 `claude` 로 떨어진다.

| 값 | 출처 (위에서부터 먼저) |
|---|---|
| 이름 | `CHROMECLAUDE_NAME` → `KASATERM_CHARACTER` → OS 사용자명 → `claude` |
| 세션 키 | `CHROMECLAUDE_PANE` → `KASATERM_PANE_ID` → `WEZTERM_PANE` → `TMUX_PANE` → `ITERM_SESSION_ID` → 프로세스 고유 태그 |
| 색 | 신원에 색이 없으면 **이름 해시 → 크롬 탭 그룹 8색**. 결정적이라 같은 이름은 어느 기기에서든 같은 색 |
| 아바타 | 프로필 이미지가 없으면 **이름 첫 글자 모노그램** |

이름을 직접 정하려면 `CHROMECLAUDE_NAME=philip claude` 처럼 환경변수를 준다.

한때 이 해석기가 조건에 안 맞으면 `null` 을 돌려줬는데, 그 한 줄이 브리지의 `if (identity)` 가드에 걸려
**오버레이·활동 로그·툴바 아이콘이 통째로 죽었다**. 브라우저 조작 툴은 멀쩡히 도는데 팝업만 비어 있어
고장으로 읽혔다. 그래서 지금은 어떤 환경에서도 신원이 채워진다.

| 요소 | 언제 | 내용 |
|---|---|---|
| 테두리 글로우 | 조작 중 | 세션 색으로 숨쉬듯 명멸 |
| 커서 | 조작 중 | 클릭·조작 지점으로 이동하는 아바타, 클릭 시 링 확산 |
| 우상단 칩 | **세션 내내** | 아바타 + `이름 · 작업명`(`browser_set_task` 로 지정) |
| 툴바 아이콘 | 항상 | 지금 움직이는 세션의 아바타(작업 중 모래시계 / 완료 체크 / 브리지 끊김 흑백) |

칩은 담당이 누구인지 알리는 표시라 조작이 끝나도 남는다 — 마지막 조작 후 2.5초 뒤 글로우와 커서만
걷고 칩은 작고 흐리게(`data-mode=idle`) 낮아진다. 세션이 닫힐 때 비로소 사라진다.
사람이 그 탭을 다른 페이지로 옮겨도 `tabs.onUpdated` 가 칩을 다시 붙인다.
shadow DOM 안에 있어 사이트 CSS 와 섞이지 않고, `pointer-events:none` 이라 클릭을 가로채지 않는다.

**확장 아이콘 팝업**은 지금 이 크롬에 붙은 세션 전부를 보여준다 — 아바타·이름·세션 키·작업명·조작 중 여부와
각자 잡고 있는 탭 목록(제목·호스트, 조작 중인 탭엔 주황 점). 탭을 누르면 그 탭으로 이동한다.
브리지가 끊겨 있으면 맨 위에 그 사실을 띄운다.

탭 목록 아래에는 **무슨 활동을 했는지**가 시각과 함께 최신순으로 쌓인다(팝업 5줄, 패널 12줄, 세션당 30개 보관).
모든 툴 호출이 `background.js` 한 곳을 지나가므로 거기서 한국어 한 줄로 옮긴다 — `클릭 — 로그인`,
`이동 — localhost:3000`, `요소 찾기 — protocols`. 실패한 호출은 빨간 글씨에 `(실패)` 가 붙어,
"눌렀는데 왜 안 됐지"를 되짚을 때 성공만 보이는 반쪽 그림을 피한다.
상태 조회성 툴(`status`·`list_tabs`·`watch`)은 기록하지 않는다 — 남기면 정작 무엇을 했는지가 묻힌다.

> **활동에 입력값은 절대 넣지 않는다.** `fill`·`type` 은 요소 이름까지만 남긴다(`입력 — 비밀번호`).
> 값까지 남기면 비밀번호·검색어가 팝업에 그대로 쌓인다. `find` 의 검색어는 사람이 준 질의라 예외로 남긴다.

팝업 헤더의 패널 아이콘을 누르면 **사이드 패널**로 옮겨 붙는다(`sidepanel.html`). 같은 화면이지만 한 번 열면
탭을 옮겨다녀도 계속 떠 있어서, 아이콘을 누르지 않고도 누가 뭘 하는지 볼 수 있다.
툴바 아이콘이 클릭 없이 보여줄 수 있는 건 그림·배지 2~3자·hover 툴팁뿐이라, 상주 표시는 이 방법뿐이다.
팝업과 패널은 `panel.css`·`panel.js` 를 그대로 공유하고 `<body>` 클래스만 다르다.

**탭 그룹은 팝업의 「묶기」 버튼으로만 만든다.** 누르면 그 세션이 잡은 탭이 세션 이름·색의 그룹으로 묶이고,
「풀기」로 되돌린다. 새 탭을 더 잡으면 버튼이 다시 「묶기」가 된다. 창이 여러 개면 창마다 따로 묶는다.
푸는 건 **이 세션이 만든 그룹에 속한 탭만** 대상이라 사람이 직접 묶어둔 그룹은 건드리지 않는다.
세션이 닫혀도 그룹은 그대로 남는다 — 사람이 명시적으로 만든 것을 함부로 없애지 않는다.

**탭 그룹을 자동으로 만들지는 않는다.** 크롬 `tabGroups` API 는 `title`(글자)과 `color`(8색)만 받고 이미지를 못 넣는다.
claude-in-chrome 이 `✅Claude` 처럼 이모지를 쓰는 게 그 때문인데, 이모지 대신 실제 프사를 쓰기로 해서
상시 표시는 전부 페이지 오버레이로 옮겼다. 파비콘 교체도 같은 이유로 걷어냈다(남의 탭 아이콘을 덮어쓰는 침습적 방식이기도 했다).
그룹은 보조 수단으로만 남겨 팝업 버튼에 달았다 — 열어둔 탭이 저절로 재배치되면 탭바가 어지럽기 때문이다.

## 포커스를 뺏지 않는다

사람이 보던 화면을 에이전트가 가로채면 안 된다. 두 겹으로 막는다.

- `new_tab` 은 **기본이 백그라운드**다(`active:false`). 숨은 채로도 조작은 전부 된다.
  ⚠️service worker 에서 부르면 `chrome.tabs.create` 의 `active:false` 가 **무시되고 탭이 앞으로 튀어나온다**(실측 —
  같은 호출이 확장 페이지에서는 존중된다). 그래서 직전 활성 탭을 곧바로 되돌리고, 로딩 완료 시점에 한 번 더 확인한다.
  되돌릴 대상은 **새 탭이 실제로 생긴 창**의 것이어야 한다 — 마지막 포커스 창 기준으로 잡으면 엉뚱한 창만 되살린다.
  결과에 `active` 를 실어 보내므로 튀어나왔는지가 바로 드러난다.
- `activate_tab` 은 **크롬 창 안에서 탭만 바꾸고 창은 앞으로 끌어오지 않는다**(`windowFocused:false`).
  다른 앱을 보고 있는데 크롬 창이 튀어나오는 게 더 큰 방해다. 탭이 활성이면 rAF·미디어는 정상적으로 돌아
  이 툴의 목적(숨은 탭 깨우기)은 그대로 달성된다.

## 조용한 경로와 승격

기본은 content script 로 도므로 **디버깅 배너가 뜨지 않고 DevTools 와 공존**한다. 다음 경우에만 `chrome.debugger` 로 자동 승격한다:

| 상황 | 이유 |
|---|---|
| 합성 클릭·입력·스크롤이 no-op 이었을 때 | 페이지가 신뢰된 이벤트만 받는다(CodeMirror, 캔버스, 일부 SSO) |
| 좌표 클릭 · 모디파이어 · 우클릭 · 더블클릭 | 합성 이벤트에 좌표 개념이 없다 |
| `press_key` | 키보드는 합성이 씹히는 일이 잦아 처음부터 진짜 입력으로 보낸다 |
| fullPage 스크린샷 · 비활성 탭 스크린샷 | `captureVisibleTab` 은 활성 탭의 보이는 영역만 찍는다 |
| console / network 수집, 파일 업로드, `eval_js`, `cdp_raw` | CDP 로만 가능 |

승격된 세션은 **유휴 15초 뒤 자동으로 떨어져** 배너가 사라진다. `browser_watch` 로 수집을 켠 탭만 계속 붙어 있는다.

## 함정 (실측·문서 확인)

- **DevTools 를 열면 디버거가 끊긴다**(`canceled_by_user`). 붙일 때 이미 열려 있으면 `DEVTOOLS_CONFLICT` 로 알려준다.
- **`chrome://`·웹스토어 페이지엔 붙을 수 없다.** `RESTRICTED_PAGE` 로 알려준다.
- **숨은 탭(`visibilityState: "hidden"`)에서는 rAF·미디어·부드러운 스크롤·프레임워크 전환이 전부 멈춘다.** 스크린샷은 갱신되므로 "코드가 잘못됐다"로 오진하기 쉽다. 그래서 `read_page`·`get_text`·`find`·스크롤 결과에 `visibilityState` 를 **항상** 실어 보낸다. `hidden` 이면 `browser_activate_tab` 으로 탭을 앞으로 꺼내고 판단하라.
- MV3 service worker 는 유휴 30초면 잠든다. 브리지가 20초마다 ping 을 보내고, 확장은 `chrome.alarms` 로도 깨어나 재연결한다.
- 언팩 확장이라 크롬을 켤 때마다 "개발자 모드 확장" 경고 풍선이 뜬다.
- **no-op 판정 구간 안에서 준비동작을 하면 승격이 영원히 안 돈다.** `el.focus()` 를 관찰 구간 안에서 부르면
  `activeElement` 가 늘 바뀌어 모든 클릭이 "변화 있음"으로 읽힌다. 준비동작은 `observeChange` **밖**에서 끝낼 것.
  (2026-07-31 실측 — 이것 때문에 자동 승격이 통째로 죽어 있었고, 신뢰된 입력만 받는 버튼으로 잡아냈다.)
- **no-op 오판은 곧 이중 실행이다.** 합성 클릭이 실은 먹었는데 프레임워크 갱신이 관찰 창보다 느렸을 뿐이면,
  재시도가 두 번째 클릭이 된다. 관찰 창은 350ms 이고(250ms 일 때 Mission Control 필터에서 실제로 오판했다),
  승격 시 결과에 `doubleFireRisk` 를 실어 보낸다. 멱등하지 않은 버튼(제출·좋아요·수량)은
  `trusted:true`(진짜 입력 한 번) 또는 `retry:false` 를 쓸 것.
- 스킴 없는 URL(`example.com`)을 `chrome.tabs.create` 에 그대로 넘기면 **확장 상대경로**로 해석된다.
  `normalizeUrl` 을 거쳐야 하고, `localhost`·`127.0.0.1` 은 `http://` 로 붙인다.
- **MV3 service worker 는 유휴 30초에 죽고 메모리를 통째로 잃는다.** 세션 상태를 메모리에만 두면
  같은 pane 인데도 매번 새 세션이 된다. 작업명 등은 `chrome.storage.local` 에 남긴다.
- **확장의 메시지 핸들러는 메시지마다 독립 실행이라 순서가 보장되지 않는다.** 세션 open 이 저장소를 읽는
  사이 뒤따라온 첫 호출이 먼저 실행돼 신원 없이 처리됐다(작업명이 조용히 버려졌다).
  세션 처리는 한 줄로 세우고(`sessionChain`) 호출은 그 뒤에 태운다.
- **모듈 최상위에 `const URL` 을 두면 전역 `URL` 생성자가 가려진다.** 브리지 주소를 그 이름으로 잡아뒀더니
  `new URL(...)` 이 전부 throw 해 `hostOf` 가 늘 catch 폴백을 탔고, 활동 로그에 전체 주소가 40자로 잘려 나왔다.
  에러가 catch 안에서 삼켜져 콘솔에도 안 뜬다 — 전역과 겹치는 이름은 쓰지 말 것(`BRIDGE_URL`).
- **한 탭의 주인은 하나뿐이다.** 다른 세션이 같은 탭을 이어받을 때 `tabOwner` 만 덮고 이전 주인의 목록을
  비우지 않으면, 팝업에 같은 탭이 두 세션 밑에 동시에 남는다. 인계는 `claimTab` 한 곳으로만.
- **같은 로직을 두 벌 두면 한쪽만 고쳐진다.** `hostOf` 가 background 와 팝업에 따로 있어서, 확장 ID 대신
  파일명을 보여주는 수정이 활동 로그에만 먹고 탭 목록엔 안 먹었다. 지금은 `url.js` 하나를 둘 다 import 한다
  (팝업·패널 스크립트는 그래서 `type="module"`).
- **세션 키를 브리지의 클라이언트 번호(`c1`,`c2`…)로 폴백하면 안 된다.** 그 번호는 브리지 프로세스 안에서만
  세는 카운터라 브리지가 다시 뜨면 1부터 시작하고, 저장소에 남아 있던 **이전 세션의 탭 목록·작업명이 되살아난다.**
  신원 해석기가 세션 키를 항상 채우므로 폴백 자체가 필요 없다.
- **크롬 탭 id 는 재시작 후 재사용된다.** 저장한 레코드를 그대로 믿으면 어제의 탭 정보가 오늘 엉뚱한 탭에 칩을
  붙인다. 저장할 때 시각을 같이 남기고 30분 지난 것은 버리며, `onStartup` 에 `pane:*` 키를 일괄 소거한다.
  세션이 닫힐 때는 지우지 **않는다** — MCP 재연결 중에 작업명이 사라지면 안 되고, 상한은 이 TTL 이 건다.
- **세션 없는 탭에 커서 op 만 보내면 눈에 안 보이는 쓰레기가 쌓인다.** content script 가 오버레이 호스트를
  먼저 만들어 두기 때문에, 화면엔 아무것도 안 보이지만(`opacity:0`) 방문한 모든 페이지에 빈 div 가 남는다.
  `showCursor` 도 형제 함수들과 같은 자리에서 `tabOwner` 를 확인하고 나간다.

## 개발

확장 소스를 고쳤으면 `browser_dev_reload`(또는 `node scripts/cc.mjs '[["dev_reload",{}]]'`) 로 확장을 재시작한다.
언팩 확장은 `chrome.runtime.reload()` 로 디스크에서 다시 읽히므로 사람이 `chrome://extensions` 를 열 필요가 없다.

`scripts/cc.mjs` 는 MCP 를 거치지 않고 브리지를 직접 두드리는 CLI 다. MCP 등록이 아직 안 실린 세션에서
같은 경로를 검증할 때 쓴다.

```bash
node scripts/cc.mjs '[["list_tabs",{}],["read_page",{"tabId":123}]]'
```

`npm run icons` 는 툴바 아이콘 4종(16/32/48/128)을 외부 도구 없이 Node 만으로 다시 만든다.
결과 PNG 는 레포에 커밋돼 있으므로 아이콘 도형을 고칠 때만 돌리면 된다.

`npm run brand` 는 `dist/<키>/` 에 이름만 갈아입힌 배포판을 만든다. 로직을 포크하지 않고 문자열 몇 개만
치환하는 방식이라, 치환 대상이 사라지면 **조용히 넘어가지 않고 에러로 멈춘다**.

`cdp_raw` 는 탈출구다. CDP 로 가능한 모든 것(디바이스 에뮬레이션, 쿠키, 인쇄, 성능 추적…)이 여기로 닿는다.

사내 대시보드처럼 *화면*이 아니라 *데이터*가 필요할 때는 렌더를 기다리지 말고 `eval_js` 로
`fetch(url, {credentials:'include'})` 를 직접 때리는 편이 빠르고 확실하다. 세션 쿠키가 이미 붙어 있다.
